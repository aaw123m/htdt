## Summary

Refs #993 — 複数ファイル出力を generation ディレクトリとして原子公開する。旧 `claim_export_stem` (存在確認のみの TOCTOU) + `write_export_files` (1ファイルずつ逐次公開) を撤去し、`write_export_generation` に統一。

- **予約**: `<stem>.export-staging` の atomic `os.mkdir` が予約そのもの — 作成できた者が stem を所有。staging名/最終名/旧フラット `<stem>_*` があれば stem を skip (新旧両レイアウトで番号単調増加、クラッシュ世代の証拠を再利用しない)
- **staging+manifest**: 全メンバを staging 内へ atomic 書込 → sha256+size を `manifest.json` に記録 (`manifest_extra` で export_id 等をピン)
- **単一公開点**: `os.rename(staging, <stem>/)` — 最終名は「完全な世代」か「無し」のみ。kill 後は staging が診断可能に残り、部分公開は構造上不成立
- **fail-closed**: 失敗時 staging ごと削除、公開直前の最終名出現は FileExistsError、disk full/権限は OSError 伝播
- **検証機械**: `iter_export_generations`/`verify_export_generation` (欠落・破損・未記録混入を名前付き拒否)、`find_export_staging`/`cleanup_export_staging` (明示的、自動回収なし)
- 命名変更: `analysis_export.csv` → `analysis/export.csv` (generation dir 内定数名、ダイアログには実パス表示)
- 呼出元: `workflow_application._write_analysis_export` + 校正設定出力を統一、旧 API は削除 (誤用不可)

テスト: 新規17件 (5並行 barrier・kill注入・squat・manifest 検証・legacy stem 繰上げ) + round9 更新分、計33件全緑 (offscreen pytest)。

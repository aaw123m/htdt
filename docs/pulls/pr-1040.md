## Summary

Operator UI for the #890 credential-vault authority, mounted as `CredentialVaultDialog` inside the existing サポート destination (`SupportPage` → `supportOpenCredentialVault` button) — no new top-level workspace. `CredentialVaultService` gains thin metadata-only read helpers (`vault_state`, `has_consent`, `list_references`, `list_events`) so the panel never touches vault backends directly.

- `credential_vault_panel.py`: `CredentialVaultPanel` renders the sealed `CredentialReference` rows (id/scope/type/vault_scope/state/version/hint/created — no secret column) plus the `CredentialLifecycleEvent` audit tree, with a vault-state banner (`unlocked`/`locked`/`unavailable`) that honestly disables material ops while keeping metadata readable.
- Dialogs: `CredentialStoreDialog` (first-store consent checkbox → the panel seals `consent_recorded` before `store_credential`; password-echoed secret field, `take_secret()` clears on read), `CredentialRotateDialog` (same `credential_id`, version+1), `CredentialConfirmDialog` (revoke/delete — distinct from #946 one-shot device-apply authorization), `CredentialReferencePickerDialog` (returns `credential_id` only; lists only credentials whose *current* row is active; `expected_scope_*` mismatch blocks OK with an actionable drift message and `accept()` fails closed).
- Copy surfaces are ID/metadata only: `参照IDをコピー` → `credential_id`; `監査マニフェストをコピー` → `export_manifest` JSON (excludes `vault_key`). `取得を検証` probes retrieval and surfaces the vault's actionable `CredentialAuthRequiredError` text (locked/unavailable/revoked/deleted/not-found).
- Refresh preserves the selected credential (restores its newest row), so verify-after-mutation flows keep context.

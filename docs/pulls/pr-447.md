## Summary

REV25-DOCSHELP — docs + in-app help truth sweep. Three classes of fix:

**1. Reason-code → help-topic coverage (the REV23-HELP bridge was half-wired).** `AvailabilityReasonSpec.help_topic_id` existed but only 10 of 37 catalog codes bound a topic, so most disabled palette rows dead-ended on their reason text. Worse, the catalog and `HelpRegistry.reason_codes` both listed codes that no emitter can produce — help links pointing at states that cannot exist. Now:

- All 30 emitted catalog codes carry `help_topic_id` mapped semantically (room/selection prereqs → `workflow.room_cad`, save codes → `workflow.data_recovery`, measurement import → `workflow.measurements`, optimization compare → `workflow.prediction_optimize`, edit-state/undo-redo/generic blocks → `trouble.command_unavailable`, prediction run → `trouble.prediction_unavailable`).
- Removed 7 unemitttable specs (`command.blocked.nothing_to_save`, `project.save.unavailable_or_editing`, `prediction.run.{requires_saved_scene_and_receiver,workspace_unbound}`, `measurement.import.{requires_saved_scene_and_point,workspace_unbound}`, `optimization.compare.workspace_unbound`) — the catalog claims to hold emitted vocabulary.
- `HelpRegistry.reason_codes` re-bound to codes that actually exist: catalog codes + the overview-readiness notice vocabulary (`room.missing`, `speaker.role_duplicate`, `measurement.phase_timing_unavailable`, `prediction.*`, `validation.recommendation_blocked`, `equipment.binding_missing`), impact notices (`impact.stale`/`impact.uncertain`) and the real activity statuses (`result_stale`, `completed_for_historical_input` — the registry had the fictional dotted spellings `result.stale`/`result.completed_for_historical_input`). Dead bindings (`value.unknown`, `capture.staged_pending`, `comparison.incomparable_revisions`, `prediction.unavailable.*`) dropped; topics remain keyword-searchable.
- `trouble.command_unavailable` and `trouble.prediction_unavailable` section text updated to describe the real bound vocabulary.

New regression tests: every catalog code resolves to a real topic through both paths (`reason_help_topic_id` and `topic_for_reason`, asserting they agree), and every emitted notice/activity code resolves. `topic_for_reason` was previously test-only dead code indexing fictional codes.

**2.

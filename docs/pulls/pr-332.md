## Summary

Round-8 review+improve pass over the app lifecycle surface (startup → exit → project switch → crash recovery → backup). Full findings and deferral sketches: `docs/reviews/round8-lifecycle.md`.

The fixes, in order of user impact:

- **Recovery dialog showed only 3 of the 5 choices `decide_launch` offers.** `verify_data` and `choose_another_project` were emitted in `LaunchDecision.choices` but had no button — dead affordances the user could read about but never click. `_choose_recovery_action` now renders every offered choice (presentation table `_RECOVERY_CHOICE_PRESENTATION`); non-mode choices become post-launch actions: `verify_data` opens Settings → data management, `choose_another_project` navigates to the Projects destination so the crashed project isn't re-entered.
- **Menu project switch could exit the app silently.** `_switch_to_project` closed the shell *before* `open_project` — a `ProjectLibraryError` (deleted entry, corrupted index) left zero windows → process exit with no message. Reordered: guards → `open_project` (failure → warning, window stays) → `close()` → `_open_document`.
- **Automatic backups never ran inside the app.** `AutomaticBackupScheduler.evaluate('periodic')`/`run_due('periodic')` existed (designed for the in-app trigger) but no production code called it — users with backups enabled got none until they opened data management manually. New `AutomaticBackupRunner` performs the evaluate+run_due check once per launch on `NativeWorkerPool`; when a generation actually runs it submits an Activity Center op (`operation_kind='automatic_backup'`, `OperationClass.DATA_MANAGEMENT`, title 自動バックアップ) so progress/failure are visible. Skipped under Safe Mode; pool shut down via a new close hook.
- **Window state now persists.** `window-state.json` (`PersistedWindowState`: base64 `saveGeometry()`, workspace id, per-workspace context selections) written from a `WorkflowShellWindow.register_close_hook` — hooks run only when the close passes all guards, can't veto, and never abort the close. Restored at composition construction; unknown destinations/contexts dropped; skipped in Safe Mode so stale layout can't re-break a recovering launch. Safe-mode windows carry '— セーフモード' in the title.
- **`_open_document` dropped `capture_receiver`/`preferences`** — spawned project windows lost the capture panel, delivery announcements, and shared the same `ApplicationPreferenceStore` file with a second instance. Both now propagate; the old composition's `delivery_staged` binding is disconnected first so deliveries aren't double-announced.
- **`--safe-mode` CLI flag** wires the previously dead `explicit_safe_mode` decision path — the flag IS the choice, so the recovery dialog is skipped (crash-loop escape without re-answering a dialog each launch).
- **`annotate_launch`** back-fills `last_project_ref`/`last_workspace` on the launch record after `resolve_startup_document`, so next launch's recovery dialog knows which project failed.

Verified-not-bugs: `quitOnLastWindowClosed` doesn't fire during close-then-show in the same slot (Qt 6.11.2 offscreen check); SQLite online `backup()` is safe against the app's open connection.

Deferred with sketches in the doc: no startup progress surface, no concurrent-instance lock UX, restore-from-backup not offered on store-corruption failures, window state is global not per-project, byte-level backup progress, first-run empty state.

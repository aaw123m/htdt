## Summary

Issue #838 slice B: an end-to-end CamillaDSP deploy/read-back/rollback reference adapter over the #1072 transport seam, plus an exact miniDSP target-profile registry and biquad text export adapter — all on the #806 evidence model (`SetConfigJson` Ok is never acoustic verification; every stage is evidence-gated).

**New modules**

- `cad_deployment_target.py` — `DSPDeploymentTargetProfile` (`dtp-`) sealed registry: 18 miniDSP profiles from the official REW table (48k/6PEQ, 96k/5, 96k/10, 192k/10, 48k/10 Dirac-class — Dirac vs non-Dirac are separate profiles) + CamillaDSP WebSocket target + existing generic-biquad fallback. `evaluate_export_target_fit(export, profile)` → `fits`/`exceeds_profile`/`rate_unsupported`/`unsupported_parameters`/`unknown_profile` — anything outside an exact profile surfaces as `unsupported_items` and blocks the #806 deploy gate.
- `cad_minidsp_export.py` — `MiniDSPBiquadExportAdapter` (`CalibrationDeviceAdapter`): materializes per-channel `biquadN,b0=…,a2=…` text with the miniDSP a1/a2 sign inversion. `supports_apply=False`, `supports_read_back=False` — operator import attestation only, never machine-verified; `derive_minidsp_handoff_stage` keeps device state `unknown` until post-measurement evidence exists.
- `cad_camilladsp_deploy.py` — `CamillaDSPCalibrationAdapter` (`CalibrationDeviceAdapter` over injectable `CamillaDSPTransport`): `materialize` = `GetConfigJson` → `compile_camilladsp_config` (htdt_-prefixed Gain/Delay/xo/peq filters + Filter pipeline steps; channel identity + original `filter_id`s pinned in `description` blob for exact round-trip; stale htdt_ names stripped, foreign filters untouched). `apply` = `operator_confirmed` + `ValidateConfigJson` gate → `SetConfigJson` → `DeviceApplyAck`. `read_back` = `GetConfigJson` → `normalize_camilladsp_config` → `CadExportedChannelSettings` for service-level deviation diffs. `capture_baseline`/`read_back_config`/`rollback_previous` produce `CamillaDSPRollbackEvidence` (`restored_verified`/`restored_previous_diverged`/`restore_failed`). `observe_runtime` → `CamillaDSPRuntimeObservation` (state/clipping/levels — distinct evidence kind from acoustic verification, with per-Get `limitations`). Endpoint policy: `binding.device_serial` carries `camilladsp://host:port`; loopback default-allowed, remote endpoints require explicit `approved_remote_endpoints`; no LAN discovery.

**Persistence (schema v95)**

3 new sealed tables — `cad_camilladsp_deployment_sessions` (`cdsp-`), `cad_camilladsp_runtime_observations` (`crun-`), `cad_camilladsp_rollback_evidence` (`crbk-`) — via `_migrate_94_to_95` + `_MIGRATIONS[95]` (v94 was claimed by #839 on main; its migration text is adopted verbatim to keep the merge clean), `_ROW_BINDINGS`, audit replay probes, JA labels.

**Tests/doc**: `backend/tests/test_issue_838_deployment_targets.py` (39 tests: registry sealing/fit, sign-flip + fail-closed materialize, compile/normalize round-trip, Validate gate, remote-endpoint approval, runtime limitations, rollback evidence, repository round-trip + tamper rejection); `docs/issues/issue-838-camilladsp-minidsp.md`.

Out of scope (per issue): REW delegated measurement provider (slice A), Equalizer APO, generic export fallbacks, proprietary correction engines, undocumented vendor protocols.

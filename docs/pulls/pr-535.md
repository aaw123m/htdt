## Summary

Adds a read-only verification system that answers for triage: which open issues already have green automated evidence, and which still need manual/physical work.

Three layers:

1. **`scripts/issue_verification_manifest.yaml`** — maps all 14 open issues to honest checks that exist today (`pytest` / `script` / `manual` kinds). Issues without automatable evidence (#34, #131) declare `manual` entries describing the exact physical evidence required instead of fabricated checks.
2. **`scripts/verify_open_issues.py`** — fetches open issues via the GitHub REST API (token env, or `--issues`/`--offline` for local runs), executes each mapped check in a bounded subprocess (per-check `timeout_seconds`, unique `--basetemp`, `QT_QPA_PLATFORM=offscreen`), and writes `issue_verification_report.json` + a Markdown table to `--report-dir`. Fail-closed on a malformed manifest; `--dry-run` prints the plan; `--post-summary(-from)` is an opt-in JA one-line comment per issue, off by default. Verdicts: `verified` (all checks green, no manual remainder), `partially_verified` (checks green, manual evidence remains), `manual_required`, `failing`, plus `unmapped`/`not_open` housekeeping.
3. **`.github/workflows/verify-open-issues.yml`** — `workflow_dispatch` only (repo convention: no PR CI), windows-latest, installs `backend[dev]`, runs the runner, uploads the report artifact. A weekly cron and the issue-comment step are included but left commented-out.

Also fixes a real latent defect the first run surfaced: `golden_path_preflight.py --clean-work-dir-on-success` crashed with `WinError 32` deleting `data-main/cad-scenes.sqlite3` while a SQLite handle was still open — the golden path itself was fully green but exited 1. `clean_work_dir_on_success` is now best-effort (GC pass + retry + warn-and-skip), so a hygiene failure can't mask a green run.

Verification: all 14 manifest check groups executed locally — every automated check passes; report verdicts: **verified ×3** (#471 TLS bounds, #472 lock test, #475 byte counts), **partially_verified ×9** (incl. #8 golden path now green end-to-end, #1–#5 epics, #132 dep-lock row, #533/#534 foundations), **manual_required ×2** (#34, #131). `backend/tests/test_issue_verification.py`: 26 tests covering manifest validation, verdict logic, offline mode, timeouts, and the cleanup fix.

Docs: `docs/ISSUE_VERIFICATION.md` (how to run, read the report, add checks when code lands).

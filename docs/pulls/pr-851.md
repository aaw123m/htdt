## Summary

GitHub open/closed is binary while HTDT's completion model is not — open issues like #804/#806/#833 look "missing" to external reviewers even though their software already landed. This adds a canonical, machine-readable issue lifecycle that answers "what landed" and "which exact gate remains" without reading commit history.

- `scripts/issue_lifecycle_manifest.yaml`: per-issue `lifecycle` (planned/in_progress/software_landed/acceptance_remaining/physical_evidence_remaining/structural_followup_remaining/complete/withdrawn/superseded), `landed` PR/commit refs (required for landed states), `remaining_gates` typed by kind (manual/physical/structural/verification), `evidence_refs`, `close_when_gates_clear`. All 27 currently-known issues classified.
- `scripts/issue_lifecycle.py`: fail-closed manifest parse; `drift_findings` (report-only) — `landed_without_refs`, `complete_with_gates`, `closed_but_active`, `superseded_without_target`, `landed_no_gate_not_complete`, `unclassified` (verification-manifest issues with no lifecycle entry; GitHub-closed excluded); `classify_issue` bucketing for a backlog view — green software checks never imply completion (`gate_remaining` until declared gates clear).
- CLI regenerates deterministically: `issue_lifecycle.py --issues-json <prefetched> --report out.md --json out.json`. Against today's full issue set: 18 gate_remaining, 3 closeable (#803/#808/#833), 5 implementation_missing, 0 error findings.

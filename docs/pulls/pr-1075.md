## Summary

Pre-run estimate authority for acoustic prediction / joint optimization: before the operator commits a run, the solver/optimization surfaces now show the exact job configuration, range estimates for runtime/peak-memory/storage, accuracy conditions, budget + fidelity verdicts — with honest `UNKNOWN` instead of fabricated precision when inputs sit outside the declared calibrated ranges.

- **`cad_prerun_estimate.py`** (new) — `PrerunJobPlan` (sealed, sha-pinned to the job axes + bindings) + `SolverCostModel` (declared calibrated ranges and per-axis cost terms; `basis='observed_run'` is rejected — measured cost belongs to `ComputeObservation`) + `PrerunEstimate` (sealed; every metric a range with evidence basis; `confidence: calibrated→bounded_extrapolation→unknown`; out-of-range/missing axes leave the metric `None` with the reason, never a fake number). `estimate_prerun_cost` returns blocking reasons (`estimated_peak_memory_exceeds_device`, `gpu_unavailable`) that stay fail-closed, vs soft warnings (long runtime, extrapolation, undeclared limits, non-rectangular geometry). Budget verdict reuses the #770 `evaluate_budget` vocabulary; `fidelity_verdict` runs the real `fidelity_cost_gate` on a synthesized `SolverBudgetProfile`. `record_prerun_observation` mints a sealed `ComputeObservation` only from real measurement (positive finite runtime; RSS stored as `process_rss_bytes`), bound to both the run record (`run_ref`) and the estimate (`profile_ref`) for auditable observed-vs-predicted. Declared cost constants measured on this Windows/Python 3.13 box (~5µs per mode-grid cell, ~1KB per accepted rectangular mode, ~0.19s per joint candidate).
- **`cad_prerun_estimates`** table (native schema v118) + row-integrity bindings + `prerun_estimate` audit replay probe + lifecycle label 「実行前計算コスト推定レコード」— stored via the generic `_SealedStore`, so forged seals are re-verified and same-id/different-sha conflicts are rejected.
- **`PrerunCostCard`** (new `prerun_cost_card.py`) — read-only JA card: 構成 (solver/backend/version), 条件 axes with per-axis status labels, 推定時間/ピークメモリ/ストレージ ranges or 「不明（校正範囲外）」, 予算判定/精度コスト証拠/信頼度 line, blocking vs warning lines, and a 「同一計画の過去実測」 line when a prior measured observation exists for the same plan.
- **`RoomPredictionPanel`** — card refreshed live on model/receiver/max-mode/environment changes (advisory preview, never persisted); run button disabled + `run_prediction` re-checks `prerun_card.blocking` at commit. `start()` seals+persists the estimate and starts the wall clock; the accepted-success path records the measured observation; cancel/stop/dispose record nothing.
- **`JointOptimizationPanel`** — card shows the authoring-preview estimate (mode/budget controls update it live) or the selected spec's exact estimate; 実行 disabled while blocking and `_execute_selected` re-verifies. `JointOptimizationContext.execute_spec` persists the estimate before `run_joint_execution` and records the observation on non-cancelled completion.

Honesty guarantees: estimates are ranges labelled estimates (never point values, never `observed_run` basis); out-of-range → `UNKNOWN` + reason; actuals only from measured elapsed/RSS; cancelled/failed runs leave no observation; soft warnings never disable the run button.

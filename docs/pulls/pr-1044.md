## Summary

Refs #1014
Refs #1021

`CaptureWatchRunner._tick` abandons a scan job at `_STALL_BUDGET_S` by cancelling it, bumping `_job_generation` and starting a replacement immediately — but `NativeWorkerPool.start` only *detaches* the old `QThread`. The old and new workers shared the same mutable `_seen`/`_pending`/`_route_failures` dicts, and `scan_capture_watch_dir` wrote them **before** the generation check, so a worker resuming from slow IO could corrupt the new epoch's baseline/pending: missed candidates, double routing, cross-root bleed.

## Fix shape

- **Job-local state + owner-thread publish.** `_tick` hands each job snapshots of the epoch dicts; the worker computes the whole next-state and returns a frozen `_WatchScanResult(root, generation, seen, pending, route_failures, results)`. The worker never touches runner state (reads included — cancellation flows only through its `cancel` event).
- `_on_completed` (Qt owner thread) publishes the next-state wholesale only while `(root, generation)` still names the live epoch — a guard that stands even if a stale completion were delivered.
- `_job_generation` also bumps on every watch-root change, so no job can publish into an epoch that began after its snapshot.
- `_job_finished(key, generation)` ignores stale generations — a late `finished` can never unlatch the replacement's `_in_flight`.
- **Idempotency**: duplicate route/ingest of the same bundle is suppressed by content `lineage_digest` at the canonical ingestion/inbox authorities (`already_staged`, `arrival_count` bump), not by `(mtime_ns, size)` hints.

Preserved: first-baseline files never auto-import; settle stays mtime/size + two scans; missing dir keeps the epoch; pool detach/cancel semantics untouched; `scan_completed` payload unchanged.

## Tests — race actually reproduced

`test_issue_1014_capture_watch_isolation.py` (7 tests) gates the real scan/route calls on `threading.Event` barriers so the abandoned worker provably resumes **after** the new epoch started: poison-marker isolation assertions, mid-route stall → one inbox row (`arrival_count == 2`), root A→B, disable→enable, shutdown, plus direct publish/latch guard unit tests.

Verified the race on the pre-fix runner: the same gated tests fail — the abandoned worker's poison and root-A markers leak into `runner._seen`.

`test_issue_1014_capture_watch_isolation.py` (7) + `test_capture_watch_runner.py` (14): **21 passed** on Windows/PySide6 offscreen.

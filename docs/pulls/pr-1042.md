## Summary

Refs #955. The Phase B exit audit of #815 found broad `except Exception` sites in the measurement/optimization UI layer that swallowed failures silently — a degraded read could falsify a default (an empty journey strip that looks like "nothing saved yet", a provenance probe dropping to `None` with no trace). This converts every broad catch in scope to the #815 boundary taxonomy; success paths are unchanged.

- 86 `# error-boundary:` markers across 20 files (measurement_workflow, optimization_workflow_workspace, all optimization_*_controller mixins, measurement dialogs/record surfaces, joint/revalidation/commissioning/robustness panels, workflow_shell, optimization_robustness{,_multidimensional}).
- Silent swallows became `except EXPECTED_OPERATION_ERRORS as exc:` + `if is_authority_failure(exc): raise` + `report_boundary_failure(exc, operation='...')` — expected operation failures report and degrade, sealed-store failures always propagate, unexpected errors propagate to diagnostics.
- Boundaries that legitimately stay broad (Qt `closeEvent` teardown, stage atomicity unstage-and-re-raise, per-sample evaluation, volatile pending-import journaling) keep `except Exception` with a justification comment; the exception identity is logged or sealed into `failure_reason` — never bare `pass`.
- The two compute-internal files get justification comments only (failure identity already sealed per-sample); the remaining ~425 broad catches outside the measurement/optimization UI layer are inventoried in `docs/issues/issue-955-error-boundaries.md` as follow-up, per the bounded-scope instruction.

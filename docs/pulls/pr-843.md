Issue #836 Action 1: a sealed, versioned `ExternalCorpusManifest` authority (`cad_external_corpus_manifest`) declaring exactly which external datasets HTDT may qualify against, at which reference strength, and carrying which claims — plus `scripts/fetch_external_corpus.py`, the deterministic fetch/import command with fail-closed checksum verification. No payload is vendored; every file is pinned by name/size/checksum and fetched by URI.

**Pinned datasets** (DepositOnce, licence resolved to CC BY-SA 4.0 via `dc.rights.uri`):
- BRAS v3 — DOI `10.14279/depositonce-6726.3`, handle `11303/7506.3`, 19 files (publisher MD5 + size; SHA-256 computed on retrieval for all but the 4.7 GB `FABIAN_HRIRs` pack, which keeps its publisher-MD5 pin rather than a fabricated hash)
- BRAS RS8 — DOI `10.14279/depositonce-25649`, handle `11303/26816`, 4 files, all with retrieved SHA-256

**20 scenes**: RS1–RS7 as `direct_reference` phenomenon oracles; the nine RS8 configurations (`RS8_01a/01b/01c/02/03a–03e`) as `direct_reference` with `applicability_limit_evidence` — the paper's ~350 Hz curvature / ~450 Hz reflector-height criteria are recorded as scene-specific physical limits, and the 100 Hz–4 kHz validity band is pinned to its published basis (material-data range), not presented as a solver crossover. CR1–CR4 are `supporting`: `CorpusScene._check` structurally rejects any qualification claim on a supporting scene, so the "not direct reference truth" warning cannot be edited away. `CLAIMS_NEVER_DERIVABLE_FROM_CORPUS` names claims no corpus scene can ever carry (owned-room validation, production recommendation, measured room truth).

**Fetch/import**: `python scripts/fetch_external_corpus.py --target-dir <dir> [--dataset …] [--dry-run|--verify-existing]` streams each pinned URI to `<dataset>/<file>`, deletes bytes failing size/MD5/SHA-256 verification, and writes `corpus_fetch_receipt.jsonl`. Verified end-to-end against live DepositOnce downloads (the checksum machinery caught a stale artifact during staging — working as intended). Files with no pinned checksum are `unverifiable`, never silently accepted.

Also: `docs/issues/issue-836-external-corpus-manifest.md`, BRAS ledger row resolved in `EXTERNAL_ASSET_ADMISSION_LEDGER.md`, and a `#836` entry in `issue_verification_manifest.yaml` (pytest check + manual fetch/qualification check).

Not done (later actions): importer, per-scene metric manifests, solver qualification runs.

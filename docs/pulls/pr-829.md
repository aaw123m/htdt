## Summary

Refs #815. Classifies and narrows the broad `except Exception` boundaries in `measurement_page_workspace.py` (76 sites), `workflow_application.py` (17), and `room_workspace.py` (6) by product semantics — not a mechanical rewrite.

New `htdt/error_boundary.py` supplies the typed vocabulary on top of the existing `user_facing_error` machinery:

- `EXPECTED_OPERATION_ERRORS` = `(ValueError, KeyError, OSError, RuntimeError, sqlite3.Error, ValidationError)` — the expected-rejection family that replaced `except Exception` at 96 sites. `TypeError`/`AttributeError`/etc. stay out so programming bugs escape to the central `push_uncaught_sink` boundary instead of reading as recoverable UI states.
- `is_authority_failure(exc)` detects integrity/persistence/authority failures by name suffix (`*IntegrityError`, `*StaleHeadError`, `*ConflictError`, `*RefError`, `*SealError`, `*TamperError`, `*SchemaError`), MRO, and sqlite corruption codes — needed because all domain authority errors are `ValueError` subclasses, so `except ValueError` alone cannot separate user-input from authority failures. Authority failures re-raise to the diagnostics boundary; they are never downgraded to default UI.
- `report_boundary_failure` / `report_unexpected_error` log through `htdt.errors` (ERROR for authority/unexpected, WARNING for expected), preserving the original reason string — adapter provenance is never masked.
- `# error-boundary:` marker convention for catches that legitimately stay broad; an AST guard test fails CI on any new unmarked broad catch in the three modules.

Per-module counts (converted / deliberately-broad): MPW 75/1, workflow_application 15/2, room_workspace 6/0. The three remaining broad catches are marker-classified: leaked `active_jobs` key teardown, the diagnostics self-report path (must never raise), and shutdown accounting.

Notable semantic fixes:

- Journey/import-availability probes narrowed to `MeasurementWorkflowError` — store failures no longer masquerade as "scene not saved".
- Registration freshness falsification fixed: an unverifiable freshness check previously fell back to `'current'` → rendered 最新 and allowed `residual_compute`; now maps to `'unverified'` → 確認不可 with compute disabled.
- Silent collection degrades (source/target/evidence/summary refreshers) now log via `report_boundary_failure` instead of disappearing entirely.

`backend/tests/test_issue_815_error_boundaries.py` adds 25 failure-injection tests: collaborator-mocked authority/adapter/user-input/unexpected injections across measurement, room-edit, and app-composition paths, plus the partial-commit retake path proving an exception mid-commit cannot leave a falsely-successful notice. `docs/issues/issue-815-error-boundaries.md` documents the taxonomy, per-category rules, and counts.

No schema change (no new store/table). Test results: 25 new + 106 regression tests pass (`test_measurement_workspace_composition`, `test_measurement_journey`, `test_measurement_rew_auto`, `test_room_workspace`, `test_workflow_application`, `test_rev44_authority_surfaces`).

## Summary

#890 — 全アダプタが経由する単一の credential vault 抽象 + プロジェクト DB には非シークレット参照のみを持つ封緘権威 (native schema v107)。

- `cad_credential_vault.py`: `CredentialVault` ABC + `MemoryCredentialVault` / `DpapiCredentialVault` (Windows DPAPI 保護 blob, user/machine scope) / `UnavailableCredentialVault` (fail-closed スタブ — 平文フォールバックなし)。`SecretMaterial` は `repr`/`str` が常に `«credential material — redacted»`、値は `reveal()`/`use(fn)`/`fingerprint()` (sha256) でのみ。
- `CredentialReference` (cred-, append-only) は `credential_id` (安定論理ID) + `vault_key` (`htdt-cred/<uuid>` 不透明ハンドル) + `identity_hint` (secret マーカーをバリデータ拒否)。`CredentialLifecycleEvent` (clev-) が consent/store/rotate/revoke/delete/use/retrieve_denied を記録 — details は secret 系キー拒否。
- `CredentialVaultService`: store は当該ドキュメントの `consent_recorded` 必須、素材書込→参照行の順 (参照なし素材を残さない); `rotate` は version+1 + supersedes ピンで `credential_id` 不変 (既存証跡/バインドを書き換えない); revoked/deleted への retrieve は `retrieve_denied` イベント + `CredentialAuthRequiredError` (actionable)。`resolver()` は #726/#879 の `credential_resolver` 規約 (credential_id/reference_id/vault_key を名前解決 — 平文引数不要)。`build_redactor(document_id)` が全アクティブ素材を登録した `SecretRedactor` を返し transcript/#884 バンドルから `«redacted:<id>»` 化。`export_manifest` は vault_key すら含まない非シークレットメタデータ。
- スキーマ v107: `cad_credential_references` + `cad_credential_lifecycle_events` (append-only, 秘密素材はスキーマ外)。row-integrity/audit factory+probe/JA ラベル配線済み。

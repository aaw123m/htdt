## Summary

#875 automated multi-position measurement campaign, implemented over the #869 acquisition engine (`backend/src/htdt/cad_sweep_acquisition.py`). A sealed `CampaignExecutionPlan` (mcplan-) materializes the exact run queue — position-major → channel → role → repetition — and an append-only journal of sealed events (mcevt-) plus per-attempt run records (mcrun-) drives `MeasurementCampaignRunner` through configure → arm → start → quality gate → retry/advance with no manual engine calls.

Key contracts:

- **Position-confirmation ladder**: `operator_attest < coordinate_entry/survey_import < tracked_fixture/position_tracker`, mapped to attested/entered/measured evidence quality. Coordinate reports are checked against `declared_position` within `position_tolerance_m`; a clicked attestation is never treated as measured position evidence. Entries requiring physical moves open a `position_gate_opened` event and block until `confirm_position` succeeds.
- **Deterministic retry policy** (`evaluate_retry_decision`): attempt budget → holdout-drift denial → consecutive-failure campaign stop → cancellation → clipping retry at reduced level → transient device retry → fail. Only explicit policy retries; every attempt (including failures) persists as a sealed run record.
- **Journal-first recovery**: `derive_campaign_state(plan, events, run_records)` is a pure fold — restart rebuilds exact remaining work, re-queues in-flight entries, and re-derives retry reduced levels from the journal. Foreign plans and non-contiguous `journal_seq` are rejected.
- **Honest outcomes**: `completed | completed_with_failures | failed | cancelled | blocked | paused | awaiting_position | in_progress`. Required entries must reach an allowed terminal state (`waived` counts only under explicit `allow_waived_required`); nothing is skipped silently — every transition is a journaled event.
- **#813 separation**: `calibration_state_provider` reports drift → holdout entries are denied auto-retry; `report_routing_change` blocks the campaign for a human under `require_human_on_unexpected_routing_change`.
- **#868-consumable output**: optional `acquisition_sink` persists swstim/swrun through the sweep repository with `campaign_ref` chained to the plan.

Schema v101 (rebased over #876's v100): `cad_campaign_execution_plans` / `_events` / `_runs` with DDL, `_ROW_BINDINGS`, audit `_ReplayProbe`s, `application_pages` lifecycle labels, and the v101 ledger row. 68 scoped tests cover every verdict/state path, seal integrity, repository round-trip + tamper detection, restart recovery, and audit registration. `WasapiAudioBackend` remains honest-unavailable — all engine interactions verified through deterministic `FakeAudioBackend` scenarios with `backend_is_simulated` retained on records.

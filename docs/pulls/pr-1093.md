## Summary

Wires the existing `ActivityCenter` registry into the shell and every long-running operation so in-flight work is never lost track of — no rebuild of the center, no new workspace, no new compute authority.

**Shell (`workflow_shell.py`)**: `ActivityStatusStrip` under the context bar shows running counts by state, latest failure, and the navigation-block reason while an EXCLUSIVE op is live; announces each state transition once via `announce_status`; 開く button → Activity page.

**Canonical registrations** (1 op = 1 record, deep-linked to origin): `prediction.run`, `optimization.candidate_search`/`extended_search` (BACKGROUNDABLE, SAFE_NEW_ATTEMPT), `optimization.adaptive_build`/`adaptive_extended_build`/`rew_import` (EXCLUSIVE — they commit sealed plans/imports), `measurement.batch_commit` (EXCLUSIVE, UNSAFE retry), `measurement.rew_list`/`rew_read` (BACKGROUNDABLE), `room.ifc_import`/`ifc_diff_import` (EXCLUSIVE sync markers), `acceptance.auto_check` (EXCLUSIVE). Navigation gates in measurement + optimization `before_deactivate` now consult `center.navigation_blockers()` — exclusive ops block with the real reason, backgroundable-only work no longer traps the operator on the page.

**Honesty**: progress renders only real units (`4/10 件`, `2/5 ステージ`, 進行中) via `operation_progress_text` — no ETA/fake %. Discarded results record *why* as failures; `completed_for_historical_input` never labeled current. Dead workers terminate via `_terminate_operations()` on stop/dispose — restart shows no phantom running rows.

**ActivityPage**: 進捗 column + per-row actions — 中止 (real `request_cancel` → cooperative callback), 再試行 (SAFE_NEW_ATTEMPT), 再試行（要確認）(UNSAFE, QMessageBox re-authorization before `rerun`), 開く (deep-link back to origin workspace).

**Center extensions**: `retry(new_operation_id=)` pre-binds the fresh attempt id to the executor key; `domain_payload_of` exposes the live payload for retry/rerun adapters; `OPERATION_STATE_LABELS`/`operation_state_label`/`operation_progress_text` shared vocabulary.

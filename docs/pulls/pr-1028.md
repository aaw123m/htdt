## Summary

`commissioning_panel.py` was read-only (`refresh` only). This wires it to the #868 closed-loop orchestrator via a new command port, `commissioning_operations.py`:

- `CommissioningOperatorController` delegates `advance` / `authorize_deploy` / `deploy` / `readback` / `rollback` / `restore_connectivity` / `cancel` to the orchestrator's existing services. It owns no truth: `operations()` derives each of the 7 `CommissioningOperation`s from `next_permitted_actions(state)` plus honest service-availability checks (missing adapter, binding-sha pin mismatch, no compile materialization, no deployment → JA `disabled_reason` on the button tooltip).
- Device-mutating paths go through `CommissioningApprovalDialog`: target device, scene-content hash, calibration candidate, export/materialization shas, diff summary and approval scope are listed before a one-shot authorization is minted (`deploy_apply` pinned to `export.requested_plan_semantic_sha256`; `rollback_apply` pinned to the resolved deployment). Existing valid seals are reused (`reusable_authorization_id` in the preview); consumed/expired/wrong-candidate scopes are never reused.
- Apply vs read-back stay distinct commands/states — `apply_error` / `diverged` / `rollback_verify_failed` transition reasons surface verbatim on the panel's result label; a blocked apply does not consume the authorization.
- Click-time re-check inside `_execute` + a busy guard make stale panels and double-execution safe; restart honesty is preserved (in-session materialization cache only → honest "コンパイル結果がありません" after reload rather than a fabricated equivalent).

`CommissioningOperatorServices` is the testable injection boundary — every input is optional and absent inputs degrade to disabled reasons, never fabricated success (fixture CamillaDSP transport throughout).

## Summary

REV31-UXFLAKE batch: four fixes hardening UX surfaces, ordering guarantees and fail-closed behavior.

### 1. Editor toolbar clips at 1024px (`native_editor.py`)
A single `QToolBar` wider than the window collapses its tail into a `>>` overflow — at 1024px only the first actions stayed reachable. Split into 4 semantic toolbars (`編集` / `スナップ` / `表示` / `復旧`); several narrower toolbars wrap onto extra rows and stay visible. Action set, shortcuts, checkable states and `_localize_inherited_ui` title matching are unchanged.

### 2. Wall-clock flake in `test_review_round9_prefs` (`project_library_repository.py`)
`open_project` stamped `last_opened_at_utc` with the wall clock (~15ms granularity on Windows): rapid opens shared a stamp, so recency silently re-ordered on the `rowid` tiebreak and `skip_last_opened` picked the wrong project. The write txn now floors the stamp at `MAX(last_opened_at_utc) + 1µs` — strictly-increasing ordering without a sequence table.

### 3. `python -O` assert fail-open audit (8 files)
Audited all ~181 `assert`s in `backend/src/htdt`. Most fail closed anyway under `-O` (the guarded value is dereferenced → `AttributeError`, used in arithmetic → `TypeError`, or re-validated by pydantic `min_length`/`model_validator`). The 12 that could silently return or persist bad state are now explicit raises:

- `capture_receiver.py` — `request_pairing`/`confirm_pairing` returning `None` → `CaptureReceiverError`
- `cad_r140_executor.py` — `ResourceQuantity.require` returning `None` → `RuntimeError`; `commit_success(result=None)` publishing a null result → `RuntimeError`
- `cad_objective_repository.py` — returning a `None` `candidate_set_sha256` → `RuntimeError`
- `cad_joint_optimization_repository.py` — wrong-typed authority-cache entries returned to callers → `RuntimeError` (×2)
- `measurement_workflow.py` — `position=None` persisted into measurement-target lineage → `MeasurementWorkflowError`
- `project_library_repository.py` — `duplicate_project` returning `None` → `ProjectLibraryError`
- `cad_acoustic_construction.py` — empty layer stack returning `None` impedance → `ValueError`
- `cad_auralization_player.py` — `active_source()` returning `None` for `active='b'` → `ValueError`

### 4. Support-matrix ↔ schema consistency test (`test_support_matrix_consistency.py`)
`capture_contract/support-matrix.json` is the runtime source of truth for path→family and version→schema-document resolution, but nothing pinned its invariants. New tests assert: every `documents[v]` key resolves to a loadable `<key>.schema.json` (through `check_schema`), versioned schemas pin `schema`/`schema_version` consts to the family `schema_id` + registered version, `emitted ∈ read ⊆ documents` and emitted is the newest version, paths are unique across families, external/unversioned families keep their declared shape, and no `.schema.json` file is orphaned from the matrix.

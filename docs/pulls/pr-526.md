## Summary

`measurement_views()` crashed the whole listing when a bound quality report's replay re-verification raised (e.g. a tampered raw asset — exactly what `test_round8_measurement_journey` exercises). The batched `report_errors` map re-raises on each reached row by design — but a listing reaches every row, so one corrupt report took all measurements down. The row gets the same isolation `dataset_error` already had:

```python
try:
    report = self._latest_report_for(...)
except Exception as exc:
    report = None
    report_state = 'error'           # new Literal member
    report_error = operation_error_message(exc)
```

`MeasurementView.report_error` carries the detail; the quality panel labels `'error'` as 検証エラー. Single-row callers (`latest_report`) still raise — detail/verify flows stay fail-closed; only the listing degrades per row.

Fixes the pre-existing rot REV43-PRODUCERS flagged: both `test_measurement_views_isolate_unverifiable_dataset` and `test_workspace_survives_corrupt_dataset_and_comparison_history` failed on clean main and now pass.

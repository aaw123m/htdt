## Summary

REV32-ROOM lane: make the room/CAD authoring surface self-explanatory. A journey audit on the real display found ~90% of room-surface controls had no explanation anywhere — context tabs were bare labels, tool-strip actions gave no hint of what they do, and 壁/開口/履歴 sections rendered unexplained. This PR adds three layers of guidance:

1. **Context tab hints** — `WorkspaceContext` gains an optional `hint` field; `TopContextBar.set_workspace` applies it as the tab button's tooltip. The five room contexts (形状/物体/スピーカー・座席/音響/履歴) each describe their job. Other workspaces' contexts default to `""` and are untouched (sibling lanes fill their own).
2. **Per-context guidance line** — `ContextToolStrip` now renders a `GUIDANCE[context_id]` line under the action row (e.g. geometry: このタブで部屋の形を作ります → つぎは「物体」タブで機器を配置), plus an `ACTION_HINTS` tooltip on every tool-strip action (部屋を描く / 形状を編集 / 計測 / 削除 / 表示… etc.).
3. **Field/tooltips everywhere else** — object palette (all 9 entity kinds), selection inspector fields + row labels (`QFormLayout.labelForField`), geometry panel (every field + new `wall_hint`/`opening_hint` labels that explain the empty sections when nothing is selected), objects tree headers, measure modes/references as per-item tooltips, constraints, video-geometry bindings/policy, prediction model/receiver/environment options, material + treatment dialogs, standards criteria tree, revision history (intro + column meanings + buttons), recovery banner, and the legacy N30a `room_editor.py` toolbar + inspector.

## Notes

- Regression coverage: `tests/test_rev32_room_guidance.py` (10 tests) asserts every room context has a hint, every strip action/guidance line exists and is rendered, and the panels' fields/headers carry tooltips — unexplained controls can't regress.
- Scoped suite green: 232 room/workspace tests + 10 new, all pass (`test_accessible_labels` showed the known Qt-teardown `worker crashed` flake under xdist; 25/25 pass serially).

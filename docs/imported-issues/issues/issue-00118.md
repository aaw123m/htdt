# Native UI/UX overhaul: workflow-first navigation, progressive disclosure, and visual stability

## Current status — 2026-09-20

The workflow-first software overhaul through UX150 is implemented, and O100G system-expansion surfaces are now connected into the existing Room / Optimize contexts via PR #255. The software CI and Windows packaging checks are green.

The remaining gate is **UX160 owned-Windows visual/first-use acceptance**: DPI behavior, font rendering, mouse interaction, 3D readability, clipping, layout stability, and first-use discoverability on the actual Windows machine. This gate should be executed with minimal RDC usage and does not require further speculative software restructuring unless the physical acceptance uncovers a concrete defect.

## 背景

現行HTDT native GUIは機能実装自体は進んでいるが、実利用時の情報設計・発見性・視覚的一貫性が不十分である。

ユーザー観察:
- どこに何があるのか分からない
- どこで何ができるのか分からない
- toolbar / dock / tree / buttonが多く、操作の入口が見えない
- 一部でlayout、余白、align、minimum-sizeの競合により表示が崩れる
- GUIを触る前に内部概念を理解しないと目的操作へ到達できない

これは単純な配色変更ではなく、**information architecture / progressive disclosure / workflow navigation / layout stability** の問題として扱う。

## 現行実装で確認した構造的原因

現在のwindow compositionは概ね次の継承で段階的にUIを追加している。

```
NativeEditorWindow
  → RoomEditorWindow
  → WallEditorWindow
  → CadEditorWindow
  → TheaterEditorWindow
  → TheaterWorkflowWindow
  → ConstraintEditorWindow
  → MeasurementEditorWindow
  → MeasurementWorkspaceWindow
  → PredictionWorkspaceWindow
  → OptimizationWorkspaceWindow
```

各層が `QToolBar` / `QDockWidget` / tree / form / action を追加するため、最終workspaceでは「機能を追加するほどUI密度が増える」構造になっている。

特に `OptimizationWorkspaceWindow` は search axis/spec/candidate、measurement plan、objectives、Pareto、campaign、validation、adaptive、extended search 等を一つの右側contextに積み上げており、scroll化しても認知負荷は解消しない。

**対策はdockをさらに整理することではなく、workspace architectureを組み替えること。**

## ベンチマーク: Home Theater Maestro (HTM)

HTMの公開UI/Live DemoをUX benchmarkとして使う。ただし外観やassetをコピーせず、情報設計・workflow・視覚階層の原則を抽出する。

公式:
- https://hometheatermaestro.fr/en/
- https://hometheatermaestro.fr/en/features.html
- https://hometheatermaestro.fr/demo/?lang=en

参考にする原則:

1. **少数のglobal destinations**
   - Overview
   - Room
   - Measurements
   - （HTDTでは必要に応じ Optimize / Results を追加）
   - Help / Settingsは下部へ退避

2. **global navigationとcontext navigationを分離**
   - Roomに入った後だけ geometry / seats / screen / speakers / acoustics 等のsub-contextを表示
   - 全機能を一つのtoolbarへ並べない

3. **Overview = 次に何をすべきか**
   - project summaryだけでなく、未完了・問題・recommended next actionを優先順に表示
   - actionから該当workspaceへ直接navigate
   - 「機能一覧」ではなく「次の作業」を示す

4. **3D viewportはDesign時の主役**
   - Room/Placementでは大きな3D contextを維持
   - Measurements/validation/analysisまで無理に3D dock shellへ押し込まず、taskに適したfull-page layoutを許可

5. **progressive disclosure**
   - primary taskで必要なcontrolだけ表示
   - Advanced/diagnostic/provenanceは必要時に展開
   - UUID/schema/job/hash等を通常画面へ露出しない

6. **document-like analysis pages**
   - Measurement import → assignment → prediction comparison → plots/verdict の順に上から読める
   - 右dockに複数treeを詰め込まない

7. **一貫したvisual hierarchy**
   - navigation / page title / section / card / fieldの階層
   - 同じspacing、radius、control height、font hierarchy
   - status badgeやwarningの意味を一貫させる

8. **feature search / command palette**
   - HTMの “Search a feature / Ctrl+K” のように、場所を覚えていなくても操作へ到達できる入口を持つ

## HTDTの新しいtop-level IA

初期案:

```
プロジェクト
├─ 概要
│   ├─ 部屋・システムの要約
│   ├─ 準備状況 / 要対応
│   ├─ 最近の測定 / 予測
│   └─ 次の操作 → 該当画面へ
│
├─ 部屋
│   ├─ 形状
│   ├─ 物体
│   ├─ スピーカー・座席
│   ├─ 材料 / 音響への反映
│   └─ 音響 / 空間表示
│
├─ 測定
│   ├─ 読み込み / 測定
│   ├─ 割り当て
│   ├─ 品質 / タイミング
│   └─ 予測との比較
│
├─ 最適化
│   ├─ 探索設定
│   ├─ 候補
│   ├─ 目的 / パレート
│   ├─ 測定計画
│   └─ 検証 / 適応
│
└─ ヘルプ / 設定
```

Predictionは単独のglobal destinationに固定しない。
- spatial predictionはRoom/Acoustics
- predicted-vs-measuredはMeasurements
- candidate batchはOptimize

のように**ユーザーのtask contextへ配置**する。

内部authorityの境界はUI navigationへそのまま露出しない。

## shellの基本方針

### 左 rail
- project selector / save state
- feature search
- global destinationsを4〜5個以内
- Help / Settingsを下端
- collapsible
- icon + short label。icon-onlyを既定にしない

### top context bar
現在workspace内のsub-contextのみ。

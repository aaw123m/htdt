## PR 本文 (原文復旧 — devin-03d87ec5)

Follow-up to #427 (already merged). Runtime offscreen E2E verification surfaced a residual defect in the `note_authorities_changed` repair: the snapshot iteration prevents `RuntimeError`, but when `_records` exceeds `record_limit`, each reclassifying `_transition` → `_archive` evicts the oldest terminal records — including ops the pass has not visited yet. The next visited evicted op resolves through the history fallback and raises `OperationTransitionError('already completed')`, aborting the batch; the production caller `_note_superseded_inputs` swallows `Exception`, so it silently half-applied.

The 530-walk harness never produced this — walks stay under `record_limit` while carrying matching `input_authority_refs`. Fix: `try/except OperationTransitionError → continue` around that `_transition`; the evicted op's surviving history row is reclassified in place by pass 2, so the batch reaches every op.

New deterministic regression `test_authorities_changed_reclassifies_past_record_evictions` (records 14 vs bound 4, 4 resident terminal): fails pre-fix with `OperationTransitionError: operation op-1 is already completed`, green post-fix.

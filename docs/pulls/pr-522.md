## Summary

REV43 adversarial review of integration seams + boundary classes on post-REV42 main (findings report: `docs/reviews/rev43-seams.md`). Two clear defects fixed; everything else verified clean or listed as judgment calls.

**Defect A — `.htdtcapture` watch folder silently lost a drop after one routing failure.** `scan_capture_watch_dir` marks a file `seen` at delivery; on a `failed` outcome or a routing exception the marker stayed, so the file was invisible to every later scan — and a restart could not recover it because the baseline pass marks every pre-existing file seen. The scanner's docstring documents the requeue path (pop the `seen` marker); it was never wired. Transient failures are real: `inbox.stage` runs `BEGIN IMMEDIATE` against concurrent writers (batch commits, GC), and a descriptor can land a beat before its companion bundle (`user_action_required`).

Fix mirrors the REW lane's `_fail_watch_files`: `_route_failures` per-path attempt counts (worker-side only, alongside `_seen`/`_pending`) → non-success routes drop the `seen` marker so the file re-settles and re-routes, capped at `_ROUTE_MAX_ATTEMPTS = 3`; at the cap the marker stays (wedged), and a signature-changing rewrite still re-delivers it. Success clears the count; counts for vanished files are pruned.

**Defect B — rejected or operator-action-needed watch drops produced zero user signal.** `_on_capture_watch_completed` counted failures only as `result is None or outcome == 'failed'` — `invalid_or_unsupported`/`user_action_required` outcomes fell through both filters, hit `if not staged and not failed: return`, and vanished with no Activity entry and no statusbar line. `failed` now covers every non-success outcome; `already_staged` re-arrivals stay quiet by design.

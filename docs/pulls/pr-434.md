## Summary

The installation handoff export (`installation.export_handoff` → `build_installation_handoff`) passed only `scene_revision_id` + `system_variant_id` into `build_installation_output_from_authorities`. Every other section pin (`video_geometry_evaluation_id`, `standards_evaluation_id`, `calibration_plan_id`/`calibration_export_id`/`calibration_verification_plan_id`, `signal_path_edge_ids`) defaulted to None/empty — so the `projector`, `standards`, and `calibration` sections and cable-run signal-path freshness could never reach an exported package: they always rendered UNKNOWN, even when exact bound authority existed in the project. Meanwhile `latest_calibration_authority_ids` — the helper written precisely so callers can pin a plan's latest persisted chain — had zero callers.

`build_installation_handoff` now resolves `service.latest_target_section_authority_ids(scene_revision_id, system_variant_id)` and passes the discovered pins explicitly:

```python
pins = service.latest_target_section_authority_ids(
    scene_revision_id, system_variant_id or None,
)
output = service.build_installation_output_from_authorities(
    scene_revision_id=scene_revision_id,
    system_variant_id=system_variant_id or None,
    video_geometry_evaluation_id=pins.video_geometry_evaluation_id,
    standards_evaluation_id=pins.standards_evaluation_id,
    calibration_plan_id=pins.calibration_plan_id,
    calibration_export_id=pins.calibration_export_id,
    calibration_verification_plan_id=pins.calibration_verification_plan_id,
    signal_path_edge_ids=pins.signal_path_edge_ids,
)
```

The discovery (`latest_target_section_authority_ids` → `InstallationSectionAuthorityPins`) mirrors the convention the treatment/datum/cable-run sections already use: list records from their authoritative repositories and take the most recently persisted one whose recorded target equals the resolved `(SceneRevision, SystemVariant)` — the same five-field equality `_require_target_binding` enforces (`document_id`, `scene_revision_id`, `scene_content_hash`, `system_variant_id`, `system_variant_sha256`). Records bound to another revision/hash/variant are skipped rather than rejected; a section with no match stays `None` → honest UNKNOWN. A missing repository yields no candidates, so services constructed without these repos behave exactly as before.

Also adds optional `signal_path_repository` to `InstallationReportService` so edge presence for cable-run freshness resolves from the persisted signal-path store instead of always reporting `signal path edge absent`.

Fail-closed semantics are unchanged: the resolved pins go through the existing canonical replay validation, `verify_installation_output_replay` still rebuilds from the exact recorded ids, and the operator's preview dialog still shows real per-section availability before writing.

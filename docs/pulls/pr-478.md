## Summary

The measurement workspace's six context tabs (読み込み/割り当て/キャンペーン/品質/比較/機器の準備) are flat siblings that never express the canonical first-run order — a newcomer lands on 読み込み with no signal of what to do first, in what order, or what each page means (REV32 understandability bar).

This adds a persistent `測定の手順` strip pinned above the page stack on every measurement page: six numbered steps evaluated from persisted state, each clicking through to the page that owns it:

```
①部屋を保存 → ②機器の準備 → ③計画を作成 → ④計測を実行 → ⑤取り込みと割り当て → ⑥品質の確認と比較
```

- New pure evaluator `measurement_journey.evaluate_measurement_journey()` maps persisted signals → `MeasurementJourneyStep(status ∈ done/current/pending/blocked, detail, context_id)`: head `SceneRevision` presence, `evaluate_instrument_onboarding` output, runner plan count + latest-run `runner_progress` cells, committed `measurement_views`, staged imports. Only the missing room blocks downstream (every authority call already fails closed on it); all other steps are recommend-order, never hard gates — the external REW-import path legitimately skips the runner.
- Steps deep-link via the mount's new `on_navigate` (`WorkflowApplication._navigate_target` → `shell.handle_deep_link`), so the shell's context bar and router stay in sync when the page switches — bare `set_context` remains the standalone fallback. The 部屋 step crosses to the Room workspace the same way.
- `次にやること` hint names the current step's concrete deficit (e.g. `要対応 4 項目 · 要確認 1 項目`, `残り n セル`) and `現在の手順を開く` jumps to it.
- Semantics worth noting: instrument `manual` items (physical checks records can never prove) cannot stall the journey — done-with-reminders, not current; a still-staged/batched import keeps ⑤ open and steers it to `assignment` instead of `import`; a partially-finished run keeps ④ current.
- Fixed the campaign `現在のステップ` label that told the user to "open the campaign" while already on the campaign page.

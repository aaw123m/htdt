## Summary

REV52-GAEMIT implements the two remaining capability-emit gaps recorded in `docs/reviews/rev51-wire.md`, and documents the structural finding for the third.

**A. GA descriptor-persist emit.** Declaration emit moved into `CadAcousticSolverDispatchRepository.save_descriptor` itself — every lane (GA, R130A-D, polyhedral) now auto-emits the declared `SolverCapabilityManifest` on descriptor persist ("persist されれば同一導出で自動 emit"). The explicit emit call sites in scripts/tests remain valid — they dedupe to no-ops. Produced emit added to `CadDeterministicPathArtifactRepository.save`: after commit it re-derives with `produced_observables=(DETERMINISTIC_PATHS_OBSERVABLE,)` and persists via the shared `save_capability_manifest` (dedupe → idempotent). Emit runs **after** the repository transaction closes (nested sqlite connections deadlock).

```
save_descriptor → _emit_declared_capability_manifest
save(artifact)  → _emit_produced_capability_manifest
    → get_descriptor(adapter_descriptor_id) [None/sha mismatch → ValueError]
    → derive_solver_capability_rows(descriptor, produced_observables=...)
```

Declared and produced manifests are distinct rows (different unevidenced reason text) — the audit-separation design from REV51.

**B. Matrix verify-only persistence.** New `MatrixRunVerification` record (`cad_prediction_matrix.py`) persisted hash-bound to `ExactJsonAuthorityStore` — no new DB table, same pattern as measurement-quality verification. `PredictionAuthorityLane.persist_matrix_run_verification(run_id)` re-verifies a terminal run against *persisted* provider authorities: three-way spec/result_set/run hash binding, `cell_state_counts` reproduction, and per READY/CACHED cell re-derivation of `result_sha256` + full transfer equality; unproduced cells (BLOCKED/FAILED/…) recorded verbatim. `promote_provider_via_matrix_run(provider_id, ref)` gates candidate → `validated`/`synthetic_fixture` on complete receiver coverage — `owned_room`/実測 is never claimed. `PredictionMatrixDialog._run_matrix` persists verification after a successful run.

**C. Hybrid provider authority — documented, not wired.** `HybridPredictionProvider` already carries `observable_capabilities`/`capability()` natively (provider-level emit exists). It cannot enter matrix verification: `collect_matrix_results` requires `receiver_responses` (spec-pinned receiver rows) while hybrid holds `absolute_pressure_samples` (unpinned point cloud). Manifest-ification needs a provider→descriptor authority mapping — a separate design, recorded in `docs/reviews/rev52-gaemit.md`.

Fail-closed preserved: undeclared produced observables raise, stale descriptor bindings raise, tampered verification records fail hash validation on read, unevidenced phenomena stay UNSUPPORTED.

Tests: `tests/test_rev52_gaemit.py` (5) + updated `test_solver_capability_manifest.py`. Scoped pytest green on merged tree; one pre-existing failure (`test_no_orphan_or_shared_schema_documents`) reproduces on clean HEAD — recorded in the report.

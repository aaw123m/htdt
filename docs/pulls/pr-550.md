## Summary

Follow-up fixes for the guided acceptance wizard (#549), found by a real-GUI E2E pass on the merged code:

- **`acceptance_page.py` — worker lifecycle.** `self._worker` kept pointing at a `deleteLater`'d `_AutoCheckWorker`; the next チェック実行 called `isRunning()` on a dead C++ object → `RuntimeError: Internal C++ object already deleted`. Effect: exactly one auto check worked per app session. Now the reference is cleared on `finished` (identity-guarded so a relaunched worker can't be cleared by a stale signal).
- **`acceptance_checks.py` — `_REPO_ROOT`.** `Path(__file__).parents[2]` resolved to `backend/`; every subprocess check (`golden_path_preflight`, `dependency_lock_check`, `o60r_audit`) always returned 不可「スクリプトが見つかりません」. Now `parents[3]` → repo root.
- **Run list.** Repopulating `run_list` fired `itemSelectionChanged` mid-rebuild and could swap the displayed run to another run (data was recorded correctly; only the view jumped). The refresh now blocks signals and re-selects the current run's row. It also uses `list_runs()` instead of `in_progress_runs()` so finished runs stay listed — labeled with their verdict — for reopen/re-export (replayability).
- Tests: `_REPO_ROOT` script-resolution regression + `list_runs` finished-run coverage.

Real-GUI re-verified on this box: two consecutive auto checks on 所有Windows受入マトリクス both ran — `env_snapshot` 合格, `check_dependency_lock.py: 成功` — and the view stayed on the same run.

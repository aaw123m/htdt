## Summary

When a click in the 3D viewport resolves more than one entity, the existing click-through cycle (`_cycle_pick_candidate`) worked but was invisible — no indication of "which of N candidates" was armed, so dense speaker/wall/seat scenes caused mis-edits. This PR adds a cursor-side chooser that makes the captured hit stack explicit.

- `RoomViewport3D._sync_pick_candidates` runs after each entity pick emission: when `pick_actor_candidates`'s stack has ≥2 entities it shows `_PickCandidatePopover` — a `重なり候補 {i}/{n}` header, `{i}. {名前} · {種別}` rows (kind wording shared with the #978 objects list), and a per-row "cannot operate" reason (`ロック中` / `非表示` / `シーンに存在しません` / workspace-provided `編集不可`). Selection stays allowed regardless of reason — selection ≠ edit permission.
- Input: `_PickCandidateKeyFilter` is installed on the interactor only while the chooser is open — wheel and ↑↓/Tab/Shift+Tab step the armed candidate (with a preview-only `pick-candidate-*` wireframe envelope that never touches SceneRevision), Enter confirms through the same `entityPicked`/`entitySelected` path a click uses (so the objects list, inspector and view state sync identically), Esc dismisses, row click = immediate confirm. `ShortcutOverride` is claimed for chooser keys so workspace Esc/Enter shortcuts cannot fire underneath.
- Stale-set discard (`dismiss_pick_candidates`): camera moves (pan/orbit/zoom/standard-view/fit/focus/camera-view restore/view-from), section-cut changes, `render_document` rebuilds where the document or hidden set changed, marquee activation, context menu, empty click, resize/DPI, focus loss. Same-document selection refreshes keep the chooser alive with refreshed rows + re-added preview.
- Active-gizmo rule: `RoomEntityTransformController._arm` dismisses and suppresses (`pick_popover_enabled=False`) for the gesture's duration.
- No additional scene picks: the chooser reuses the picker's own `GetProp3Ds` stack and the existing `_cycle_ids`/`_cycle_index` state — `test_no_scene_repicks_through_chooser_lifecycle` pins zero `picker.Pick` calls across open/cycle/confirm/dismiss (bench note for #867).

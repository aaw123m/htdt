## Summary

REV24-UXFLOW wave — the interaction half of the usability pass: fix places where the UI's own surfaces misreport reality (status bar, dirty indicators), where dialogs had no safe keyboard default, and where validation dead-ended the user. Behavior-true fixes only, no redesign.

**Status surfaces that lied**
- `WorkflowApplicationComposition._bundle_job_completed` never cleared the in-flight status line, so after a project-bundle export/import finished the bar kept reading "…エクスポートしています…" until something else posted. The job's message is now stored in `_bundle_status_message` and cleared on every terminal path — but only while it is still `currentMessage()`, so a fresher notice posted mid-job is never wiped.
- `RoomWorkspace._refresh` only wrote the dirty indicator `if not self.status.text():` — the notice label is never cleared once text lands, so after the first notice the dirty line was permanently suppressed and "保存しました" stayed up while edits were pending. The strip now carries a dedicated `dirty_status_label` badge (WARNING semantic when dirty) updated unconditionally; `self.status` remains the last-action notice.
- `NativeEditorWindow._set_dirty_status` posted 未保存/保存済み through the transient `showMessage` channel — the next notice clobbered it forever. Moved to a permanent `statusBar().addPermanentWidget(QLabel)` (`_dirty_indicator`), initialized on load and refreshed on save/recover (both swap `self.working` and previously left the indicator stale).

**Dialogs**
- `dirty_state_dialog._choose` had no default button: Enter was unpredictable across three destructive choices. Now defaults to the first non-destructive choice, or キャンセル when every choice is destructive (busy → stop_busy only). Same for `choose_snapshot_action` → defaults to 保存して{action}.
- `_choose_project` / `_pick_one` list pickers ignored Enter/double-click — now `listing.itemActivated → dialog.accept()`, the same gesture as the command palette list.
- `_new_project` / `_rename_project` / `_duplicate_project` dead-ended on a blank name (warning → menu again). Extracted `_prompt_project_name`: re-prompts until non-empty or Cancel, returns `name.strip()`.

## Test
New `backend/tests/test_rev24_uxflow.py` — 11 cases covering badge truth, busy-line lifecycle, Enter defaults, picker activation, and the re-prompt loop.

Gate: `pytest` on the new file (11/11) plus every test file importing the touched modules (~66 files) — all green under `-n 4`. One preexisting failure on origin/main confirmed by stash-compare and unchanged by this PR: `test_round23_help_guidance.py::test_room_workspace_resolution_failure_maps_exception` (resolve_dirty_state returns the no-preview message before the mocked `commit_preview` is reached — impl/test drift from an earlier wave).

## Not addressed (deliberate headroom)
- ~300 `showMessage` notices remain permanent-by-design ("last action" text) — audited as honest, not mass-converted.
- Solver work still runs on the UI thread in a few paths with WaitCursor (bounded, acceptable); bundle ops already use `NativeWorkerPool`.
- Workspace-level focus restoration after dialogs is Qt-default (returns to prior focus widget) — no regressions found.

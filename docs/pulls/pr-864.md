## Summary

REV65 shell-slice deep review (`application_pages`, overview/journey/envelope surfaces) of `408ec651..main`. Three confirmed defects in `CaptureInboxPage` (`application_pages.py`); all other reviewed surfaces verified clean (review record: `docs/reviews/rev65-shell.md`).

- **`_sync_contribution_detail` rebase-context block**: new bare `except Exception` silently degraded every failure — including `IntegrityError`/`SealError` from the sealed store — to "no context" and disabled the rebase/apply buttons. Now `EXPECTED_OPERATION_ERRORS` + `is_authority_failure` re-raise, and expected failures are recorded via `report_boundary_failure(operation='再基準コンテキストの解決')` before degrading closed.
- **`_sync_contribution_detail` evidence block**: `f"証跡: 解読失敗（{exc}）"` leaked raw `str(exc)` into the operator-visible detail pane (raw `[Errno]`/pydantic noise). Now renders `operation_error_message(exc)` and propagates authority failures — matching the convention already used by `_run_export` in the same file.
- **`_record_rebase_decision` task picker**: undecided-task labels were `task_id[:8] + reason`, then `labels.index(choice)` bound the decision. Two undecided tasks sharing the 8-char prefix and reason collide, and the second pick records the decision against the first task. Labels now disambiguate duplicates with the full `task_id` (same idiom as `device_labels` in the mission dialog).

Tests: `backend/tests/test_rev65_shell.py` (5 tests — each fix verified failing on pre-fix code, passing after; the Qt slot-absorption behavior is exercised by detaching `itemSelectionChanged` and invoking the sync directly). 52 tests across `test_application_pages`, `test_golden_path_journey`, `test_overview_readiness`, `test_overview_lifecycle`, and the new file all pass offscreen.

## Findings (report only)

- `golden_path_journey`: `export` step marks done at `verified` while its detail still says 「いつでも出力できます」— judged intentional final-milestone presentation; steps also evaluate state independently, so later steps can be done while prerequisites aren't (guidance-only strip).
- `applicability_envelope_panel`: displays `solver_domain`/`capability=supported` as raw tokens — the authoritative report (`cad_applicability_envelope`) renders the same tokens, so this matches designed vocabulary exposure.
- `list_*` calls in `_refresh_missions`/`_refresh_contributions` are unguarded (uncaught boundary via Qt slot) — consistent with all existing refresh methods.
- `_sync_contribution_detail` early return leaves `self._selected_contribution` stale — unreachable in practice (requires `_active_rebase_context` set, which is cleared first).
- New buttons lack `setAccessibleName` — 14/20 pre-existing buttons in the same file also lack it; not an established convention.
- `_export_mission_dialog` doesn't force a `.json` extension on the chosen filename (bytes written are identical regardless).
- Half-wired `apply_record`/`rebase_record` configs would leave a visible-but-permanently-disabled button — actual wiring is always complete.

## Summary

`NativeWorkerPool.start` connected `worker.completed` directly to the caller's `on_completed`. `completed` emits inside `NativeWorker.run` on the worker thread, and PySide only *queues* delivery to receivers with QObject thread affinity — a plain callable (lambda, bound method of a non-QObject owner like `WorkflowApplicationComposition`) is invoked **directly on the worker thread**, where its Qt calls (dialogs, `QMessageBox.exec()`, status surfaces) deadlock — the REV24-UXFLOW deadlock class, previously fixed per call site.

Each task now gets a `_WorkerCompletionRelay` — a QObject with owner-thread affinity — that forwards the payload tagged with the Python worker object it was created for. `_dispatch_completed` gates on the live task record **and** `record[1] is worker` (Python-object identity) before invoking the callback:

- vs `QObject.sender()`: the queued metacall stores a raw C++ sender pointer; if the emitting worker is freed before dispatch its address can be reused by the next task's worker — a stale emission would then look live and deliver a cancelled/`WORKER_CANCELLED` payload to the new task's callback (reproduced under `test_worker_state_machine_walk` load). The relay's strong ref pins the emitting C++ object until the metacall is consumed, so reuse cannot happen; identity is compared on Python objects.
- vs `disconnect` alone: Qt cannot retract a metacall already posted — the dispatch-time record gate drops those.

**Teardown design (the part that regressed the earlier attempt):**
- **Callback raises** → propagates out of the slot to `sys.excepthook` (native-diagnostics + uncaught surface); never swallowed.
- **Callback after shutdown/stop_all/detach** → the record is popped at release; every later delivery (including metacalls already in the queue) is dropped at dispatch.
- **Relay lifetime** → on release the relay is popped from `_relays` and `worker.completed.disconnect(relay.receive)` severs the connection — *never* `deleteLater`: the relay wrapper is the last owner of `self._worker`, so a deferred delete cascades into destroying a moved-to-thread worker inside `sendPostedEvents` — the same Windows abort the pool's worker wiring avoids (verified: deterministic `Fatal Python error: Aborted` in fixture teardown under the deleteLater design; disconnect-based release is stable across repeated runs). The orphan C++ relay lives as a pool child and dies with the pool.
- **Worker finishing while UI torn down** → `destroyed → _detach_all` keeps threads alive at module scope (unchanged `_LINGERING_THREADS` graveyard semantics).

**Call-site audit** — every `pool.start` `on_completed` now lands on the pool's owner thread:

- `workflow_application.py` — the `_BundleJobCompletionRelay` workaround is folded in and deleted; `_bundle_job_completed` (plain-class method that runs `QMessageBox.exec()`) is passed directly. This was the only non-QObject receiver hazard.
- All other `pool.start` callers (`room_prediction`, `system_expansion_widgets`, `robustness_authoring_panel`, `prediction_workspace`, `optimization_*_controller`, `measurement_page_workspace`, `measurement_editor`, `joint_optimization_panel`, `automatic_backup_runner`) connect QObject receivers — already queued-safe; now also protected by the dispatch gate.

**`analysis.export_bundle` moved to the bundle pool** (bounded UI-blocker): the synchronous path re-verified every measurement's evidence bundle (SHA-256 over stored asset bytes) plus series assembly behind `WaitCursor` — measured well over 100 ms on projects with real capture data and unbounded by construction. Two hops: `_analysis_export_prepare` (worker) → `_analysis_export_prepare_done` (UI: warnings + `QInputDialog`/dir prompts, strings unchanged) → write job → `_analysis_export_write_done` (UI: result dialog). Cancel is cooperative (`cancel_event` re-checks); `WORKER_CANCELLED` still surfaces through `_bundle_job_completed`.

**`_region_shell_triangles`** gets `_surface_triangle_indices`: an identity-keyed (`id()` + weakref purge) per-compiled-geometry `surface_id → triangle indices` map — `R120CompiledGeometry` is a frozen hash-validated model, so hash-keyed memoization would cost as much as the scan it removes. Row order is identical to the old per-region linear filter.

New regression tests in `test_native_worker.py`: owner-thread delivery, queued-before-release drop, superseded-worker drop, callback exception surfacing without wedging the pool.

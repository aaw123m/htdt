## Summary

Round 9 of the iterated review program — the error & failure journey: what the user actually sees when cancel, partial failure, uncaught exceptions, startup corruption, and I/O failures happen. Full audit, evidence, and deferred sketches live in `docs/reviews/round9-errors.md`. Prior-round surfaces (round-6/7 string-leak sweep, round-8 store recovery, round-9-report atomic writers) were verified for regressions, not re-audited.

Highest-severity defects fixed:

- **`CommandHistory` corrupted itself on failing commands.** `push` mutated `_commands`/`_index` *before* calling `command.apply`; `undo`/`redo` consumed the index step around a `revert`/`apply` that could raise. A raising command therefore recorded itself, truncated the redo tail, or made the next undo revert a command that was never applied. All three methods now apply/revert **before** any index mutation — a raise leaves history byte-identical.
- **Uncaught slot exceptions were invisible.** PySide6 6.11.2 routes them to `sys.excepthook` (verified offscreen); `install_exception_hooks` logged them to `htdt-native.log` but showed nothing. The hook now also posts a non-modal status-bar notice (`予期しないエラーが発生しました（詳細: <log path>）`, 10 s) via `_surface_uncaught_on_statusbar` — GUI-thread only, exception-safe, worker threads stay on the `completed` channel.
- **Permission-denied data dir exited the GUI silently.** `native_cad.main` caught only `ManagedDataUnavailableError`; a raw `OSError` (bootstrap config, relocation journal) hit `print(stderr); return 1` — invisible in a packaged launch. The catch is now `except Exception`, moved after launch-mode resolution: maintenance modes keep stderr+exit, GUI mode shows `report_launch_failure`.

Supporting fixes:

- `NativeWorker` emits the exception object (not `str(exc)`) as the `completed` error payload — type information now survives the thread boundary for class-based mapping. All consumers audited; `WORKER_CANCELLED` sentinel comparisons unaffected.
- `CommandRegistry.set_error_handler(handler)` gives the single dispatch point (palette, shortcuts, menu actions) a failure surface; the composition wires it to `warn_user(shell, '「<command>」', exc)`. No handler → exceptions propagate as before.
- `user_facing_error`: `RewApiUnavailable` maps to `rew.unavailable` (ordered before its `RewApiError` base); `ENOSPC` maps to `io.no_space` "ディスク容量が不足しています".
- `measurement_workflow` per-item batch errors (`dataset_error`, stage/commit `entry.error`) and `workflow_application` import/export/backup failure paths now carry mapped localized messages via `warn_user`/`operation_error_message`; raw `{exc}` embeds fixed across `room_workspace`, `optimization_extended_controller`, `optimization_search_controller`, `room_prediction`, `application_pages`.

Verified honest, not bugs: worker cancel is cooperative (Event + bounded shutdown + `_LINGERING_THREADS`, documented); `ActivityCenter` never fakes determinate progress; data-management batch failures report per-item localized messages; launch intents dead-letter malformed descriptors with honest dialogs; capture delivery validates hash/length/idempotency.

Deferred with sketches: persistent surface for uncaught exceptions (status-bar notice is transient); per-op cancel-polling audit for can't-interrupt callables; surfaced retry for REW transport failures; per-command error-handler override.

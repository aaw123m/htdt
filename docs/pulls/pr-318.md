## Summary
Round-4 review of `benchmarks/` + numerical paths (`docs/reviews/round4-numerics.md` documents the full hunt, incl. verified-clean areas and deferred items). Five fail-open/fail-wrong gaps were verified against a live interpreter and closed; all other candidates checked clean.

- `acoustic_bakeoff_observation.evaluate_monotonic_convergence_observable` — an all-zero finest reference made `relative_rms = inf`, then the `BakeoffObservableEvidence` finiteness validator raised `ValidationError`: the evaluator **crashed** instead of returning `fail` evidence for exactly the case the gate exists to reject. Now emits `relative_error=None` (the existing `_relative_error` zero-magnitude convention); status remains `fail` via the already-appended violations.
- `acoustic_bakeoff_observation.evaluate_sampled_observable` — accepted sampled observables carrying `monotonic_convergence` / `matches_peer` / `must_differ_from_peer` / `repeatable_same_seed` / `continuous_overlap` and scored them by plain tolerance without evaluating the declared contract. Now raises for any relation other than `matches_reference` (zero blast radius: all non-`matches_reference` observables in `r100a_manifest.json` have `samples: ()`).
- `comparison.compare_frequency_responses` — no input validation: empty axis → `IndexError`; non-finite/non-positive frequency → raw `ValueError`/`OverflowError` from `math.log2`; NaN `level_db` → plausible-looking wrong metrics (mean=-1.0 for a NaN point) that survive until `allow_nan=False` canonical JSON. New `_validate_response`/`_validate_band` raise `ComparisonError` (subclasses `ValueError`). `COMPARISON_ALGORITHM_IDENTITY`/SHA256 untouched; all previously-valid inputs produce bitwise-identical output.
- `cad_benchmark.evaluate_observable` — reference and prediction band values were paired **positionally after independent filtering, comparing counts only**. Reference `[100,200]` Hz vs prediction `[150,250]` Hz returned `PASS error=0.0`. Now `_band_values` converts eagerly (non-finite/non-numeric samples → `UNKNOWN` instead of silently dropped/crash) and mismatched frequency grids → `UNKNOWN 'missing or misaligned'` for both `magnitude_fr` and `complex_transfer`.
- `cad_benchmark` tolerances — `gt=0.0` admitted `inf` → fail-open (`error=9e9` returned `PASS`). `allow_inf_nan=False` on `BenchmarkObservable.tolerance`; `EvaluationProfile` validator requires finite positive overrides.

Deferred with remediation sketches in the doc: `_point_in_triangle` compares a m⁴ discriminant against a m tolerance (slivers ≤1.6e-5 m² misclassified; sibling polyhedral kernel uses m² consistently); `EvaluationProfile` override content not bound into evidence identity; `stochastic_sample_keys` `f{f:g}` label collisions; `acoustics.py` missing-speaker-id `KeyError`; importer non-list payloads raise `AttributeError` instead of `ValueError`.

## Summary

REV28 fail-closed & capability-gate audit track: dynamic probes (write-and-execute, not read-only review) verified six cases where a gate silently claimed capability it could not prove. All are fail-closed violations of the repo's core invariant; each fix is minimal and ships with a regression test.

## Defects fixed

1. **Fabricated boundary-distance PASS for exterior listeners** (`cad_standards_layout_observation._boundary_distance_m`): distance-to-boundary was measured for seats *outside* the room polygon, producing a real-looking observed value. Now `polygon.covers(point)` is required before deriving — exterior listeners yield no derivation → criterion UNKNOWN.
2. **Garbage azimuths from near-degenerate forward axes**: `_listener_references` guarded only `norm == 0.0`; a `roll_deg≈90` seat leaves xy-norm ≈1e-16 and still produced azimuths. Now `norm < _MIN_FORWARD_XY_NORM (1e-6)` → no azimuth criteria derived.
3. **Fabricated azimuth for co-located speaker/listener**: `_signed_azimuth_deg` normalized a ~zero vector (quaternion residue → e.g. 180.0°). Now returns `None` when xy distance < 1e-9 m; pair candidates filter out missing azimuths and a dolby-role group with no measurable pair stays underived.
4. **Criterion-id reuse served the wrong quantity**: `derive_layout_observations` keyed only on `criterion_id`, so a user profile could mint an authority claiming a quantity the lane never measured. Now the declared `(quantity, unit)` must match `_DERIVED_QUANTITY_UNIT` or the criterion stays UNKNOWN and no authority is written.
5. **Unknown stimulus level reported ready** (`run_playback_preflight`): `digital_level_dbfs=None` skipped every level check → `automated_start_permitted=True`. New `unknown_test_level` reason (severity `confirm`) blocks automated start and requires confirmation.
6. **UTF-16/UTF-32 DOCTYPE bypass** (`xml_guard`): the doctype scan only matched the UTF-8 byte pattern, and the docstring's claim that pyexpat rejects wide-encoded DTDs is false — a probe showed `<!ENTITY>` expansion succeeded on UTF-16 input. Now BOM-prefixed UTF-16/32 is decoded+rescanned and BOM-less UTF-16 is sniffed via `<\x00?\x00` / `\x00<\x00?` prefixes.

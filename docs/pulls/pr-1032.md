## Summary

The 測定 → 品質 page's 保存済み測定 table (issue #969) gains combinable filters with honest counts, an id-keyed selection model, and an adaptive detail layout — verified offscreen and on the real GUI at ~1280 and ~900 px.

**Filters (new bar above the table):** 品質 (verdict) / 状態 (attention facets) / 入力 (channel role) / 測定位置 (position) combos + free-text search + 絞り込みをクリア. All intersect (AND); the count label states `N件中M件を表示`. 状態 facets are derived honestly per row (要対応 / 要再測定 / レポート再評価 / 校正が未確認・不合格 / 検証エラー / 除外) — only *evaluated* calibration checks count for the calibration facet. Choices rebuild from the current listing; a vanished value resets to すべて.

**Id-keyed selection:** the table is now sortable, and every row→record lookup resolves `measurement_id` from `Qt.ItemDataRole.UserRole` (`_quality_row_index_for_id` / `_quality_view_for_row`) — selection can't drift across sort/filter/refresh. A selection note states *why* a selection is not shown (filter-hidden vs vanished) instead of silently pointing at another row; `focus_entity`/`select_measurement_id` clear filters to reach a hidden deep-link target. After repopulation the refresh re-applies the header's sort indicator via `sortItems` — fixes a one-click-late first sort observed on the real GUI.

**Adaptive detail:** `quality_split` flips Horizontal→Vertical when the scroll viewport drops below `1180 px` (`_QUALITY_DETAIL_STACK_MIN_WIDTH`, keyed on `page.viewport()` — the page host can't shrink below its own ~1160 px minimum, so its width never signals "narrow"). Detail now leads with `測定ID: <id>` + rationale + evidence + retake/disposition next-action path.

**A11y:** JA `accessibleName` on all filter controls/table/detail; detail is `StrongFocus` + keyboard-selectable; `quality.filter.*` explanations registered.

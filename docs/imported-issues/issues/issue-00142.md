## 目的

現在存在しないspeaker/channelをDigital Twin上へ **Proposed entity** として追加し、channel topology・speaker model・配置可能領域・高さ・aim/toe-in等を定義して、既存O10〜O90 authorityを使いながら最適なsystem expansion候補を比較できるようにする。

代表例:

- 現在3.0.2のprojectへSL/SRを仮想追加
- SL/SRのallowed region、高さ、壁離隔、左右連動、aim範囲を指定
- 3.0.2 vs 5.0.2、または複数のSL/SR配置案を比較
- 対応source/directivity modelがあればcoverage/SPL/seat variation等を評価
- O90で設置誤差耐性まで比較
- 実際に導入後はProposedからAs-built/Measuredへ昇格し、REW実測でvalidation

## Core semantics

- existing/as-built speakerとproposed/virtual speakerを同一状態として扱わない
- 3.0.2等のcurrent topologyを破壊せず、SystemVariantとして派生させる
- speaker roleは固定schemaにせず、versioned LayoutProfile / role definitionへbinding
- Proposed speakerはsource model provenanceを必須化し、unknown directivity/SPLを捏造しない
- channel-independent predictionとmulti-channel excitation scenarioを分離
- absent speakerにmeasurement evidenceを偽装しない
- topology/configuration/placement/equipmentを一つのhidden scoreへ縮約しない
- production recommendationは対象objectiveのR-series/O60/R180 evidence gateを迂回しない

## Proposed implementation slices

### O100A — Proposed system variant authority
- immutable SystemVariant / ProposedEntitySpec / ChannelRoleBinding
- current/as-built/proposed/measured state separation
- variant diff and exact SceneRevision derivation
- add/remove/replace speaker candidates without mutating baseline

### O100B — virtual channel placement search
- per-role allowed/exclusion region
- XYZ/height/aim/toe-in bounds
- linked symmetry / pair constraints
- O10/O80 candidate generation reuse
- feasibility and exact provenance

### O100C — source/equipment capability integration
- EquipmentDefinition/source model binding
- directivity capability
- sensitivity/SPL/headroom inputs where evidenced
- unknown/magnitude-only/complex capability separation
- multiple equipment alternatives as explicit variants

### O100D — topology/objective comparison
- 3.0.2 vs 5.0.2 etc as named SystemVariant comparison
- coverage / seat variation / SPL/headroom / FR / reflections / installation cost as capability-gated independent objectives
- StandardsProfile/layout-angle evaluation when available
- no opaque "best system" score

### O100E — multi-fidelity topology search
- topology → geometry/profile → coverage → acousticの段階screening
- approximate pruningはaudit可能にし、最終比較はcommon fidelityで行う
- canonical roadmap O100Eの使用R-series capability条件に従う

### O100F — robust expansion
- O90 tolerance analysis on proposed speaker position/aim
- compare nominal vs robust system variants
- candidate-specific installation tolerance overlays

### O100G — UX / lifecycle / as-built promotion
- Room: 「スピーカーを追加（仮想）」 / proposed badge
- Optimize: 「構成比較」 / 「追加スピーカー配置」
- 3D ghost styling for proposed entities
- apply selected variant as a new SceneRevision
- installation completion creates As-built state; does not rewrite proposal evidence
- measurement campaign can then bind to the installed SceneRevision

## Acceptance focus

- current 3.0.2 project can create an immutable 5.0.2 proposed variant containing SL/SR
- SL/SR have independent or linked allowed regions and search axes
- no baseline SceneRevision mutation until explicit apply
- unsupported source/directivity capability blocks affected objectives rather than fabricating

## Summary

Implements #810 — acoustic validation is now uncertainty-aware instead of relying on a universal holdout RMS threshold (ASME V&V 20, GUM/JCGM 100/101, Thydal 2021 VUQ, ISO 3382).

**New authority** (`cad_validation_uncertainty.py`, `cad_validation_uncertainty_repository.py`; schema v85, full audit wiring + JA labels):

- `ValidationUncertaintyProtocol` — sealed, preregistered, versioned contract: every production-relevant observable is declared as a `ValidationObservableMetric` (quantity/unit/domain/comparison metric/applicability band/minimum uncertainty semantics + a `UncertaintyDecisionRule`).
- `ObservableUncertaintyEvaluation` — binds one (observable, candidate, split) and evaluates residuals **per band** via GUM combination of declared measurement-side and prediction-side uncertainty. Quadrature unless a bounded `declared_bound` side or `declared_correlated` policy forces linear combination; the weakest side's semantics governs the result, and a side below the declared minimum fails closed.
- `UncertaintyValidationVerdict` — aggregates bound evaluations + an optional legacy `CadModelValidationRecord` snapshot into the study verdict. `EvaluationBinding` snapshots are re-checked by the repository against stored records, and `protocol_observable_ids` re-checks that the verdict was judged against the protocol's sealed observable set.

**Fail-closed vocabulary** — `BandUncertaintyVerdict` (consistent / discrepancy_significant / below_evidence_resolution / evidence_too_uncertain / insufficient_uncertainty_information), `ObservableUncertaintyVerdict` (+ model_form_discrepancy_required / reference_too_uncertain / input|numerical_uncertainty_dominates / band_coverage_incomplete / insufficient_evidence), `AbsoluteValidationVerdict`, `CalibrationEvidenceState`, `RankingVerdict`. Missing budget, missing measurement uncertainty, spectral gaps, and un-evaluated declared observables can never read as agreement.

**Hard rules**

- Calibration and holdout are absolutely separate — `CadValidationPair.split` dictates admissibility; a record cannot serve both roles and both splits of the same (observable, candidate) can never bind one verdict.
- Bounded inputs (`declared_bound`, propagated `combined_bound`) are never silently converted into probabilistic sigmas; correlation policy is explicit (`independent_unless_declared` / `declared_correlated`).
- Model-form discrepancy stays distinct: a significant residual demands `model_form_discrepancy_required` unless a declared model-discrepancy envelope covers it — it can never hide inside measurement uncertainty.
- JND is annotation-only (`PerceptualInterpretation.role = 'perceptual_interpretation_only'`), never an uncertainty source.
- `max_holdout_rms_db` remains a valid input — the record is snapshotted (`legacy_*` fields) and reported as one metric — but can never alone yield `consistent_with_reference_within_uncertainty`. Ranking/trend accuracy is a separate verdict; this work enables no production recommendation.

**Tests** — `backend/tests/test_issue_810_uncertainty.py` (87 tests): every verdict path incl. all insufficient-evidence paths, declared-observable coverage, all three combination semantics, split-mixing rejection, seal/id integrity, repository round-trip + tamper detection, snapshot restatement checks, JA labels. `docs/issues/issue-810-uncertainty.md` documents scope, vocabulary, and integration points.

## Summary

Refs #995
Refs #994

The field explorer's slice path froze the GUI and could allocate ~394 MiB for one pixmap: `explorer_slice` + a per-pixel Python raster loop + `QPixmap.scaled(w*8, h*8)` all ran synchronously in the GUI event handlers, and a failed/deselected selection left the previous heatmap painted (#994).

- **Worker-side compute**: slice extraction, `SliceRaster` rasterization and `QImage` construction run on a `NativeWorkerPool`; `QPixmap` conversion + paint stay on the GUI thread. Session build + repository save are worker-side too (~4M-sample builds take seconds).
- **Debounce + epoch gate**: every control edit bumps a monotonic `request_id`, cancels the in-flight raster, and queues one request behind a 120 ms debounce — 100 rapid edits collapse into a single bounded final render; superseded payloads are dropped at `_slice_job_completed` and re-verified against current combo state in `_apply_slice_result`.
- **Honest decimation**: `FIELD_SLICE_MAX_RASTER_CELLS = 1_000_000`; `SliceRaster` subsamples by the smallest uniform integer stride (binary search) and the status line labels it (`表示 501x501 (間引き x2 · サンプル本体は不変)`). Canonical samples/sealed authorities are never touched; `lo`/`hi`/`hidden` are measured on the FULL slice so an extremum can't hide in a dropped cell.
- **Bounded paint memory**: `FIELD_SLICE_MAX_PIXMAP_EDGE=2048` / `FIELD_SLICE_MAX_PIXMAP_PIXELS=4_194_304` cap the painted pixmap to ≈16.8 MiB worst case (was ≈164–394 MiB).
- **#994 clearing**: unsupported quantity, missing plane/coordinate/session, worker failure, deselect, or cancel all clear pixmap + scale bar + probe readout and show the mapped reason. Probe readout is now context-bound to (session, quantity); an armed 3D overlay unchecks itself when its request becomes impossible.
- **Busy affordance**: indeterminate `QProgressBar` + 「キャンセル」 while slice/build work is in flight; cancel reports honestly (`断面計算をキャンセルしました · 表示条件を変更すると再計算します`).

## Layout feedback-loop fix (found on real GUI)

First verification found the painted slice never persisted + busy row never hid — a `field_image_label` Resize→`_refresh_view`→repaint→Resize feedback loop. Fixed structurally: `QSizePolicy.Ignored` on the label, fixed-height busy row, repaint-only-when-device-target-diverges (>12 px dead-band) via a new `_request_repaint` path that re-renders the same selection **without** clearing the current paint; `ScreenChangeInternal` (DPI move) covered. Re-verified fixed end-to-end.

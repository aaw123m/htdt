## Summary

Implements the issue #878 target-adapter capability-negotiation + strongest-path selection slice: every deployment target now publishes a sealed capability manifest, deploys run as sealed staged transactions with operator authorization pinning, and a fail-closed evaluator ranks deployment paths by evidence strength (`machine_readback > applied_ack > file_verified > assisted_attestation`), callable by the #868 orchestrator.

Key pieces:

- `cad_deployment_pipeline.py` — `DeploymentPipelineService` drives `opened → baseline_captured → compiled → previewed → authorized → applied|partial_write → readback_matched|diverged → rollback_verified|failed`; `DeploymentOperatorAuthorization` (one-shot, scope `apply`/`rollback`) pins the candidate materialization sha and is validated before the stage gate; `derive_pipeline_evidence_strength` re-derives strength from pinned mechanism/verdict fields, so the record validator rejects overclaim — machine-readback evidence is never claimable from file writes.
- `AdapterCapabilityReport` extends with `deploy_mechanism`/`readback_mechanism`/`rollback_mechanism`/`runtime_observation`/`supported_features`/`limit_notes`/`auth_requirements`/`applicability`/`protocol_authority` — all default fail-closed; the #838 registries (`cad_camilladsp_deploy`, `cad_device_adapter_file`, `cad_minidsp_export`, `cad_rew_provider`, `cad_measurement_target_registry`) publish them via `build_capability_declaration` on `DeploymentCapabilityDeclaration`.
- `cad_avr_lan_adapter.py` — `AvrLanCalibrationAdapter` claims only the documented Denon/Marantz telnet grammar (`CV<ch> <val>` trims, 38–62 in 0.5 dB steps, `CV<ch> ?` readback, baseline-restore rollback); delay/crossovers/PEQ/routing surface as `unsupported_items`. `AvrLanTransport` protocol + `FakeAvrLanTransport` (records itself `protocol_authority='simulated'`, `production_eligible=False`); non-loopback endpoints require `approved_remote_endpoints`.
- `MINIDSP_DEPLOYABILITY` — sealed registry built from `list_dsp_target_profiles()`: all 23 miniDSP profiles classified `assisted_only` (no documented machine API pinned); `UnknownMinidspModelError` on unknown ids.
- `EqualizerApoInstaller` — bytes-exact install + installed-file re-read + content-sha comparison seals `ApoInstallRecord` with `file_verified` only on `content_sha_matched` (distinct from "file written"); optional `verify_exported_apo_config` semantic check on installed bytes.
- `AssistedInstructionManifest` + `AssistedDeploymentAttestation` — step-specific instructions, all declared steps required, `post_measurement_required` pinned, strength fixed at `assisted_attestation`.
- `evaluate_deployment_path`/`rank_deployment_paths`/`select_strongest_(production_)path` + `evaluate_deployment_paths`/`select_deployment_path` methods on the commissioning orchestrator.
- Persistence: `CadDeploymentPipelineRepository` + 5 sealed tables (`cad_deployment_pipeline_records`, `cad_deployment_operator_authorizations`, `cad_assisted_instruction_manifests`, `cad_assisted_deployment_attestations`, `cad_apo_install_records`) — schema v102 with `_ROW_BINDINGS`, `_RepositoryChain`/`_ReplayProbe` wiring, lifecycle JA labels, schema ledger row.

## Summary

Implements #876: machine verification of channel identity, routing, and polarity for configured speaker layouts — REV67 self-slice, native schema v100.

`cad_channel_verification.py` — sealed `ChannelVerificationPlan` (`cvpl-`) derived from declared #621 `CadChannelIdentityChain` records (chains without an exact routing are rejected, fail closed). `run_verification_plan` drives each channel through the #869 `MeasurementAcquisitionEngine` (configure → arm → start); every excitation is sealed through the real #869 evidence authority (`record_run`), so `acquisition_run_ref` pins the retained `swrun-` sha rather than a synthetic id digest.

Analysis: response arrival is measured against the IR window origin (channel-index-independent); `level_dbfs` is the engine-measured sweep-window signal level (`noise_floor + snr`) — the deconvolved IR is unit-normalized and carries no level evidence. `response_signature_sha256` hashes (arrival, quantized level, polarity sign): two logical channels yielding identical signatures cannot both be machine-verified (`duplicate_suspect`, map `ambiguous`).

Verdict ladder (`evaluate_channel_verdicts`):
- routing: `verified` / `missing_output` / `duplicate_suspect` / `level_mismatch` / `unverified`
- polarity (vs `reference_channel` only): `consistent` / `inverted` / `unevaluated`
- evidence: `machine_verified_routing` / `machine_verified_relative_polarity` / `machine_assisted_ambiguous` / `operator_attested` / `unknown`
- a simulated backend caps evidence at `machine_assisted_ambiguous` — a fake run never proves real wiring; `OperatorChannelAttestation` (`cvoa-`) is a permanently-manual fallback that can only upgrade `unknown`/`ambiguous`
- map: `verified` (all machine-verified) / `failed` (hard defects) / `ambiguous` (signature collisions, attestations) / `incomplete` / `unknown`

`stale_channels_for_routing` pins a routing-signature sha per result so a routing change stales only the affected channels. `cad_channel_verification_repository.py` persists all four record kinds via `_SealedStore` (column drift checks, append-only, `ChannelVerificationConflictError`), with `_ROW_BINDINGS`, 4 `_ReplayProbe`s, and JA labels wired. 22 tests cover plan validation, scripted-backend drives (verified/inverted/missing/duplicate/level-mismatch/simulated/attested/staleness), repository round-trips and tamper rejection, and sealing invariants.

## Summary

REV26-QTSTAB: kill the nondeterministic xdist worker-teardown crash class (`worker 'gwN' crashed` / `node down: Not properly terminated`) that two convergence passes flagged — `test_save_focused_editor`, `test_workflow_application`, sporadic GUI-adjacent workers. All passed serially; they only died under `-n 4`, at interpreter/fixture teardown.

**Root cause — orphaned worker threads ran un-cancelled through process exit.** Composition tests never fire close hooks (a hidden widget's `close()` is a no-op, so `_shutdown_bundle_pool`, `AutomaticBackupRunner.shutdown`, etc. never run). When the shell/controller is then destroyed, the linger maps detach the still-running QThread — but neither detach path set the cooperative cancel flag. The orphaned job (backup scan, sqlite copy loop) kept churning to natural completion across later tests and into interpreter teardown, where `~QThread` terminated the thread mid-operation → sporadic abort. Rate matched observations: needs a thread both leaked AND mid-work at the exact teardown moment.

**Fix (shared level — no xfail/skip, no weakened assertions):**

- `native_worker._detach_all` now `cancel_all()`s before detaching — a dying pool stops its work cooperatively instead of abandoning it running.
- `data_management._detach_active_thread` now `request_cancel()`s the job before reparenting — same contract.
- New shared drains: `drain_worker_threads()` (`_LIVE_POOLS` WeakSet + linger map → `stop_all`/cancel+interrupt+quit+bounded wait) and `drain_operation_threads()` (`_LIVE_CONTROLLERS` + linger map → same). Both return the still-running count; remainders stay detached by design — `QThread.terminate` corrupts GIL/SQLite/native state, never used.
- `atexit` hooks in both modules drain at interpreter exit — covers the real app teardown path too, not just tests.
- `conftest.pytest_sessionfinish` (per xdist worker): pump DeferredDelete + `gc.collect` so `destroyed` handlers fire and detach stragglers into the maps, then call both drains, then final pump. Per-test fixture also guards `deleteLater` with `try/except RuntimeError` for half-dead wrappers. `close()` stays avoided deliberately — a dirty shell's `closeEvent` can open the modal dirty-mount resolve dialog, which hangs forever offscreen.

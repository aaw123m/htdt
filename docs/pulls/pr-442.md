## PR 本文 (原文復旧 — devin-5b4afa91)

## Summary

REV24-PERFACC (#437) memoized path-independent geometry but left every occlusion query as O(segments × triangles): `_segment_blocked`, the late-field `_segment_blocked_ignoring_triangles`, and the portal region-shell membership scans each iterated all candidate rows per query. This PR adds a dependency-free uniform-grid spatial index (new `occluder_grid_index` module) and threads it through all three paths. The index only narrows candidates — the existing exact Möller–Trumbore / point-on-triangle tests still decide every verdict, so results are identical.

## How it works

- `_UniformOccluderGrid` partitions rows into uniform cells over their shared AABB (`~4 cells/row` density, ≤64/axis). Each row is inserted into every cell overlapped by its AABB **inflated by `0.25·(|e1|+|e2|)`** — the maximum distance an exact hit point can lie outside the AABB, since both exact tests cap barycentric tolerance at `min(0.25, tol/scale)` (unscaled callers only ever pass `geometric_tolerance_m`, an epsilon ≪ 0.25). The grid box itself is padded by the largest row bound. This makes the candidate set a *provable superset* of exact hits, not a heuristic.
- `candidates(start, end)` slab-clips the segment to the grid and walks traversed cells via 3D DDA (Amanatides–Woo), yielding deduplicated rows. `point_candidates(point, radius)` yields rows of cells overlapped by `point ± radius` (boundary-query analog of the same superset).
- `_IndexedOccluderRows(tuple)` carries the grid lazily — identical iteration/unpacking semantics to the plain row tuple, so all existing call sites and external callers keep working. `isinstance` dispatch keeps plain-tuple inputs on the identical linear path; single-shot default paths wrap in `tuple()` to skip grid construction.

Applied at:

- `_occluder_triangles` → `_segment_blocked` (GA occlusion)
- `execute_late_field_energy`'s `occluder_records` → `_segment_blocked_ignoring_triangles` (late field)
- `_region_shell_triangles` → `region_membership_with_portal_caps` (boundary `_point_on_triangle` scan + 3 parity-ray scans) and `region_segment_membership_with_portal_caps` (crossing scan). `region_shell_cache` already stores the returned object per execute, so one grid serves all membership queries for that region.

## Proof of identical semantics

- New `test_segment_blocked_uniform_grid_matches_brute_force` / `test_segment_blocked_ignoring_triangles_grid_matches_brute_force`: 3000 random segments × {1e-9, 1e-6} tolerances × {scaled, unscaled} with ignored ids — **0 verdict mismatches** vs the plain-tuple path.
- New `test_indexed_occluder_rows_bare_rows_cover_exact_hits`: segment/point candidates on bare `(va,vb,vc)` rows are a superset of every `_ray_triangle_parameter`/`_point_on_triangle` hit, plus a dedup invariant.
- Golden results unchanged: 85 tests in the 3 touched-path files and ~650 tests across all 28 files exercising these paths pass with zero failures.

## R110 byte-verification caching — deferred (per task rule)

`verify_managed_asset` (`managed_assets.py`) re-hashes file bytes on every read, but the codebase keys caches exclusively by content/semantic identity — no revision- or mtime-keyed file verification cache exists to extend, and the content-addressed contract is deliberately self-verifying per read. Implementing memoization would introduce a new cache-invalidation contract, so it stays deferred.

## Remaining headroom

- `_region_shell_triangles` itself still enumerates all compiled triangles per region (build-time, O(triangles) once per region per execute) — fine at current scene sizes; a scene-revision-level index would amortize it further.
- Repository save/get (~550 ms) is dominated by canonical-JSON + SQLite I/O, not occlusion — untouched.

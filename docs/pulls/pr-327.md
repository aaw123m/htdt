## Summary

Round 7 review pass on solver & measurement math (report: `docs/reviews/round7-accuracy.md`). Three accuracy bugs fixed with regression tests; one HIGH finding deferred with analysis.

**IR reflection markers ignored `time_zero_sample`** (`cad_ir_analysis.py`): `delay_s` is documented as "relative to the direct-arrival sample" but the code hard-coded `direct_index = 0` — i.e., window start. With any pre-roll (`time_zero_sample > window start`), every marker delay was inflated by `(t0−start)/fs` and pre-t0 energy was reported as a reflection. Verified live: a reflection 3 ms after a 10 ms direct read as 13 ms. Now `delay_s = (i − t0_index)/fs` with markers restricted to `i > t0_index`, reusing the same `t0_index` the energy metrics already anchor to. Default specs (`t0 == start`) are unchanged; `IR_ANALYSIS_ALGORITHM_SHA256` deliberately not bumped per the round-6 precedent.

**FIR materialization used `np.interp`** (`cad_fir_filter.py`): linear-interpolating an impulse response has no anti-aliasing (decimation folds out-of-band content into the passband — an 18 kHz component becomes a phantom ~6 kHz one at 24k) and droops sinc² to ≈ −8 dB at the new Nyquist on upsample. Replaced with the repo's already-tested `htdt.fft_bandlimited_resample_v1`. Also `time_reference_sample` now rescales (`round(ref·target/source)` clamped) instead of clamping the source index — the pre/post-ringing split previously measured against the wrong physical instant on any rate change. `FIR_MATERIALIZATION_AUTHORITY_VERSION` → `fir10-fir-materialization-2` so provenance records which resampler produced the taps.

**PPW spatial-Nyquist floor** (`cad_candidate_wave_execution.py`): `points_per_wavelength` accepted any positive float; below 2 the grid can't represent even one wavelength at `fmax` yet the config validated and would run a meaningless solve. Now `Field(ge=2.0)` (all in-repo callers use 8–12).

**Deferred HIGH:** `compute_minimum_phase_deg` returns `atan2(spectrum.imag, spectrum.real)` = arg(log H), not `spectrum.imag` = φ_min — flat −3 dB magnitude reports −180° instead of 0°. Not swapped because the correct extraction fails the existing golden test by ~35° (the reference cepstral implementation's own truncation bias dominates on that fixture); per the `_point_in_triangle` precedent this needs a dedicated estimator redesign + re-derived golden values, documented in the report.

Tests: full suite `pytest -q -n 4` (5303 tests) green except `test_ctrl_s_commits_focused_inspector_position` (verified failing identically on clean main — UI wiring, unrelated) and one ordering flake under `-n 4` that passes in isolation (`test_evidence_lifecycle_rejects_illegal_promotions`, unrelated module).

# #972 基準ワークスペースの検索・絞込 (状態/領域) + 件数表示

## 変更

- `StandardsCriterionPanel` (standards_workspace):
  - 検索欄 (`standardsSearch`) — 基準名・基準ID・数量・出典
    (発行元/文書名/参照箇所)・適用領域 (生キーと日本語表示の両方) を
    casefold 部分一致で横断検索 (`_criterion_search_haystack`)
  - 状態フィルタ (`standardsStatusFilter`) — 全て / 適合のみ /
    不適合のみ / 判定材料不足のみ / 対象外のみ / 未評価のみ /
    制約に選択済み (ハード制約にオプトインした項目だけを並べる)
  - 領域フィルタ (`standardsDomainFilter`) — 表示中プロファイルの
    `applicable_domains` から動的に選択肢を構築
    (`_sync_domain_filter`)。プロファイル切替で消えた選択は
    「全て」へフォールバック。未知の領域キーは生値をそのまま表示し
    虚構の訳語は作らない
  - リセット (`standardsFilterReset`) — 絞込中のみ有効。検索と両
    フィルタを一括解除。結果行の先頭 (左端) に配置し、ドックの
    横スクロールで右端が隠れる配置を避けた
  - 結果行 (`standardsResultStatus`, word-wrap 有効) —
    `フィルタ外の制約選択 K 件 · 基準 N 件 · 制約選択 M 件 · 表示 X/N`
    を表示。フィルタで選定済み制約が隠れた場合は必ず K 件を
    行頭に報告し (ドック横スクロールで語尾が切れても見える)、
    選択自体は `_selected_constraints` (criterion_id 集合) に残るため
    見えなくても `hard_constraint_gate` に効き続ける
  - レイアウトは検索 / 2フィルタ / リセット+結果行の3段構成 —
    右スタックの最小幅 (~280px) を超えないため (#986 と同じく
    細いヘッダ行を積む)
  - ツリーは7列化: 既存5列 (配置制約/基準・状態・観測値・必要条件・
    証拠) の位置は維持し、「領域」「出典」を末尾に追加
- 絞込0件時は全列スパンの 「条件に一致する基準はありません」行
  (ツールチップに適用中の絞込条件とリセット案内)、基準0件の
  プロファイルでは 「このプロファイルに基準項目がありません」
- チェック状態は `criterion_id` ベースの `_selected_constraints` が
  真実のソース — 再絞込・リフレッシュ・評価再実行をまたいで保持
  (#975 のフォーカス復元はそのまま)

## 判定権威

新たな判定権威は導入しない。表示される状態は従来どおり
`evaluate_standards_profile` の結果のみで、未評価行は「未評価」の
まま。ゲートは引き続き `explicit_hard_constraint_gate` — フィルタで
非表示の選択済み FAIL/UNKNOWN もブロックする。

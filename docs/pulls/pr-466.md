## Summary

REV29: closes the two live-reader/writer vs file-mutation races REV28 proved dynamically, with one shared idea applied twice — **hold the exclusion across re-validation + file mutation**.

**GC-vs-writer resurrection** (`run_storage_gc`): row deletes committed before `unlink()`, so a writer committing a sha256 reference in the gap produced a permanently dangling `missing_referenced`. Now two `BEGIN IMMEDIATE` transactions: txn 1 does live-check → per-candidate sha256 content verify → registry deletes + pending-ledger inserts (unchanged crash-recovery semantics); txn 2 takes a *fresh* write exclusion, recomputes `referenced_asset_digests`, and for each pending digest either restores the captured registry row + keeps the file (resurrected) or `stat`+`unlink` inside the lock and clears the pending row. Writers got the symmetric change: `ensure_installed` moved *inside* their existing `BEGIN IMMEDIATE` at all 7 `cad_measurement_assets` write sites, so republish = {install bytes, insert ref} is atomic — both orderings serialize under the same SQLite write lock. `BEGIN IMMEDIATE` also gets `_begin_immediate`'s bounded retry (4 attempts, 50–200 ms backoff) to ride out commit bursts.

**Reopen-vs-replace**: `release_read_handles_under` closed pooled read handles but lazy re-opens landed in the release→`os.replace` gap → WinError 32. New counted per-root `_ReopenFence` (`fenced_read_reopens_under`) wraps every release→swap window — `restore_backup`, `recover_interrupted_restore`, data-relocation cutover + journal recovery, `native_upgrade`. `_SharedReadConnection._reopen` and `SceneRepository._read` wait on the fence for their root *or any ancestor* before opening a handle, recheck `held()` inside the same locks the release path needs (deadlock-free), then resume on the post-swap file — readers see old-or-new, never torn. `begin_restore` needs no change: its swaps execute inside `restore_backup`'s fence.

**Verification** (throwaway probe `backend/tests/probe_rev29_atomic_swaps.py`, not committed): `missing_referenced` **17 → 0** under the same GC-vs-writer load; swap failures **30/30 → 0/30** under a reopening reader; sustained mixed load — no deadlock, 10/10 quiesced swaps, `missing_referenced=0`. Regression tests: resurrection-restore test (monkeypatched mid-GC commit), fence nested-holds test, fenced-swap-under-reopening-reader test; asset-atomicity tests re-instrumented for the in-transaction install order. 291 scoped tests green.

Residual: a fully saturated writer can still starve GC's `BEGIN IMMEDIATE` into `database is locked` past the bounded retry — fail-closed, retryable; `project_bundle`'s bulk-import `install_stream` keeps the old install-before-txn pattern (different scope/trade-off); db-only swaps can transiently resurrect a registry row whose file GC took — self-heals on the next pass and cannot arise from real swap sites.

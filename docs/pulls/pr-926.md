## Summary

Implements #887: a versioned adapter SDK contract that every provider/device adapter declares, plus an executable conformance suite gating whether an adapter may claim conformance — never a bare pass.

**Contract** (`cad_adapter_sdk.py`): sealed `AdapterSdkContract` (`asd-`) embeds the #878 `AdapterCapabilityReport` **verbatim** and pins it with `capability_sha256` — mechanism literals, filter classes, `protocol_authority` reused, no parallel vocabulary. Adds `supported_operations` (must include `capability`), `AdapterSafetyInvariants` (one-shot mutation authorization always true; `forbidden_operations` drawn only from the closed `FORBIDDEN_OPERATION_KINDS` set; `credential_boundary` holds handles, never values), `contract_status` (`production`/`assisted_only`/`read_only`/`simulated` — `simulated` is rejected for non-simulated authorities), and `compatibility_range`.

**Suite** (`cad_adapter_conformance.py`): `ConformanceSuiteRunner` executes 14 named scenarios (`happy_path`, `unavailable_target`, `authentication_failure`, `timeout`, `cancellation`, `malformed_response`, `partial_write`, `stale_capability`, `firmware_drift`, `unsupported_feature`, `readback_mismatch`, `retryable_vs_terminal`, `rollback_success`, `rollback_failure`) against a `ConformanceSubject` and seals a `ConformanceResultRecord` (`acr-`). Verdicts: `conforming` / `conforming_with_limitations` / `non_conforming` / `unverifiable`. Required scenarios derive from the adapter's own lanes (`apply`→`authentication_failure`, `read_back`/`file_verify`→`readback_mismatch`, `rollback`→`rollback_success`); optional scenarios that can't be exercised are limitations, never faked. Each `ConformanceScenarioResult` pins `transcript_sha256` + typed probes.

**Re-derivable**: results pin `descriptor_ref` (descriptor sha) + `suite_version` + `contract_version`. `conformance_is_stale` + fail-closed `assert_conforming` raise `AdapterConformanceError` with typed `.kind`: `insufficient_version` / `unproven` / `stale_descriptor` / `stale_suite` / `non_conforming` / `unverifiable` / `limited` — unproven or stale evidence is never conforming.

**Persistence** (`cad_adapter_sdk_repository.py`, schema **v108**): two append-only `_SealedStore` tables `cad_adapter_sdk_descriptors` + `cad_adapter_conformance_results` with `latest_result_for(descriptor_sha256)` for the downstream gate; replay-canonical audit probes, `_ROW_BINDINGS`, migration ledger, JA lifecycle labels wired.

**Honest in-repo outcomes** (`run_in_repo_conformance`): AVR LAN & CamillaDSP → `conforming_with_limitations` (simulated evidence — simulated transports can never claim protocol conformance; CamillaDSP correctly mints a `production` *contract* but `simulated` provenance); miniDSP & EqualizerAPO → `assisted_only` + file provenance; file adapter → `assisted_only`; configured-endpoint discovery & REW provider gate → `read_only`. No in-repo adapter mints unconditional `conforming` from deterministic fakes.

Tests (`backend/tests/test_issue_887_adapter_sdk.py`, 52 tests): every verdict path incl. a deliberately broken adapter, suite-version/descriptor-sha staleness, every `assert_conforming` kind, seal/transcript tamper, repository round-trip + append-only + tamper detection, row-integrity scan, audit coverage modes. Doc: `docs/issues/issue-887-adapter-sdk.md`.

## Summary

REV46 fresh-eyes audit of the verification system after REV45. Full findings report (severity — what — fix/no-fix+why): `docs/reviews/rev46-issueverify.md`.

The headline fixes harden the machinery REV45 added:

- **Process containment**: every check now runs in a Windows kill-on-close Job Object (`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`). REV45's `taskkill /T /F` could not reach detached grandchildren and reaped nothing when the runner itself died mid-check; nested job membership covers grandchildren and the kernel kills all members when the last job handle closes. `_sweep_process_tree` runs on *every* attempt exit (a `passed` check could still leak children). `taskkill` remains the fallback; POSIX uses `start_new_session` + `killpg(pid)` (pgid==pid stays signalable after the leader exits; `os.getpgid(dead_pid)` raised). Popen `OSError` is now an `error` attempt instead of a crash, and retries pause 2s for async handle release.
- **Upsert ownership + self-heal**: a comment is ours only when it *starts with* `<!-- verify-open-issues -->` AND carries the `自動検証` signature — a human quoting the marker mid-body is never edited. Past posting races that left duplicate marked comments self-heal: PATCH the oldest, DELETE the rest best-effort.
- **Cache key completeness**: key now covers runner-managed env (`QT_QPA_PLATFORM`, `PYTHONIOENCODING` — offscreen-vs-GUI changes verdicts) and `platform.machine()` in the env fingerprint. `--use-cache` stays local-only (dispatch = fresh-truth request); rationale documented.
- **Schema/CLI guards**: check ids must be unique manifest-wide (shared `logs/` dir), and reject leading dots and Windows device names (`con`, `nul`, `aux`, `com1-9`, `lpt1-9`) — `logs/<id>.log` cannot be created on windows-latest. `--issues` rejects non-positive numbers; non-list API pages raise a clean error; JSON report publishes via tmp+`os.replace`.
- **Manifest**: maps issue #538 (auralization evidence & shareability) — pytest over the four existing auralization/listening-session suites + JA manual entry for the unimplemented review-package/listening-validation scope.
- **Workflow**: upload step gets `if: always()` (a failing verify step must not swallow the report), `run_attempt` in the artifact name, `if-no-files-found: warn`. Permissions stay `contents:read` + `issues:read`.

## Summary

REV57-AUD lands four sealed authorities for acoustic/playback verification gaps (#621, #634, #628, #632), schema **v40** (19 new append-only tables; REV57-DISP took v39 mid-flight so this lands one version later). Each authority follows the established sealed-model + repository + `_ROW_BINDINGS` + `_ReplayProbe` + JA label wiring; every axis/state is reported — omission reads as failure, never as valid.

### #621 — acoustic channel-identity / polarity verification
- `CadChannelIdentityChain` binds a logical renderer channel to a hop chain (renderer output → processor/DSP → DAC → amp → #597 cable → speaker instance → acoustic endpoint), each hop `known`/`inferred`/`unknown` independently; known-by-label alone is never an acoustic proof.
- `CadChannelIdentityTest` pins the exact #608 stimulus record used; `CadAcousticEndpointObservation` records who/what heard the channel (operator, measurement mic w/ level class, near-speaker mic, array localization, telemetry).
- `CadPolarityVerificationRecord` keeps the five layers separate (physical wiring / DSP inversion / source-internal / acoustic relative / frequency-dependent phase) — a DSP-inversion workaround is verified as *compensated*, never rewrites the wiring defect.
- `evaluate_channel_identity` ladder: `verified` / `verified_compensated` / `verified_with_limitations` (program-material or manual-only evidence) / `identity_mismatch` with reconciliation `all_match → multiple_unexpected_endpoints → device_map_mismatch → acoustic_endpoint_mismatch → insufficient_evidence` / `polarity_fault` / `not_driven_by_renderer` (renderer fallback ≠ dead speaker) / `stale` (AVR/DSP reset, firmware #592, cable service #597, amp/speaker change #596, render topology #603).

### #634 — listener-area coverage / acoustic-aim qualification
- `CadAcousticAimState`: cabinet pose, acoustic reference axis, dataset reference axis, design aim target, as-built observed aim stay distinct; `cabinet_to_dataset_rotation` is an explicit unit quaternion — never an implicit assumption.
- `CadCoverageListenerArea` carries per-position design/holdout roles so a single MLP trace can't qualify the whole area; `CadCoveragePrediction` binds sources (measured-3D requires `directivity_ref`; `nominal_beamwidth_only` is a permanently weaker class, never upgraded), applies each screen/grille/boundary transfer exactly once, and requires a #609 timebase pin for coherent summation.
- `evaluate_coverage_qualification` ladder: `predicted_and_measured_agree_within_envelope` → `predicted_only` / `field_measured` → `qualified_with_limitations` → `source_directivity_limited` / `occlusion_limited` / `spatial_sampling_insufficient` / `profile_source_ambiguous` → `indeterminate`. Envelope tolerance comes only from an explicit `CadCoverageProfileRef` — the A102 2022-vs-2023 revision question stays owned by #599, no guessed thresholds.

### #628 — installed loudspeaker instance-variation authority
- `CadInstanceAcousticEvidence` levels `model_reference_only → … → instance_in_room_measurement`; instance-level evidence requires instance-sourced observables, and in-room ≠ free-field.
- `CadModelToInstanceDelta` is an immutable artifact pinned to *both* evidence records; `validate_delta_compatibility` blocks on-axis→3D directivity, low-level→large-signal, and impedance claims without `impedance_zf` on the instance side.
- `classify_instance_delta` ladder ends at `confirmed_fault` / `suspected_defect` / `outlier` / `within_declared_tolerance` / `matched_within_project_tolerance` / `no_population_tolerance_available` / `measurement_inconclusive` / `environment_dependent` — tolerances are only ever explicitly bound; AES-X241-style population stats stay research-only.
- `CadMatchedSetDeclaration` (l_r, l_c_r, surround, height, multi_sub; ≥2 `installed_instance` pins) evaluated per independent metric (level/FR/polarity/impedance/delay/nonlinear spreads); the limiting member is the instance furthest from the group median. Same-model replacement invalidates serial evidence (#596 path).

### #632 — media-playback capability qualification
- `CadPlaybackStackIdentity` pins device/OS/app/engine/firmware/license/source mode; `CadMediaProfileRequirement` records container, delivery class, codecs+profile+level, video/audio params, encryption — `wave_profile` allowed only for `segmented_adaptive` delivery, versioned and optional.
- `CadPlaybackCapabilityRecord` classes `declared_by_device_api` / `declared_by_application` / `tested_playable` / `tested_with_limitations` / `tested_fallback` / `unsupported` / `unknown`; `tested_*` requires `empirically_tested`/`observed_output` evidence, `unsupported` requires a failure attribution ≠ unknown, `tested_playable` requires `requested_profile_rendered` output.
- `CadPlaybackOperationRun` covers seek/pause/representation-switch/period-transition/track-change/language/subtitle/background-resume/standby-wake — first-frame-rendered is never the whole capability.
- `evaluate_playback_capability` verdicts: `qualified_exact_profile` / `qualified_with_fallback` (SDR/downmix/object→bed/transcode surfaces, never hidden) / `qualified_with_limitations` / `player_unsupported` / `output_profile_mismatch` / `transport_dependency_failed` / `intermittent` / `insufficient_evidence` (also emitted with `stale=True` when the stack updated since evidence). DRM stays observation-only; no global capability badge.

## Literature basis

- Channel identity: CEDIA/CTA-RP22-style channel ID check-tone procedures (per-channel stimulus + endpoint confirmation, one channel at a time); AES polarity conventions separating physical wiring reversal from DSP/source inversion, with acoustic polarity verified at the endpoint rather than inferred from the chain; the device-map-vs-physical reconciliation split follows standard AVR rerouting/DSP workarounds documented in CEDIA commissioning guidance.
- Coverage/aim: loudspeaker directivity (horizontal/vertical coverage angle vs ear-height axis), off-axis level loss, early-vs-late energy windows, and seat-to-seat variation envelopes as used in immersive-audio commissioning (ITU-R BS.1116-style listening-area evaluation, Dolby/THX seating tolerance practice); coherent summation requires a shared measurement timebase — energy summation otherwise.
- Instance variation: manufacturing tolerance practice (golden-sample vs production spread), impedance/resonance/sensitivity/THD observables, matched-pair/set selection by spread-from-group statistics; population tolerances are declared, never invented.
- Media playback: Dolby Atmos / DTS:X real-decode vs declared-capability distinction, bitstream vs PCM paths, DASH/HLS representation switching and period transitions, HDCP/DRM observation-only constraints, WAVE test-content versioning (WAVE-PCM profile binding restricted to segmented adaptive delivery).

## Summary

HTDT's release machinery already binds revision + lock + verification evidence + artifact SHA-256 (#833), but there is no publisher-identity stage for distributed Windows artifacts. This adds an optional Authenticode signing path that stays strictly separate from correctness verification.

- `scripts/sign-release.ps1`: signtool stage — explicit `-Artifacts` list, `-Thumbprint` (cert store, preferred) or `-PfxPath` + `HTDT_SIGN_PFX_PASSWORD` env var, `-TimestampUrl` (/tr + /td sha256), sign → `signtool verify /pa` → post-sign SHA-256 → `<artifact>.signature.json`. `-RequireSigning` fails if any artifact is not `signed_verified`; without capability the report visibly records `unsigned`/`unverifiable` and the build stays valid.
- `scripts/release_signature.py`: merges a `publisher_signature` block NEXT TO `verification` (`scope: publisher_identity_only`) — artifact sha256 recomputed from disk (report-claimed hashes never trusted, mismatch is an error), signer identity/timestamp recorded only when actually `signed_verified`, `--require-signed` fail-closed, report schema has no secret surface (password/key fields rejected structurally).
- `build-windows-artifacts.yml`: new `require_signature` dispatch input; the stage decodes `HTDT_CODESIGN_PFX_BASE64`/`HTDT_CODESIGN_PFX_PASSWORD` secrets to `$RUNNER_TEMP`, signs + merges, and deletes the PFX in `finally`. Opt-in only — personal/dev builds are unaffected.
- Signing scope documented: installer exe + explicitly listed exes; a signed ZIP does not sign its contained executables; pre-sign provenance identity and final signed-artifact identity are both kept (no byte-reproducibility claim across signing). #725 evidence attestation remains a separate concept.

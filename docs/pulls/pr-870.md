## Summary

REV65 review pass over the unattended automation surface — `scripts/*.py`, `scripts/*.ps1`, `.github/workflows/*.yml`. Seven confirmed defects fixed; each has a failing→passing regression test in `backend/tests/test_rev65_pipeline.py` (all run offline; neighboring signature/lifecycle/release-verification/corpus suites re-run green: 82 passed). Full notes in `docs/reviews/rev65-pipeline.md`.

Defects:

- `scripts/release_signature.py` — `signed_sha256` was unconditionally required non-empty, but `sign-release.ps1` emits `''` for `unsigned`/`signing_failed`/`unverifiable` reports: every non-signed report died in `load_signature_report`, so the honest non-signed merge path (`publisher_signature.status` next to the verification block, the clean `--require-signed` error) was unreachable. Now required non-empty iff `status == 'signed_verified'`; a digest on any other status is rejected.
- `scripts/ux160_acceptance.py` — `subprocess.TimeoutExpired` from the 600 s cell timeout propagated uncaught: one hung cell killed the whole matrix run before `matrix.json`/the report were written. Now recorded `blocked`/`detail='timeout'` per the docstring contract.
- `.github/workflows/build-windows-artifacts.yml` — both artifact names lacked `${{ github.run_attempt }}`; upload-artifact v4+ names are immutable, so a re-run of the same run/commit collided and could never go green. Appended (the convention `verify-open-issues.yml` already documents).
- `scripts/fetch_external_corpus.py` — an unknown or non-fetchable `--dataset` id produced an empty plan → exit 0 having verified nothing (fail-open); `urlopen` had no timeout → an unattended fetch could hang forever. Unknown/unfetchable ids now `parser.error` → exit 2; `--timeout-seconds` (default 300) bounds each blocking read.
- `scripts/build-native.ps1` — `git status` failure collapsed `$Dirty` to `$false`, stamping "clean" into `build_info.json`/display version when the real state was unknown. Now throws like every other tool invocation in the script.
- `scripts/commit_manifest_verification.py` — the documented exit 3 (integrity/commit failure) was unreachable; store write failures surfaced as traceback exit 1. Commit block now returns 3 on failure.
- `scripts/issue_lifecycle.py` — `classify_issue(check_statuses=...)` was dead wiring: `main()` never supplied check results, so `implementation_present_checks_red` could never trigger and red automated checks on a landed issue classified as `closeable`/`gate_remaining`. New `--verification-report` accepts `issue_verification_report.json`.

## Findings (report only)

- `verification_evidence.ps1` — empty `-ExpectedCommitSha` skips commit binding yet still reports `status='verified'` (overclaim; requires a domain call on downgrade vs reject).
- `commit_manifest_verification.py` — unmapped checks warn on stderr but exit 0; `skipped_manual` counts any unmapped status although manual checks never appear in the report's `checks[]` (dead counter).
- `run_release_verification.py` — report-dir names are second-granularity; same-second runs share a directory (benign, writes are atomic).
- `ux160_driver.py` — 0-byte placeholder PNG survives a failed `grab().save` (evidence artifact, not a verdict input).
- `issue_lifecycle.py` — `load_verification_issues` on a non-mapping YAML raises `AttributeError` instead of clean `_fail`.
- `release_signature.py` — `FORBIDDEN_REPORT_FIELDS` scans top-level keys only; harmless — the merge whitelists fields into the manifest.

## Summary

Round-9 audit of the PyVista/VTK viewport surface (`room_viewport.py`, `room_workspace.py`, `field_explorer_panel.py`). Full evidence and deferred items live in `docs/reviews/round9-viewport.md`. Verification is local pytest only (3.12.10, `QT_QPA_PLATFORM=offscreen`); this box has no GL, so render assertions use a recording fake plotter.

**Performance**
- Every `add_mesh`/`add_point_labels`/`add_text` previously ran with pyvista's `render=True` default → `Renderer.add_actor` → `parent.render()`: one full GL pass *per actor*. A `render_document` rebuild (~30–80 actors incl. glyphs/envelopes/rays) re-rendered the framebuffer dozens of times per entity edit, and each overlay helper (`render_measure_overlay`, `render_constraint_overlay`, `render_video_overlay`, `render_search_domain`, `render_history_ghost`) did it again. All adds now pass `render=False`; each public entry point ends in exactly one `_render()` (compositors still coalesce via `deferred_render`).
- `QtInteractor` default `auto_update=5.0` ran a 200 ms timer → five whole-scene re-renders per second at idle, forever. Now `auto_update=False`; nothing relied on it since all mutation paths render explicitly.

**Correctness**
- Pick coordinates were vertically mirrored: pyvistaqt feeds the interactor bottom-up device-px coords, but `pick_actor_at`/`pick_world_position`/`emptyClicked` passed Qt top-down DIP coords to VTK-space APIs, and `entityPicked` vs `emptyClicked` emitted *different* conventions. The public surface is now uniformly Qt widget coords; `_widget_to_display_position`/`_display_to_widget_position` convert (×dpr, y-flip) at the VTK boundary.
- Field-slice elevation planes (xz/yz) were drawn rotated 90° — row axis is the elevation axis in `extract_field_slice`'s `(row, col, fixed)` packing, but rows were drawn top-down as if horizontal. `_slice_pixmap` now orients by axis name (`x_m`→horizontal, `z_m`→vertical, flipped up). Display-side only, so hashed `FieldSliceView` cache entries stay valid.
- Hidden entities still rendered floating labels and acoustic-overlay meshes, contradicting the hide verb / #482 selection contract. `_render_labels` and `_render_acoustic_overlay` now filter `_hidden_ids`.
- `render_video_overlay` lacked the `scene_content_hash` staleness guard `render_prediction_results` already had — a stale evaluation drew a misaligned camera cone after scene edits. Mirrored the guard.

**Interaction (round-8 deferred items #9 and #10, implemented)**
- Box select: left-drag (previously dead — pyvistaqt strips VTK move observers) past a 6 px threshold drives a `QRubberBand`; on release `pick_entities_in_region` projects each entity actor's `GetBounds()` corners through `world_to_screen` (no GL needed) and emits `entitiesMarqueeSelected(ids, additive)` → `set_selection_many`. A release pick is suppressed after a marquee so it can't collapse the region selection.
- Click-through cycling: `pick_actor_candidates` maps `vtkCellPicker.GetProp3Ds()` front-to-back hits to entity ids; repeat clicks within 4 px cycle e1→e2→e3→wrap.

**Field explorer**
- Colormap scale bar (`_scale_bar_pixmap` + lo/hi unit labels), and the status line now reports axis orientation, `lo…hi` range with units, sample count, and masked-sample count.

**Deferred (sketched in the review doc)**: hover highlight (needs a throttled pick pipeline), label collision management (`vtkLabelPlacementMapper` route), legacy standalone windows remain out of scope.

**Tests**: `backend/tests/test_room_viewport_r9.py` (11 tests) + affected suite (`test_room_viewport_semantics`, `test_room_workspace`, `test_cad_spatial_field`, `test_cad_field_explorer`, and 20 other importing files) — all pass. One failure observed under multi-file ordering, `test_room_inspector.py::test_metric_spinbox_wheel_requires_focus`, reproduces identically on clean `main` — pre-existing order-dependent flake, unrelated.

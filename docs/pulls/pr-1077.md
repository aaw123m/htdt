## Summary

Refs #990 — Reference Library を機材・材料・規格の横断検索・比較・出典確認ができる面にする。新しい権威 (authority) は一切作らず、既存サービスの読み取りだけで構成する。

**Read model** — `htdt/reference_library_browser.py` (Qt 非依存):
- `collect_library_rows(index, detail_resolver=, usage_sites=)` はアーカイブ含む全エントリを `(family, identity)` 単位で束ね、`is_latest` を自称する行のうち最大 version のみを最新とする。同名・同モデルの別バージョン/別メーカーは `semantic_key = identity@version#authority_hash` で常に区別され、併合しない。
- `build_reference_library_detail_resolver(scene_repository, data_dir)` は `authority_hash` で `EquipmentLibraryService` / `CadSpeakerLibraryRepository` / `CadMaterialLibraryRepository` / `StandardsProfileLibraryService` / 同梱 projector・tactile pack を突合するスナップショット。未解決は `record_missing` (記録なし) として正直に表す。権利表示は license フィールドの有無に忠実: 機材定義は権利欄を持たないため一律「権利情報なし」、スピーカー/材料は `license_name` + `redistribution_permitted` を集約 (None → 権利未確認)。
- `collect_usage_sites(scene_repository, document_id)` は canonical な2系統のみ — `resolve_current_equipment_binding` (明示 binding / variant 由来) と `CadInstalledEquipmentRepository.resolve_instance_definition` の型付き解決結果をそのまま返す。書込・rebind なし。
- `filter_rows` (クエリ NFKC+casefold × family/category/source/status), `compare_rows` (同 family 2 行の項目差分 + 各行の dependents)。

**Page** — `ReferenceLibraryPage(list_definitions, library_index=, detail_resolver=, usage_resolver=, open_target=)`。`library_index=None` では従来表示のまま (compat 維持: `self.table` 3 列, `_family_frames`, `focus_definition`)。index 付きでは「横断検索・比較」タブを追加:
- 検索欄 (名前/メーカー/型番/ID/出典/バージョン/使用箇所ロールを横断) + family/区分/出典/状態コンボ (すべて・最新のみ・要注意・未適格/アーカイブ)。
- 結果表 6 列、行選択で詳細パネル (kind/ID/バージョン/SHA-256/参照キー/スコープ/出典/根拠区分/権利/欠損根拠) と使用箇所一覧。2 行選択で A/B 比較 + 入替で失効し得る dependents。
- 遅延描画: 50 行ごとの「さらに読み込む」、0/100/1000 件はテスト済み。状態バッジ (最新/旧版/根拠不足/記録なし/アーカイブ) で適合認定を出さない誠実さを維持。

**Deep links (参照のみ)** — `InstallationPanel.libraryRequested` + 「ライブラリで確認」→ `WorkspaceDeepLink(LIBRARY, kind=EQUIPMENT_DEFINITION, intent=PROVENANCE)`。ライブラリ側 usage-site 行の「開く」→ `NavigationTarget(SCENE_ENTITY | INSTALLED_EQUIPMENT_INSTANCE, intent=INSPECT)` を `QTimer.singleShot(0)` 経由で発行 (#1023 の signal 中 dispose 回避)。adoption は従来の明示フローのまま。

**Tests** — `backend/tests/test_issue_990_reference_library.py` (16件): 同名マルチバージョン/別メーカーの非併合、状態フィルタ 4 種、record_missing の未適格化、詳細フィールドの正確性、比較差分 + dependents、usage-site の NavigationTarget 発行、50 行ページャ + 0/100/1000 件、`focus_definition` の reveal、実 SceneRepository での `collect_usage_sites` end-to-end、新規コントロールの accessibleName。

既知の unrelated 失敗: `test_accessible_labels.py::test_mounted_destinations_have_no_unnamed_controls` は本 PR に無関係な既存コントロール (seatCoverage/correspondence/activity) で main でも失敗する (origin/main e9547460 で確認済み)。

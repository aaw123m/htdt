## Summary

`DeliverablesDialog` stacked every catalog `QGroupBox` + entry row directly into the dialog `QVBoxLayout` at fixed 640x520 — no `QScrollArea`, so lower categories, 書き出し buttons and the Close row were unreachable with many candidates or at 125–200% DPI. The catalog service and readiness evaluation are untouched; this is presentation-surface only.

- **Layout shape:** pinned header (プロジェクト id + 現在のリビジョン pin), `QLineEdit` search, `QComboBox` status filter (すべて/出力可能/制限付き/要入力/古い) and a row-count label never scroll; candidate groups live inside a `QScrollArea` (widgetResizable, NoFrame); a pinned warning-notice label and `QDialogButtonBox` Close sit below the scroll.
- **Progressive disclosure:** each `_EntryRow` shows badge + title + first-sentence reason summary; full reason, `source_authorities` pins and `expected_formats` sit behind a per-row 「詳細を表示」 toggle. Badge wording now mirrors the filter vocabulary — `available_degraded` → 制限付き, `stale_review` → 古い（要レビュー）, never conflated with plain 出力可能.
- **Click-time re-validation:** `書き出し` calls `_execute_output`, which re-reads `catalog()` and requires the same `deliverable_id` to still hold the same `command_id`, a still-outputable availability, and identical `source_authorities` pins before running — drift refuses with a notice + rebuild, so a stale display or a project switch can never emit unauthorized/outdated output. Filtering only hides widgets; buttons stay bound to their own entry id (no cross-select).

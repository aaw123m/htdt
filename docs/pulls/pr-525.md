## Summary

Follow-up fixes for the two open findings REV43-SEAMS reported but did not fix.

**Watch lane permanent silence** — `CaptureWatchRunner._in_flight` is the only re-entry gate and clears solely via the worker's `on_finished`. A route call that blocks forever (e.g. a contended `BEGIN IMMEDIATE`) would absorb every later tick — matching the ~11 min silent-lane episode SEAMS observed. `_tick` now enforces `_STALL_BUDGET_S` (300s): past it the runner logs CRITICAL, `pool.cancel`s the job cooperatively, bumps `_job_generation`, and releases the latch. The same-key `pool.start` then detaches the lingering thread to module ownership — no GUI-blocking `stop_all`. The generation token guards `_seen`/`_route_failures`/`_pending` so a wedged worker that wakes up later cannot write runner state its replacement now owns.

**Uncaught `OperationTransitionError`** — `_on_automatic_backup_completed` (workflow_application.py:~1028) is invoked through a queued signal; its op can already be terminal (e.g. cancellation landed first), so `complete`/`fail` raised and crashed the slot with a CRITICAL log. Guarded with the same `try/except OperationTransitionError` convention `data_management` uses for its terminal transitions.

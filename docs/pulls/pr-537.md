## Summary

Design + implementation review of the REV44 open-issue verification system (PR #535), with the worthwhile improvements implemented in one pass. The manifest→runner→report shape survives review — the changes are concentrated in *what the runner does with the verdicts* and in real defects found reading the code.

**Design changes**

- `--post-summary` now **upserts** a single marked comment per issue (`<!-- verify-open-issues -->`) instead of posting a new comment per run — the old semantics were too spammy to ever enable. Latest verdict stays visible on the issue without digging artifacts. `unmapped`/`not_open` issues are skipped and failed writes exit non-zero.
- New opt-in `--use-cache`: verdicts keyed by `(check config, HEAD sha, interpreter env fingerprint)` skip re-verifying unchanged code. Refuses dirty worktrees (local edits aren't covered by the key) unless `--allow-dirty-cache`; cached results are marked `cached: true` — a cache that lies is worse than no cache.
- New `--rerun-failed N` (default 1): this suite has known xdist/Qt teardown flakes, so a failed check retries — but every attempt and a `flaky` flag are recorded, keeping fail→pass visible rather than silently trusted. `timeout` is never retried (budget already spent).
- New `--fail-on-verdict`: opt-in exit `3` for anyone who later wants this as a gate; default remains verdicts-as-data.
- Report gains an **At a glance** triage section (close candidates / red checks / manual-only / stale entries) — answers "what can I close now" first.

**Defects fixed**

- `subprocess.run(timeout)` killed only the direct child — xdist workers survived on Windows holding basetemp handles. Checks now run via `Popen`; timeouts kill the process tree (`taskkill /T /F` / POSIX `killpg`).
- `--issues <closed>` ran the full suite and reported `verified` — now reports `not_open` and skips checks.
- `--issues <subset>` flagged every *unrequested* manifest entry as stale — `not_open` now compares against the live open set only.
- `--post-summary-from` did a needless live-issues fetch before replaying a saved report — moved ahead of the fetch path.
- `--issues abc` raised an uncaught `ValueError`; manifest schema now also validates check-id charset (ids become log filenames) and `title`/`notes` types; `|` in issue titles no longer breaks the MD table; JSON `log_path` carries its `logs/` prefix.

Rejected alternatives documented in `docs/ISSUE_VERIFICATION.md` (labels, tracking-issue digest, unconditional cache, hidden retries).

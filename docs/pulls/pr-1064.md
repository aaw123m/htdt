## Summary

「3Dに収まる」は「証跡つきで設置できる」とは違う。Adds a read-only
設置実現性検査 layer that renders the persisted
`SpeakerInstallationContext` records through
`cad_installation_feasibility.installation_feasibility()` onto the CAD
room view — verdicts are the authority's output verbatim; the UI never
re-judges.

- `htdt.installation_feasibility_viewmodel.build_installation_feasibility_preview(document, contexts, service_clearances)` — maps each context to an `InstallationFeasibilityItem` carrying the exact entity + bound element (`element`, `element_ref` = wall_id / ceiling / floor), the derived `InstallationRequest`, the verbatim `InstallationFeasibilityReport` (six checks), a gated headline verdict, JA on-site `confirmations`, and evidence-gated anchors (`wall_face`/`slab_face`/`cutout_volume`/`service_volume`/`cavity_volume`). Keyed to `scene_content_hash` — edits lapse the overlay honestly.
- Request provenance — every field is declared evidence: `mount_surface`/`element` from `selected_mounting_mode` + `host_entity_id` (wall ids bind only when the host IS a wall; entity hosts degrade to `furniture_top` → `not_applicable`); `payload_kg` only from the `mountable` capability binding (absent → headline stays 未評価, checks still surface); in-wall `cutout_depth_m` from the entity footprint span along the wall normal; `service_clearance_m` only from a persisted `ServiceEnvelopeProfile`.
- Viewport — `installation-feasibility-*` actors, all `pickable=False`: verdict glyph spheres (entity + substrate anchor), translucent mounting-face fill/outline on the bound surface, and translucent extrusions for cutout/service/cavity only when evidence-backed (no cavity layer → no invented depth). Legend + summary + disclaimer (「施工許可・建築基準・耐荷重法規への適合認定ではありません」) text actors; toggle OFF removes everything; coexists with opclear/selection/camera-fit.
- Panel — `RoomInstallationFeasibilityPanel` on the placement stack: preview toggle, honest counts (`記録N件 · 証拠あり…`), verdict-colored item list, per-selection detail with all six `FeasibilityCheck` reasons in JA + 現場確認項目.

## Verdict vocabulary

`supported` 証拠あり `#59d98c` · `conflict` 不適合 `#e05555` · `unknown` 不明 `#8a93a3` (gray — never the conflict red; unknown becomes on-site confirmation items) · `not_applicable` 対象外 `#6b7280` · unevaluated → wireframe glyph.

## Tests

`backend/tests/test_issue_1005_installation_inspection.py` — 20 tests: entity/element binding, verbatim check passthrough vs `installation_feasibility()`, unknown≠fail glyph vocabulary, undeclared-payload headline gating, entity-host `not_applicable`, evidence-gated volumes (masonry → no cavity volume), in-wall cutout>declared-cavity conflict, `head_sha256` staleness on edits, entity-removal honesty (対象機器が不在), wall-face anchor at the entity's true projection, panel JA reasons + confirmations, actor cleanup, narrow-320px / DPI-2x / UIA. Adjacent regression: `test_issue_1010_operational_clearance.py` 16/16.

## Real-GUI verification (Mesa GL)

Verified end-to-end on the native app with a seeded project (wall topology + stud-wall assembly, 3 speakers with `mountable` bindings, 3 contexts, one service envelope): toggle ON draws glyphs/faces/volumes + legend/disclaimer; UNKNOWN renders gray (never red) on glyph, face, and row; six reasons + confirmations render in JA in the panel; entity move re-anchors glyphs; entity delete lapses the row to 対象機器が不在 and removes its actors while keeping the record; toggle OFF removes all `installation-feasibility-*` actors. One defect found in verification (wall-face pinned ~1 m from the segment start instead of the entity's projection) is fixed here with a regression assertion.

Known limitation (pre-existing, same as `opclear-*` text): VTK text actors on the test box drop CJK glyphs — the Qt panel shows all JA text.

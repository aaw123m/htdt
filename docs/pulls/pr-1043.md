## Summary

Rights investigation + fail-closed compatibility verdict for real manufacturer CLF `.CF1`/`.CF2` binaries (#952).

**Fixtures found (4, sealed in `CLF_LICENSED_FIXTURES`):** CES Audio `cls-3100.CF1`/`cls-3100.CF2` via the CLF Group distribution section, `Genelec Oy-4020A.CF2` via genelec.com, and the CLF-viewer-kit's `clf2_v2_*` sample — each pinned by SHA256 + size + verbatim permission context. Use/analysis is granted by each source's own wording (CLF FAQ: "To use the data for a design you need software that can import the binary CLF format data"); **no source states a redistribution grant**, so no real bytes are vendored — evidence is the sealed record + execution log in the issue doc.

**Decoder: none — documented-block path.** The binary spec is by-request only (CLF spec §14) and no licensed decoder was found (CFxLib/free_clf unlocatable), so a licensed fixture honestly resolves to `decode_blocked`. What ships instead:

- `detect_clf_binary_variant` — signature now covers the gen-2 `.CF2` layout real files actually carry (`41 BD 0A 00 02` + `v2.0`; all 14 real samples confirm generation byte ↔ marker agreement, so mismatches and `.CF1`-gen2 fail closed)
- `inspect_clf_declared_surface` — bounded (4 KiB) read of the viewer-visible author/model declarations for provenance pinning; secured arrays untouched
- `evaluate_clf_payload` → `ClfImportEvaluation` — outcome vocabulary (`licensed_ok`/`decode_blocked`/`rights_unknown`/`no_licensed_fixture`/`solver_input_insufficient`) + the six-column #935 sufficiency audit; a supplied payload that drifts from its pin is reported as tamper evidence, not the fixture
- `CLF_FIELD_DECLARATIONS` — per-field honesty table sourced from the spec only; per-file values stay `not_decoded`
- interop corpus gains a `clf/vendor-binary-v2.CF2` stub asserting the gen-2 signature

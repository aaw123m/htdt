## Summary

Round-3 Qt/UI-layer correctness review of `backend/src/htdt` (PySide6 6.11.2, pyvista 0.49.0). Full write-up in `docs/reviews/round3-qt.md`.

Fixed:

- **`room_viewport._render_underlays` crash (High).** `quad.active_t_coords` was deprecated in pyvista 0.43 and removed in 0.46; on the pinned 0.49.0 it raises `PyVistaAttributeError`, so importing a raster underlay killed the next workspace render with an uncaught exception. Switched to `quad.active_texture_coordinates`, verified on 0.49.0 to register a real VTK `TCoords` array that `add_mesh(texture=...)` actually consumes.
- **`QTimer.singleShot(0, callable)` without context (Low ×3)** — `cad_composition.py` (`statusBar().showMessage` lambda after a rejected room replace) and `measurement_workspace.py` (`_sync_content_extent`, `_fit_initial_size_to_screen`). If the widget was destroyed between posting and dispatch, the shot fired on a deleted C++ object → `RuntimeError`. All three now use `QTimer.singleShot(0, self, callable)`; verified empirically the context overload is dropped once the receiver's `DeferredDelete` is processed.
- **`DataManagementDialog.closeEvent` silently swallowed close (Low).** The `before_deactivate` reason ("wait for the data operation" / "restart required") was discarded, so clicking X during a busy operation did nothing with no feedback. The dialog now shows the reason via `QMessageBox.information` before `event.ignore()` (QDialog has no statusBar).

Verified clean (details in the doc): all ~47 lambda connects have child/same-lifetime senders; deleteLater/parenting discipline holds (or deliberate, documented exceptions in `native_worker`/`native_cad`); periodic timers are parented and stopped in closeEvent; worker pools use job guards + `shutdown()`; all `exec()` dialogs are parented; pick/dispose paths guard deleted C++ objects with try/RuntimeError; no `QAbstractItemModel` subclasses, `processEvents`, or cross-thread emits besides the correctly-queued `delivery_staged`.

Deferred (info): field-explorer synchronous compute on the GUI thread; `cad_input.dispose` shortcut lifetime (bounded); round-2's `data_management` worker-teardown sketch stands.

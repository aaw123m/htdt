## Summary

`PresentationWorkspace._build_review`/`_build_proposal` ran `OffscreenSceneRenderer` construction + `build_*_package` + `verify_*_package` synchronously inside `clicked` handlers — freezing the Qt event loop for the whole build. This PR moves both jobs onto a bounded `NativeWorkerPool` lane (the existing worker-pool export pattern, reused — not re-implemented) and registers each run in the shared `ActivityCenter`.

- `presentation_export_runner.py` (new) — `PresentationExportRunner(QObject)` mirroring `SupportHealthRunner`'s contract (`start`/`request_cancel`/`shutdown` + Qt signals). The renderer is constructed **inside** the worker via `renderer_factory` — VTK/Qt thread affinity honored; no live `QtInteractor` is touched cross-thread. `PresentationExportJob` (frozen) pins session id + `session_sha256`, `scene_revision_id`/`content_hash`, render settings, output dir, and expected item counts at click time.
- `ActivityCenter` ops `presentation.export.review`/`.proposal`: `EXTERNAL_IO`, `CANCEL_UNTIL_COMMIT`, `SAFE_NEW_ATTEMPT`, `BACKGROUNDABLE`, deep link to the pinned revision, `project_ref` = session document (this-project scope), `input_authority_refs` = session sha + `scene-revision:<rev>:<hash>`.
- Progress is measured only: stage i/n + real `done/total` units (フレーム / シート) + cumulative bytes written. No `%`, no ETA.
- Staged publish: build into `.<name>.staging-*` sibling dir → re-verify manifest → `mark_commit_point` → `os.replace` atomic rename. Cancel honored until commit; any failure/cancel/crash removes the staging tree — a `.<name>.staging-*` leftover (e.g. process kill) can never be mistaken for output.
- `package_progress.py` (new) — `PackageBuildProgress`/`ExportCancelledError`/`ProgressCallback`; both builders accept optional `progress`/`cancel_event` kwargs (no-ops for existing synchronous callers).
- Workspace: 出力を中止 button (visible only while running), busy-gate on double-click, non-blocking status updates, stale pinned revision → `COMPLETED_FOR_HISTORICAL_INPUT` + 旧リビジョン note, `closeEvent` drains the lane on project switch. Failures correlate to diagnostics via `[diag:]` ids (#962).
- Output contents/manifest/evidence format unchanged — same builders, same verifier.

## Summary

Implements the testable half of #807's planning scope — the inventory, automated cycle check, UI/domain/persistence separation, and size budget — without moving any module.

**`scripts/package_boundary_audit.py`** — AST analysis of all 955 `htdt` modules: layer classification (kernel/persistence/domain/ui/application), rule violations, Tarjan SCC detection, size budget, JSON + markdown report. Measured state: 652 domain / 216 persistence / 77 ui / 5 application / 5 kernel; **one ~470-module mega-SCC across the authority namespace** (the quantitative evidence for the issue's flat-package risk) plus three recorded small cycles; Qt discipline is already clean except `cad_input.py` (a QWidget with a domain-style name, exempted pending rename).

**`test_issue_807_boundaries.py`** — enforces on every commit:
- `no_qt_in_lower_layers` (domain models never depend on Qt widgets)
- `persistence_must_not_import_ui` (adapters never own product semantics)
- `kernel_imports_only_kernel`
- `no_new_cross_layer_cycles` — new cycles touching ui/application fail; the 3 known cycles are pinned exactly
- `SIZE_BUDGET_LINES = 5000` — the 6 giants carry decomposition notes; any new over-budget module fails
- exemptions are self-cleaning (unused entries fail), and the mega-SCC must stay >100 members or the decomposition plan needs revisiting

**`docs/issues/issue-807-package-boundaries.md`** — the boundary spec (allowed dependency directions), the incremental migration plan (leaf-first moves, sealed hashes unaffected since `identity_payload()` hashes contents not module paths), and what stays manual.

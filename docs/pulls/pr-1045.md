## Summary

`PresentationWorkspace._build_review` / `._build_proposal` validated the chosen output directory with `target.startswith(('/', 'C:', 'D:'))` — rejecting valid `E:`/`F:` drives and every `\\server\share` UNC path, while letting `C:relative` (drive-relative, not absolute) string-pass through. Both call sites now go through one typed rule, `htdt.output_target.validate_output_target(raw, *, package_name)`, resolved against the real filesystem and returning an `OutputTarget(root, package_dir)` or raising `OutputTargetError` with a stable machine `reason` + a localized operator `suggestion`.

Check order (fail-closed, no fallback outside the chosen root): non-empty → `PureWindowsPath.is_absolute()` → invalid chars → drive/UNC-anchor reachability → component-wise `is_symlink()/is_junction()` reparse walk → exists/is_dir → package-dir link escape + non-empty collision + a conservative 200-char `MAX_PATH` budget → real `os.open(O_CREAT|O_EXCL)` create/delete write probe. Named reasons cover `empty`, `not_absolute`, `invalid_chars`, `drive_unavailable`, `share_unavailable`, `redirected`, `missing`, `not_directory`, `link_escape`, `collision`, `path_too_long`, `not_writable`, `share_denied`, `io_error` — each with a Japanese suggestion shown by `QMessageBox.warning`.

Two implementation details worth calling out:

- The write probe deliberately avoids `tempfile.mkstemp`: its Windows `PermissionError` branch re-checks `os.access(dir, W_OK)`, which still reports writable on ACL-denied dirs and retries forever — it busy-spins instead of failing (measured on this box). `_assert_writable` uses a direct `os.open` with a uuid name so denial names `not_writable`/`share_denied` instantly.
- Redirect detection walks spelled components instead of comparing resolved-vs-spelled paths, which would false-positive on 8.3 short names (`C:\Users\ADMINI~1\...`).

Honest success reporting: after `build_review_package` / `build_proposal_package`, the workspace runs `verify_review_package` / `verify_proposal_package` (re-hash of every manifest entry) before setting the status line to the exact `output_dir` + `エントリ N 件` + `マニフェスト SHA-256`, and only then reveals a new 「出力先を開く」 button (`QDesktopServices.openUrl`) that can only ever point at the verified build. Validation happens before any write, and the helpers are pure — a rejected target leaves the session, `SceneRevision`, and filesystem untouched. The chooser now goes through `file_dialog_memory.get_existing_directory` (key `presentation.export_dir`) like other dialogs; no new export formats.

Tests: `backend/tests/test_issue_984_output_path.py` — 46 tests. Grammar rejects (platform-free), a Windows filesystem matrix (valid dir / trailing separator / forward slashes / missing / file-as-root / disconnected drive / missing share / collision / link escape / path-too-long / writability), both builders driven through a mocked chooser sharing the same rule with scene invariance, and guarded physical legs (`TestPhysicalTargets`) for real drive letters, the loopback `\\localhost\C$` share, and `icacls` write-deny (local → `not_writable`, UNC → `share_denied`). The unreachable-network leg is opt-in (`HTDT_TEST_UNREACHABLE_NET=1`) due to the TCP-445 timeout. Result: 45 passed, 1 skipped; `test_rev47_presentation` + `test_analysis_export` regression-clean (30/30).

Docs: `docs/issues/issue-984-output-path-validation.md`.

Known gaps: real remote-share denial and dead-server timeouts need the manual legs (loopback UNC only here); `path_too_long` uses the conservative 200-char budget rather than probing the OS long-path opt-in.

## Summary

Round-7 review pass over end-to-end workflow coherence (docs/reviews/round7-workflow.md). Traced every emitted `NavigationTarget`/`htdt://nav/v1` URI to the mount that receives it and verified the receiver can resolve the carried id. Several golden-path handoffs were broken or dead-ended:

- **`sync_revisions` positional call crashed the whole room history page** — `room_workspace._sync_history_panel` passed `head_revision_id`/`labels` positionally into the keyword-only signature, so every `_sync_history_panel` call (activate, context switch, label save, restore) raised `TypeError`. The panel tests all passed keywords, so the drift went unnoticed — the 履歴 surface was unreachable on main.
- **Measurement calibration/onboarding page unreachable** — 6th workspace page (`機器の準備`) had no canonical context and the `calibration → campaign` alias redirected links away; nothing ever called `set_context("calibration")` outside tests. Now a canonical context (visible in the context bar) with the alias removed.
- **Timeline deep links aimed at dead surfaces** — captures → MEASUREMENT/'import' (item lives on the Inbox page), presets/health/AV-sync/notes/checkpoints → OVERVIEW (mount has no `on_entity_requested`), `measurement_imported` → 'comparison' (a measurement id resolves to a selectable row only in the quality table). Retargeted: captures → `INBOX`; pageless authorities → `ACTIVITY` (their own timeline row becomes the focusable record); `measurement_imported` → 'quality'.
- **`activity_focus` could never match its declared kinds** — ACTIVITY registered `focus_kinds={ACTIVITY_JOB, PROJECT_CHECKPOINT}` but the handler only scanned the revision-ledger (scene revision ids), so every focused resolution reported "アクティビティ一覧に該当の記録がありません". Now scans the events table by parsing each row's stored nav URI, then the operations table by `operation_id` (now stored in `UserRole`), then the ledger; ACTIVITY `focus_kinds` extended to the pageless authorities.
- **Room `focus_target` rejected reachable ids** — `SCENE_REVISION` and `INSTALLED_EQUIPMENT_INSTANCE` ids were looked up as scene entities → `KeyError` → "項目が存在しません". Revisions route to a new `RoomHistoryPanel.select_revision`; instances resolve via `CadInstalledEquipmentRepository.get_instance(...).scene_entity_id` (with a document-id guard and clear messages for foreign/unbound instances).
- **Optimization `focus_target` ignored `primary_id`** — a `SYSTEM_VARIANT` deep link landed on the comparison page with whatever variant was already selected; now `selector.select_variant(primary_id)` selects it (misses report a focused failure).
- **Stale/foreign sections crashed navigation** — `navigate_to_target` let `select_context`'s `ValueError` propagate through the Qt slot; unknown sections now land on the workspace with a status-bar message.
- **Measurement `focus_entity` selected invisible rows** — matched quality-table row while another page was displayed; now switches to 'quality' first.

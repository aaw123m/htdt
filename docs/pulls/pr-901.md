## Summary

Native performance budget for the primary workflow (#867). Named, benchmarkable operations are measured as distributions (p50/p95 + RSS) against deterministic representative fixtures, and evaluated against an explicit budget manifest — a single timing is never claimed as evidence.

**Components**
- `htdt/perf_fixtures.py` — deterministic generated projects: small (24 entities/4 revisions), medium (300/12), large (1500/24). Identity is `fixture_spec_sha256` (generator version + spec) — the same spec produces the same sha on every machine; stale fixtures regenerate wholesale.
- `htdt/perf_harness.py` — 13-operation registry: application startup cold/warm (real subprocess import), project open/save/reopen, scene/revision application, `workspace_first_mount` + steady-state `workspace_transition` (real `WorkflowApplicationComposition` navigation, non-VTK surfaces), measurement plot load (model layer), comparison view prep, idle/loaded RSS (psutil-free probe via `GetProcessMemoryInfo`/`/proc/self/statm`), shutdown. `viewport_3d_interaction` is `hardware_sensitive=True` — never run as a fake CI timing; deferred to the owned-machine protocol and listed verbatim on the report.
- `htdt/perf_budget.py` — `PerfEnvironment` (real `git rev-parse` sha + dirty flag + OS/CPU/RAM + fixture document sha + iterations), `OperationDistribution`, `PerfBudgetEntry` (must assert ≥1 dimension or `ValidationError`), verdict ladder `within_budget`/`exceeds_budget`/`unmeasured`/`hardware_sensitive_skipped` → sealed `PerfRunReport` (canonical sha256): any exceeds → `failed`, any unmeasured → `incomplete`, all within → `passed`. An unprobed RSS against a memory budget is `unmeasured`, not a pass.
- `scripts/perf_benchmark.py` — CLI: `--fixture-size --iterations --warmup --check --out`; emits report JSON + Markdown; `--check` exits 2 on `failed`/`incomplete` and also when the budget manifest is missing.
- `scripts/perf_budgets.yaml` — budgets per operation×size with rationale (reference-box baseline + 2-4× headroom).
- `release_verification_manifest.yaml` — new required class `performance-budget` (excluded from the dev profile): `perf-budget-small` runs `--check` + `perf-budget-unit` runs the pytest suite. Not capability-gated — a required class cannot depend on an optional capability.

**Regression-detection proof (required by the issue)**
- `test_intentional_slowdown_regression_is_detected` runs the real harness on a real fixture, then evaluates the measured distribution against a tightened budget → `failed`/`exceeds_budget` end-to-end.
- `test_slow_operation_measured_higher` shows a genuinely slower code path produces measurably larger samples.
- `test_failing_operation_is_unmeasured_never_passed` shows a raising op records unmeasured evidence → report `incomplete`, never a pass.

**Non-goals honored**: no micro-optimization targets, no benchmark-as-solver-validity claims, no UX-acceptance substitution, no cross-hardware absolute-timing equality — identity travels via fixture spec sha + `PerfEnvironment`.

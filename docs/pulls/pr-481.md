## Summary

REV32-TERMS: the measurement workflow's fields, statuses and errors now explain themselves in JA — every field/column/metric carries an explanation (meaning + unit + valid values), a TermId-registry glossary dialog lists the domain vocabulary, and error/status surfaces show what the code means and what to do next.

- New `measurement_explanations.py` is the single registry: `FIELD_EXPLANATIONS` (~83 dotted keys → `FieldExplanation{meaning, unit, valid, term}` rendered as tooltip/WhatsThis on inputs, their form labels, table header cells and combo items), `STATUS_EXPLANATIONS` (~70 raw status codes → "意味 · 対処" text for batch/campaign/quality/onboarding cells and disposition/purpose combo items), `METRIC_EXPLANATIONS` (comparison metric row names). Helpers: `apply_explanation`, `explain_form_row`, `explain_table_columns`, `explain_combo_items`.
- New `GlossaryDialog` in `workflow_help.py`: every `HelpRegistry.glossary()` term rendered as a card (term, meaning, not-this, provenance, related-topic titles) in a scroll area with a live `用語を検索…` filter. Reached via a `用語集・ヘルプ` button in the workspace header and the palette `help.glossary` destination.
- New `trouble.operation_error` help topic binds all 45 `UserFacingError` reason codes; `warn_user` gained `on_help` (adds a ヘルプ button, re-execs until a non-help click), and the operation-error notice, divergence box, duplicate prompt, and correction/disposition reason dialogs all open the bound topic the same way (`_open_error_help` → `topic_for_reason`).
- `ReasonTextDialog` replaces `QInputDialog.getText` at the correction/disposition prompts so they can carry a help button. The duplicate prompt now reads the `exec()` StandardButton result instead of `clickedButton`, keeping the help-click re-exec semantics correct.
- `measurement_editor` dock forms (channel role, compare A/B + band, pattern anchor/preset/spacing) wired to the same registry.

## Workflow composition

`workflow_application.py` をapplication composition rootとして追加した。

`--workflow-shell` 起動時は以下をlazy mountする。

- 概要: readiness-driven `OverviewWorkspace`
- 部屋: `RoomWorkspace`
- 測定: `MeasurementPageWorkspace`
- 最適化: `OptimizationWorkflowWorkspace`

shell/routerはdomain semanticsを持たず、workspace factory / command binding / data lifecycleだけを
composition rootが接続する。

accepted legacy `OptimizationWorkspaceWindow` は通常起動のdefaultとして維持する。
UX150/UX160のWindows visual acceptance前にlauncher authorityを切り替えない。

## UX120 Room

新Room workspaceへ以下を接続した。

### Camera / pointer

- MMB: pan
- Shift + MMB: orbit
- wheel: zoom
- RMB: central command registry由来のcontext menu

### Commands

- M: 選択objectの移動をarm
- R: 選択objectの回転をarm
- X / Y / Z: active transformのaxis constraint
- F: 選択へfocus
- Home: scene fit
- Esc: transform / room geometry operation cancel
- Enter: active operation commit
- Ctrl+D: duplicate
- Ctrl+S / Ctrl+Z / Ctrl+Y: active Room WorkingDocumentへbind

M/R dragは `TheaterWorkingDocument.begin_* / preview_* / commit_preview()` を使用する。
viewportは `working.document` を描画するためpreviewが即時表示される。
commit後だけrecovery snapshotを更新し、Undoは既存CommandHistoryを使用する。

### Room geometry

`RoomGeometryInputController` を追加し、new Room viewport上で:

- polygon vertex clickによるroom作図
- first vertex / Enterでclose
- Top viewで既存vertex drag
- invalid polygon reject
- Escで終了/cancel

を実装した。transient pointer stateだけをcontrollerが所有し、valid snapshotのcommitは
`RoomWorkingDocument.replace_room()` に委譲する。

### N70 prediction integration

follow-upで既存N70 authorityを新Roomの「音響」contextへ接続した。

- existing request identity / JobGuard / CadPredictionRepositoryを再利用
- current SceneRevision / content hash / constraint workspace hashへexact binding
- background worker + cancel
- stale/delayed result reject
- saved runの現在/要再計算表示
- current runだけdirect/first-reflection geometry overlay表示
- central `prediction.run` commandを新Roomへbind

詳細: [UX120 Room prediction integration](UX120_ROOM_PREDICTION_2026-09-19.md)

## Settings / Data Management

rail下部に「設定」utilityを追加し、top-level workspaceには増やしていない。

Settings dialogは#128の `DataManagementWidget` をhostし、#124の
`DataManagementController / ApplicationDataLifecycle` を利用する。

restore lifecycle:

1. shell mutation/navigation freeze
2. **一度mount済みの全workspace**の `before_deactivate` を検査
3. dirty draft / active preview / REW job等があればfail closed
4. 全workspace mountをclose/dispose
5. existing `native_backup.restore_backup()` authorityでrestore
6. fresh `SceneRepository` をconstruct
7. Overviewからlazy workspaceを再構築
8. shellをthaw

stale repository / WorkingDocumentをrestore後に再利用しない。

## Navigation authority

`workflow_navigation.py` が引き続き唯一のworkspace/context/deep-link authority。

optimization legacy aliasもここでnormalizeし、workspace固有routerを第二authorityとして作らない。

## Validation scope

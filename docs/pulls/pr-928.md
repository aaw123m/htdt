## Summary

#889 asks for a safe self-update path: stage a package, preflight compatibility, apply behind a restore point, health-check after the swap, and roll back automatically on failed health. This adds a sealed `cad_application_update` authority plus staged updater service; all state lives in a sealed transition log so a crashed update is recoverable on next launch.

**Records** (8 sealed tables, native schema **v108**): `UpdatePackageDescriptor` (`upkg-`), `UpdateSessionRecord` (`upd-`), `UpdateStageTransition` (`utr-`), `UpdatePreflightReport` (`upre-`), `UpdateRestorePoint` (`urp-`), `UpdateHealthReport` (`uhc-`), `UpdateOperatorAuthorization` (`uauth-`), `UpdateOutcomeRecord` (`uout-`).

**Pipeline** — `opened → package_fetched → package_verified → preflight_evaluated → recovery_point_captured → staged → applied → health_checked → committed | rolled_back | rollback_failed | blocked | failed | cancelled`. `derive_update_state` folds the sealed `utr-` log (same pattern as #868); mid-crash sessions resume from the log — `held`/`failed` resolution by stage, `rolling_back` re-entry re-runs the bounded rollback.

**Preflight** — 12 named checks (release channel, signature per #849 `publisher_signature` vocabulary incl. first-class `unsigned`, release evidence, platform, runtime floor, schema window, migration direction/reversibility, pending migrations, disk space, running transactions, crash-recovery pending, adapter compatibility) → fail-closed `eligible` / `eligible_with_warnings` / `incompatible` / `unverifiable`. Unknown evidence never reads as eligible. Apply requires a one-shot `uauth-` operator authorization; forward-only migrations need explicit `acknowledges_irreversible_migration`.

**Rollback honesty** — rollback restores the restore point *and* verifies it (install bytes + captured data items); an unverifiable restore lands `rollback_failed`, never `rolled_back`. `UpdateRollbackScope` (`not_attempted`/`binary_only`/`full`) prevents claiming project/schema restore across a forward-only boundary — `full` is rejected at record validation unless the restore point proves `rollback_scope_capable` and all data items verified.

**Seams** — the service does no network I/O itself: `UpdatePackageSource` / `UpdateInstallDriver` / `UpdateEnvironmentProbe` ABCs with `LocalDirectoryPackageSource`, `FilesystemUpdateDriver`, `LiveUpdateEnvironmentProbe` implementations plus deterministic `Fake*` fakes (corruption, truncated fetch, wrong sha, schema-incompatible, crash-mid-swap, crash-mid-rollback).

**Tests** — 80 tests covering every verdict/stage path, tamper detection, unsigned-but-explicit policy, seal/id integrity, repo round-trip + broken-seal rejection; 24 schema + 63 audit/integrity tests green.

**Device-only remainder** — real process restart, real platform/GPU/audio health observation, and real package transport stay behind the probe/driver seams (documented in `docs/issues/issue-889-application-update.md`).

## Summary

Implements two REV56 P0 authorities on the sealed-record pattern:

**#574 — bass-management/crossover qualification gate** (`cad_bass_management_qualification.py`). Composes the existing #633 `BassManagementProfile` declaration with measured evidence; never duplicates it.

- `SplicePathEvidence` binds per-(role, sub group, seat) response curves for `main_only`/`sub_only`/`main_plus_sub_summed`/`lfe_only`/`redirected_bass_only` paths — phase, delay and polarity are optional evidence, magnitude required.
- `evaluate_splice` computes `worst_splice_margin = min(summed − max(main,sub))` over the crossover band; a dip below the declared −6 dB threshold is measured cancellation, attributed to `polarity_mismatch` / `delay_mismatch` (λ/2 half-period rule) / `phase_cancellation_at_splice`. With phase evidence on both isolated paths, the declared delay/polarity-adjusted complex sum is compared to the measured sum — >3 dB RMS divergence is `device_state_mismatch` (the deployed state is not the declared one).
- Gates demote only: `routing` (reuses `evaluate_bass_management`), `duplicate_low_frequency_path` (double_bass), `usable_band[role]`, `filter_topology` (unknown device filters = recorded limitation, not hidden pass), `splice_summation`, `sub_headroom[dest]` (coherent worst-case sum of redirected+LFE+boost vs declared capability), `deployed_state` (full qualification needs `remeasured_post_apply` evidence under an `applied` profile).
- Verdict separates `status` (qualified / qualified_with_limitations / not_qualified / insufficient_evidence) from `scope` (unqualified / candidate / qualified_point / qualified_region). Control-seat splice only → `qualified_point`; holdout-seat constructive evidence → `qualified_region`; holdout cancellation records `multi_seat_instability` and caps scope. The verdict binds `profile_sha256` — editing the profile never reuses the verdict. All 12 issue-spec failure reasons are literals.

**#608 — test-stimulus/calibration-asset registry** (`cad_stimulus_registry.py`). Kind labels are never identity.

- `StimulusAssetEntry` (sealed): content hash, full `StimulusGeneratorSpec` (sweep law/band/duration/amplitude/fades/silences — ESS/Farina identity), `StochasticRealization` (seeded requires seed+RNG; fixed_realization requires its hash; `unseeded_live`/`statistical_profile_only` are honestly not bit-exact replayable), level semantics (digital/electrical/acoustic + crest factor + FS convention), channel/object identity, media format (raster/range/EOTF for video patterns), `StandardProfileRef` (standard_id + revision + publisher checksum), rights.
- `evaluate_stimulus_eligibility` runs ordered fail-closed gates vs `ProcedureStimulusRequirement`: INCOMPATIBLE (subtype/origin/standard-profile mismatch; publisher-checksum ≠ registered content hash = substituted file), WRONG_REVISION (e.g. IEC 60268-16 2011 vs 2020 speech spectrum), WRONG_SAMPLE_RATE, band coverage, WRONG_LEVEL_OR_CREST_FACTOR, INSUFFICIENT_EVIDENCE (no content hash / unrecorded attributes / no playback report for bit-exact delivery), TRANSFORMED_NOT_BIT_EXACT (declared non-transparent playback transforms), ELIGIBLE_WITH_LIMITATIONS (source-only verification — delivered signal unobserved).
- `StimulusMeasurementPin` (sealed) binds measurements to registered assets; `stimulus_claim_allowed` returns `(False, 'claim_blocked_no_stimulus_pin…')` — no calibrated/standard-compliance claim on an unpinned measurement.

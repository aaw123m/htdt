## Summary

#884 requires a one-action, deterministic, privacy-classified diagnostic bundle for field-failure support. The #604 `DiagnosticPackageBuilder` already handled bounded zips and category selection; this PR adds the missing acceptance-criteria layers on top of it.

**Field classification**: new `FieldClassification` enum (`SAFE_DIAGNOSTIC` / `PROJECT_METADATA` / `SENSITIVE_PROJECT_DATA` / `SECRET_NEVER_EXPORT`) with `CATEGORY_CLASSIFICATION` covering every `PackageCategory`; each member's class is recorded in the manifest.

**Write-time redaction**: `redact_support_value()` runs on EVERY member payload at staging time — a collector bug or future category can never leak content. It scrubs Windows/POSIX/UNC paths, IPv4/IPv6 (calibrated to not mangle timestamps or version strings), token/JWT values, and wholesale-replaces dict values whose keys name secrets (`password`/`token`/`api_key`/`credential`/`private_key`/`authorization`) or identities (`hostname`/`customer`/`serial`).

**Byte-exact preview**: `build()` was refactored into a shared `_stage()` pass; `preview()` runs the same collect→redact→budget pipeline without writing the zip, so the previewed member set and sha256s can never disagree with the export. `SupportBundlePreviewDialog` shows this list — member name, classification, size, redaction count — plus excluded categories and collection errors, BEFORE the file-save dialog. The "include project IDs" checkbox re-stages the preview live.

**Integrity + determinism**: manifest v2 records per-member `sha256`, `classification`, `redactions`, `excluded_categories`, `collection_errors`, and an `integrity` map; ZIP entries get fixed timestamps so identical state produces byte-identical members.

**Crash isolation + honest collectors**: new `context_providers` channel adds `runtime_context` (OS/Python/dependency pins), `gpu_context` (deliberately reports `renderer: unprobed` — the graphics stack may be the fault), `audio_context` (WASAPI stub reported as `backend_unavailable`, fake marked `simulated`), `workflow_state`, `release_evidence` (sha256+verdict, not payload), `measurement_engine_status`, `device_transaction_status`. A raising provider becomes a `collection_errors` entry, never a failed export.

The Support Page export flow is now: collect → preview dialog → save-as → archive. 27 new tests cover classification completeness, every redaction class, preview↔export byte identity, integrity manifest correctness, and probe-crash isolation.

## Summary

`Size3` and `RoomPrism` were the only two dimension models without a `finite` validator — `Field(gt=0)` admits `+inf`, so a crafted scene payload (imported bundle, tampered DB row) could carry infinite room/entity dimensions through model validation into solvers producing `inf`/`NaN` acoustics. `Position3`, `Offset3`, `Direction3`, `Quaternion`, `Matrix3`, and both vertex models already enforce `isfinite` via identical `@field_validator` blocks; this adds the same convention to the two missing models.

- `Size3.x_m/y_m/z_m`: `finite` validator (`'size values must be finite'`)
- `RoomPrism.width_m/depth_m/height_m`: `finite` validator (`'room dimension values must be finite'`)
- Regression tests in `test_review_round17_input_validation.py` (same theme as existing non-finite rejections): ±inf/NaN rejected for both models; subnormal/huge-but-finite values still accepted.

Verified by probe: before the change `RoomPrism(height_m=inf)` and `Size3(x_m=inf)` validated; after, they raise `ValidationError`. Scoped suite: 20 + 50 tests green.

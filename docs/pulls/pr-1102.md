## Summary

#992 real-GUI verification found the データ管理 generations row wider than its `QScrollArea` viewport: `dataManagementGenerationsCombo` sized to the longest archive name (~55 chars) plus two fixed-size action buttons kept the row minimum at ~1264px, so `このバックアップを復元テスト…` (added in #1092) needed horizontal scrolling at ~800px windows.

The fix applies the existing `CaptureInboxPage._sync_action_layout` adaptive convention instead of inventing a third style:

- New `_GenerationsRow(QWidget)` folds the secondary `drill_button` into a `操作 ▾` overflow `QToolButton` (InstantPopup, `setAccessibleName("保存済みバックアップのその他の操作")`); the menu `QAction` runs the exact same `_run_restore_drill` slot. The primary `このバックアップを検証して復元…` action never collapses, matching the primary-triage-ops rule.
- Fold trigger: `_actions_required_width()` (child size hints, combo contributes only its minimum) vs `_available_width()` — measured against the **scroll viewport minus ancestor chrome**, not `width()`: a too-wide row's granted width can never see the shortage. 24px hysteresis matches the inbox page.
- `generations_combo` switches to `AdjustToMinimumContentsLengthWithIcon` + `setMinimumContentsLength(12)` so long auto-backup names stop pinning the row's minimum (~702px → ~194px contribution); the popup still shows full names.
- The fold state is seeded at construction (hidden secondaries don't count toward `minimumSizeHint`, so the content widget fits the viewport from first layout) and resynced in `resizeEvent` and `_refresh_generations` (longest-name content changes the required width).
- `_refresh_actions` mirrors the busy/restart-disabled state onto the menu action.

Measured on this box: dialog 800px → row min 642px ≤ 786px viewport, drill folded; 1400px → unfolded.

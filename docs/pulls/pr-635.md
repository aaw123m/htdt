## Summary

Two new sealed-record authorities on native schema v24→v25 (11 tables), per issues #592 and #599.

**#592 — Device configuration snapshot / restore authority** (`cad_device_snapshot.py` + repository):
- `DeviceConfigurationSnapshot` (`devsnap-<sha24>`) pins manufacturer/model/HW rev/serial/firmware/module state/preset + observed fields, `captured_at_utc`, evidence class and adapter. `state_content_sha256` digests only identity pins + fields so two captures of the same device state diff as identical despite different capture times.
- Evidence classes are gated by model validators (`device_export_backup` requires `backup_artifact_sha256`, `device_readback` requires fields or an observation pin, `unobserved` fields cannot carry values) — empty evidence claims are rejected.
- Append-only provenance DAG via `parent_snapshot_ids` (children require persisted parents; experiment branches never overwrite known-good). `DeviceKnownGoodBaseline` promotion requires readback/export evidence + retained backup + post-verification (`evaluate_known_good_eligibility`).
- `diff_snapshots` is semantic only when both sides carry fields; opaque captures report state-hash equality only — never "no change" from a matching preset name.
- `ConfigurationRestoreRecord` (`devrst-`) requires an artifact or source snapshot; the verdict is derived by `evaluate_restore_verdict` (`restored_exact_observed_state` needs success + identical semantic diff — vendor "Load" ack never suffices) and re-validated by the model.
- `DeviceFirmwareTransition` (`devfw-`), `PreUpdateDeclaration`→`evaluate_pre_update_gate` (`update_ready`/`update_unverified`/`update_blocked`, `None` is blocked), `ReplacementDeviceAssessment` (`devrpl-`) with 7 portability classes, and persisted `DeviceConfigurationBackupArtifact` rows content-addressed by `content_sha256`.

**#599 — External standards registry / revision authority** (`cad_external_standards.py` + repository):
- `ExternalStandardDocument` keyed by `standard_id@edition` with publisher/number/title/edition/dates/locale/primary+secondary URLs/rights/review policy, sealed by `document_sha`. 14-state non-linear lifecycle (draft → current → reaffirmed/under_revision/superseded/withdrawn/status_conflict/…).
- `StandardLifecycleObservation` (`stdobs-`) records "this tier-`N` source claimed `status` at `T`"; `detect_lifecycle_conflict` treats same-tier disagreement as `status_conflict` while tier hierarchy resolves lower-tier disagreement (store beats committee page). `standard_citation_allowed` fail-closes on unregistered/draft/dead-lifecycle production citations.
- `StandardProfileMapping` (`stdmap-`), `StandardsEvaluationPin` (`stdevpin-`, pins doc edition + mapping version + calc version + input evidence ids), `StandardsRevisionDiff` (`stddiff-`, 7 change kinds), admission workflow `discovered`→`production_eligible`/`limited`/`retired_for_new_projects`, 8 rights classes.
- `seed_standard_documents()` registers ~30 real in-repo citations with webstore-verified lifecycles: `iso-3382-1@2009` under_revision (ed.2 at DIS as separate `iso-3382-1@ed2-draft` DRAFT_RESEARCH_ONLY entry), `iec-60268-5@2003` withdrawn 2026-04-17 → `iec-60268-21@2018`, `ansi-asa-s12-2@2019` superseded→2026 yet still pinned by `cedia-cta-rp22@v1.2` (honest superseded-pinned-by-dependent), `avixa-v202-01@2016`↔`@2026` tier-resolved conflict recorded in seed observations.

## Summary

`CadCoverageRepository._validate_evaluation_binding` re-ran the pinned evaluator without `priority_profile`, so any scenario with `population_weighting='seat_priority'` could never persist an evaluation — the replay deterministically raised `'seat_priority weighting requires the bound SeatPriorityProfile'`. Unreachable today (all production callers use `equal_unweighted`), reported by the #1001 seat-coverage session.

- `CadCoverageRepository.__init__` now holds a `CadSeatPriorityProfileRepository` over the same `SceneRepository`; the replay resolves the persisted profile itself rather than trusting a caller-supplied object.
- In `_validate_evaluation_binding`, `seat_priority` populations resolve `population.priority_profile_id` and fail closed when the profile is missing or its `profile_sha256` doesn't match the recorded binding (`'coverage seat priority profile authority missing'`), then pass it as `priority_profile=` into `evaluate_coverage`.
- Symmetric guard in `_resolve_scenario_authorities`: a `seat_priority` scenario bound to an unpersisted/mismatched profile is rejected at `save_scenario` (`'coverage scenario references an unpersisted SeatPriorityProfile'`) instead of becoming a dangling binding.

Out of scope (unchanged): `listener_pose_resolver` replay fidelity — evaluations recorded with a custom resolver still can't persist, same as before.

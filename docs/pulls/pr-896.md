## Summary

Implements the HTDT-owned closed-loop commissioning orchestrator for #868: `PRECHECK → BASELINE_MEASUREMENT → INGEST/QUALITY_GATE → ANALYZE → OPTIMIZE → OPERATOR_APPROVAL → COMPILE_FOR_TARGET → DEPLOY → READBACK_VERIFY → POST_MEASUREMENT → BEFORE/AFTER → ACCEPTANCE_DECISION` — machine-controlled + human-authorized + machine-verified, with rollback and resumability at every device-mutating boundary.

Key pieces:

- **Stage machine** (`htdt/cad_commissioning_orchestrator.py`): pure, deterministic, total — `stage_transition(state, event) -> TransitionDecision | TransitionRejection`. No implicit transitions: every event lands an explicit `CommissioningStageTransition` with reason/evidence refs. Terminal stages reject all events; disconnect flags reject everything except restore/abort; `succeeded=False` on an advance-rule event lands `blocked` at the same stage (never silently advances).
- **Sealed records** (6 new tables, `NATIVE_SCHEMA_VERSION` 97): `cad_commissioning_orch_runs/_transitions/_authorizations/_rollbacks/_before_after/_verdicts` — full `_SealedStore` + `NATIVE_BASELINE_DDL`/`_ROW_BINDINGS`/`_RepositoryChain`/`_ReplayProbe` wiring. Run state is re-derivable from the sealed transition log (`derive_run_state`), so the loop resumes after app restart.
- **Operator authorization** pins the *candidate* hash — `candidate_sha256` = the `plan_semantic_sha256` the operator approved — because materialization doesn't exist yet at approval. `deploy()` then verifies `materialization.export_id` + `exported_settings_semantic_sha256` descend from exactly that authorized export; a wrong-candidate or expired/consumed authorization blocks. `rollback_apply` authorizations pin `deployment_ref` instead.
- **Deploy/readback/rollback honesty**: `deploy-ACK < read-back verification` — `runtime_observed` requires `readback_matched is True`; file export / human intent never claims deployment verification; baseline config is preserved at deploy and rollback verifies the restored device config (`restored_verified`), landing `blocked` (not terminal) on failure so retry/abort stay legal.
- **Invalidation evaluator**: `evaluate_invalidation(run, **pins)` deterministically maps changed pins (scene / routing / device_binding / provider manifest / measurement etc.) to stale downstream stages; `apply_invalidation` walks the run back via `authority_invalidated` events. A clean re-check (`succeeded=False`) lands `informational` — idempotent.
- **Acceptance** fails closed: `CommissioningAcceptanceVerdict` rejects `accepted` whenever criteria are missing, indeterminate, or any evidence is stale; `CONFIG_READBACK_MATCHED` / `RUNTIME_OBSERVED` / `POST_MEASUREMENT_VERIFIED` stay distinct evidence kinds feeding `derive_evidence_strength`.
- **UI**: `commissioning_panel.py` — read-only workflow panel (stage, blocked reason, next permitted action, rollback availability, evidence strength, stale markers + transition log) with JA labels, `accessibleName`s, fail-closed UNKNOWN rendering, `operation_error_message` at the error boundary. No device-mutation path.
- Delegated measurement providers only (`cad_delegated_*` manifest pins provider identity/version/capabilities); deploy/readback goes through the existing `cad_camilladsp_deploy` adapter contract — no REW/CamillaDSP-specific assumptions in the authority layer, unsupported/UNKNOWN capability fails closed at `COMPILE_FOR_TARGET`.

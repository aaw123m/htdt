## Summary

Implements #950: the Decision Brief's five evidence gates are now **auto-resolved from real sealed producers**, so `ready`/`apply_candidate` is reachable — previously pins were declared-only and no path populated them.

**`backend/src/htdt/cad_decision_brief_evidence.py`** (new, ~750 LOC) adds `DecisionBriefEvidenceResolver`, which re-verifies each `ComparisonAlternative` against the producer stores by exact `(scene_revision_id, content_hash)` + `(system_variant_id, sha256)` scope:

- `solver_gate` ← `CorrectionQualificationRecord` (state ladder → verdict; `SPATIALLY_HOLDOUT_VERIFIED`/`MEASURED_AT_CONTROL_POINTS`/`DEPLOYED_AND_REMEASURED` = verified/measured, simulated states = conditional/predicted, `INCOMPATIBLE` = failed)
- `channel_verify` ← `ChannelVerificationVerdict` (verdict map; plan's `expected_speaker_entity_ids` must live in the candidate revision and a variant must not touch them)
- `deployment` ← `CalibrationDeployment` (scope via `calibration_plan_id` → sealed plan payload; device-scoped `DeploymentPipelineRecord` only as `freshness='unknown'` fallback)
- `campaign` ← `CampaignVerdict` (`recommendation_eligible` = verified; scope via preregistration refs)
- `production_gate` ← `ProductionReadinessDecision` (`production_ready` = verified, `no_go`/`limited` rejected)

Fail-closed per spec: cross-revision/cross-variant records are rejected (`mismatch`), same-id/different-sha = `stale` (never satisfies), declared `evidence_refs` are never trusted (each re-fetched and re-verified), and probe exceptions degrade to a missing gate + JA note instead of raising. Rejected candidates are counted in the JA note.

`.kind_resolvers()` emits the `kind → KindResolver` map `CadDecisionBriefRepository` needs so `save_brief`'s `ExactAuthorityResolver` proves the auto-pinned kinds (`correction_qualification`, `channel_verification_verdict`, `calibration_deployment`, `deployment_pipeline_record`, `campaign_verdict`, `production_readiness_decision`).

**`decision_brief_panel.py`** wires it into the rebuild button (one-click): per non-baseline alternative it runs `resolve_gates`, passes `gates=` to `build_decision_action`, and derives the recommendation — `apply_candidate` only when all five gates are satisfied + comparable, else `collect_evidence` naming the unsatisfied gates in JA (actor `operator`, verify-by real producers). Batch (`recompute_brief()`) uses the same path.

**Tests** (`backend/tests/test_issue_950_decision_brief_evidence.py`, 10 cases): all-five-verified fixture → ready + identical sha on save/read and deterministic recompose; missing/partial/predicted-only/failed/cross-revision/cross-variant/stale-sha/variant-speaker-change → never ready; panel `recompute_brief()` reproduces the identical brief semantics vs the domain compose.

## Summary

`#941`/`#942` 系の動的パネル（`DecisionBriefPanel` カード再生成、`GeometryIntakePanel` 欠陥/修復提案テーブル、`MeasurementPageWorkspace` 品質テーブル、`StandardsCriterionPanel` 評価更新）に、#804 で定義された a11y 契約を統一適用する。共有ヘルパを `dynamic_a11y.py` に集約し、各パネルは「stable item ID ベースのフォーカス維持」「状態遷移ごと 1 回だけの読み上げ」「無効化理由 + 解消先を同画面に掲示」の3契約を持つ。

`dynamic_a11y.py`（新規）:
- `STABLE_ID_ROLE`（`UserRole + 40`）で行の安定識別子を束ねる。
- `capture_focus` / `restore_focus`: 再構築の前に `QApplication.focusWidget()` を `FocusToken` へ記録し、再構築後に復元。item-view は同じ stable id の行へ `currentIndex` を再設定し、行が消えた場合はビュー自体に錨を残す（矢印キーで再アンカー可能）。生き残ったウィジェットは weakref 判定でフォーカスを動かさず、破棄されたものだけ同名 `objectName` へ再解決する。先頭で `DeferredDelete` + `MetaCall` の posted event を吐き出す — `deleteLater()` 済みのゾンビと、可視階層に追加された子が持つ「暗黙的 show の MetaCall」が確定してから解決しないと、半変異のツリーに対して誤解決するため。
- `DynamicAnnouncer`: `announce_state(aspect, state, ...)` が `(aspect, state)` の変化時のみ `QAccessibleAnnouncementEvent` を発火（urgent は Assertive）。同一状態の再描画・ポーリングは沈黙する。発火履歴は `events` に記録し、テストが sink ではなくモデルで検証できる。
- `reason_label`: 無効化理由を同画面に置く `StrongFocus` 付き QLabel — 無効ボタンは Tab 順から外れるため、理由はフォーカス可能な別コントロールでないとキーボードから読めない。

`native_accessibility.py`: `operation_blocked` / `operation_unblocked` を `AnnouncementEvent` + `REQUIRED_ANNOUNCEMENTS` に追加。`DisabledControlReason.resolution` + `display_text()`（`理由 — 解消: 解消先`）。人間可読チェックは「空白 or CJK を含む 8 文字以上」に修正（日本語フレーズは空白を持たず従来ルールで検証不能だった）。

各パネルの適用:
- `GeometryIntakePanel`: `set_report`/`set_proposal` で capture→rebuild→restore。`set_stage` が診断/派生の disabled 理由（対象なし/提案なし/決定未了/派生済み）を `stage_hint` に `disabled_hint` で連結表示（理由は `room_workspace` 側で状態から生成）。セルボタンに `intake-accept:{action_id}` 等の安定名。判定・決定・失敗を aspect 付きで1回通知。
- `DecisionBriefPanel`: `refresh()` を try/finally で包み例外時も `restore_focus`。カード `brief-action:{action_id}`、unreachable ボタンにカード内 `brief-hint:` 理由ラベル。brief の current/stale 遷移を `result_stale`/`operation_completed` で通知。カードを `QWidget(actions_container)` で生成（親なしトップレベルを再親付けすると posted show が降りるまで非表示のまま残る）。
- `StandardsCriterionPanel`: `evaluate_hint` に「プロファイルなし/評価対象なし」の理由+解消先。ツリー `criterion_id` で `currentItem` を復元。評価を `evaluation_id` 単位で、ゲート制約のブロック/解除を `operation_blocked`/`operation_unblocked` で通知。
- `MeasurementPageWorkspace`: `quality_table` に `measurement_id` 束ね。`_refresh_quality` でフォーカス復元しフィルタ消滅時はテーブルに錨を残す。`_sync_quality_actions_enabled` が retake/disposition/correct/attach の理由を `disposition_label`/`retake_label`+tooltip に併記。`quality_report_state != 'current'` の行は `result_stale` を1回通知。

テスト・証拠:
- `backend/tests/test_dynamic_a11y.py`（23件）— fake `QAccessibleAnnouncementEvent` sink で 1 回通知・urgent マッピング・busy/stale 明示を検証。offscreen での実施であり実受入とは呼ばない。
- `scripts/ux160_acceptance_run.py` に `dynamic_a11y` チェックを `ALL_CHECKS` + fixture lane に追加。`ux160_driver.check_dynamic_a11y` がアナウンサー保持パネルを探索し、stable アンカーのフォーカス保持・同一状態再描画の沈黙・画面内理由ラベルの有無を採点。
- 実 Windows UIA/実スクリーンリーダー読み上げは #804 owned-Windows manual gate に残す（本 PR の検証は Qt 側イベント発行まで）。

Follow-up（本 PR 外）: 車線内の主に先行済みコントロールの unnamed-controls リスト（`test_mounted_destinations_have_no_unnamed_controls` の既存 fail 集合 — seatCoverage*, correspondence_*, projectLibrary*, ActivityPage の QLineEdit）。今回の新規コントロールはすべて accessibleName 付き。

## Summary

A crafted `.htdtproject` whose `manifest.json` (or a `db/*.jsonl` member, or a JSON cell value reached during identity remap) is deeply nested JSON crashed `import_project_bundle` with an uncaught `RecursionError` — the one malformed-input class that escaped the `ProjectBundleError` contract. `RecursionError` is a `RuntimeError`, not a `ValueError`, so the existing `except ValueError` wrappers missed it while `JSONDecodeError`/`UnicodeDecodeError` mapped cleanly.

Changes:
- `import_project_bundle`: wrap the manifest `json.loads` in `except (ValueError, RecursionError)` → `BundleManifestInvalidError('bundle manifest is not valid JSON')` (re-raises `ProjectBundleError` subclasses unchanged; pydantic `ValidationError` is a `ValueError` so schema-malformed manifests now also surface as the contract error).
- JSONL member parse and both internal re-parse sites (`_row_identity_values`, `_apply_value_map`'s `parsed`/`reparsed` hints): extend the existing excepts with `RecursionError`, preserving their skip semantics.
- Two regression tests: forged bundle with a 5000-deep `manifest.json` → `BundleManifestInvalidError`; forged `db/*.jsonl` member with matching manifest/`rows_sha256` recompute → same for the JSONL path.

Verified: malformed inputs reject cleanly — truncated zip → `ProjectBundleError`, `..` traversal member → `BundleManifestInvalidError`, oversized member → bound rejection; `test_project_bundle.py` 17/17 green.

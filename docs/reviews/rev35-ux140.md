# REV35-UX140 — legacy QMainWindow adapter removal, stage (a): inventory + tests

Scope: inventory every surface reachable only through the legacy UI path
(`--legacy-ui`, the `OptimizationWorkspaceWindow` QMainWindow chain, and the
standalone editor windows), compare against what the workflow shell reaches,
and pin the parity map with workflow-path tests. This track ships **tests +
inventory only** — no production-code changes — so stage (b) can migrate the
stragglers and stage (c) can delete the window + adapter without colliding
with the parallel UX lanes.

## Entry surfaces (how each path is reached)

| Surface | Reach |
|---|---|
| `htdt-native` (`htdt.native_cad:main`) — default | Workflow shell: `build_workflow_shell(repository, document_id, project_library, capture_receiver, preferences, safe_mode)` → `WorkflowApplicationComposition` |
| `htdt-native --legacy-ui` | `OptimizationWorkspaceWindow(repository, document_id)` — no capture receiver, no `ApplicationPreferenceStore`, no project library, no safe-mode policy |
| `python -m htdt.native_editor` | `NativeEditorWindow` standalone (N20b editing layer only) |
| `python -m htdt.room_editor` | `RoomEditorWindow` standalone |
| `python -m htdt.wall_editor` | `WallEditorWindow` standalone |

The legacy window composes the whole editor chain as one QMainWindow:
`NativeEditorWindow` (N20b scene editing) → `RoomEditorWindow` (N30a room +
object placement) → `WallEditorWindow` (N30b wall/opening editing) →
`CadEditorWindow` (`cad_composition.py`) → `TheaterEditorWindow` (N40 speaker
sets/aiming) → `TheaterWorkflowWindow` (`theater_workflow.py`) →
`ConstraintEditorWindow` → `MeasurementEditorWindow` →
`MeasurementWorkspaceWindow` → `PredictionWorkspaceWindow` →
`OptimizationWorkspaceWindow` (dock + search controller mixins).
Launch intents resolve through `_route_launch_intent` on both paths; the
legacy window receives `user_action_required` because it has no
`workflow_application` to deep-link into.

## Deliberately absent from workflow (not gaps)

- `--legacy-ui` composition itself — the adapter this campaign removes.
- Standalone `native_editor` / `room_editor` / `wall_editor` entry points —
  debugging helpers that compose into the legacy window; stage (c) removes
  them with the chain.
- The legacy `最適化` dock's *combined* scroll layout — the workflow splits it
  into six workspace contexts by design (IA in `workflow_navigation.py`).

## Tests added (`backend/tests/test_rev35_ux140.py`)

Workflow-path parity tests pin every row of the parity map above — each test
constructs the real workflow surface (`RoomWorkspace` with `FakeRoomViewport`,
`OptimizationWorkflowWorkspace` with `FakeOptimizationViewport`,
`MeasurementPageWorkspace` with a `MeasurementWorkflowController`) and asserts
the capability-bearing widget/controller is mounted. The three gap rows have
`xfail`/`skip` tests with `UX140-stage-b` TODOs: they assert the surface is
*absent* today and flip to `xpass` once stage (b) mounts it.

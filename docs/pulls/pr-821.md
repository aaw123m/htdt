## Summary

Automates #804's UX160 owned-Windows acceptance matrix and fixes the real defect it found.

**Harness (new, run on the owned Windows box):**
- `scripts/ux160_driver.py` — drives the real display (never offscreen) in-process: walks all 13 destinations × ~27 contexts via the router, captures per-destination screenshots, and runs four machine checks per cell — layout-overflow heuristic (`minimumSizeHint` vs allocated size), a 400-press Tab focus-chain cycle probe, disabled-action reason audit (tooltip/statusTip/accessibleName), and the Ctrl+K command palette. Writes `verdict.json` before window teardown so evidence survives the box's known exit-127 shutdown flake.
- `scripts/ux160_acceptance.py` — subprocess-per-cell orchestrator sweeping `QT_SCALE_FACTOR` ∈ {1.0, 1.25, 1.5, 2.0} × {seeded, fresh} and merging to `matrix.json` + `docs/issues/issue-804-ux160-matrix.md`; exits non-zero on any blocked cell so it is usable as a manifest `script` check (added under issue 804, with a `manual` row for the rows that genuinely need a human: real pointer/VTK gestures, readability judgment).

**Bug found by the first full run (fixed):** at 150%/200% every destination reported rail overflow — `WorkflowRail.COMPACT_WIDTH` was a fixed 72 px while scaled-font glyph buttons need ~75–87 px. `set_compact` now sizes the rail from `WorkflowRail._compact_width()` — the widest button `sizeHint` plus outer margins — with `COMPACT_WIDTH` kept as the floor. `setFixedWidth` moved after margin updates so the hint measurement is settled. Regression assertions added in `test_workflow_shell.py`.

**Result:** all 8 matrix cells green post-fix (0 overflow findings, complete focus cycles, 0 unlabeled disabled actions, palette operational, clean exit).

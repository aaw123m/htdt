## Summary

Deep-dive of the failure-critical data paths (REV52-DATA): restore swap recovery, relocation cutover, bundle asset closure, automatic-backup change detection, and the audit completeness mechanism. Four verified defects fixed with regression tests; `docs/reviews/rev52-data.md` records the verified-clean surfaces and remaining issues.

**Fixed defects:**

1. **Relocation could brick startup on Windows** — `plan_data_relocation` explicitly allows an existing *empty* destination, but `os.replace(staged, destination)` fails on Windows for ANY existing directory (WinError 5). Post-`STAGED_VERIFIED`, `_recover_journal_locked` retried the identical rename on every startup → permanent `assert_managed_root_available` failure. Fix: `_promote_directory` removes an existing-empty destination before the rename (execute + recovery paths); `_park_directory` reclaims empty park slots and diverts populated ones to `<parked>.<n>` so a foreign generation is never silently overwritten (journaled `parked_dir` updated to the actual name).

2. **Bundle silently dropped `htdt_acceptance_evidence` bytes** — `_ASSET_REGISTRY_TABLES` covered 2 of the audit's 8 `_ASSET_TABLES` specs. Verified empirically: a pulled acceptance-evidence row exported without its managed file → dangling row on import into a foreign environment. Fix: export asset closure and import asset checks now iterate the audit's `_ASSET_TABLES` directly (one registry, no drift): declared-size rows require a shipped manifest member, digest-only rows accept locally retained verified bytes, declared `relative_path` must resolve to `measurement-assets/<digest>`, and export resolves paths through `managed_asset_path` (containment).

3. **Aux-only edits never triggered periodic backups** — `managed_data_fingerprint` ignored `backup_included_components()`, so a `commissioning-plans.json`-only change (which rides inside every archive) never invalidated the 15-minute evaluation. Fix: fingerprint now folds each included component's size+mtime.

4. **Interrupted restore onto an empty root brick-looped** — `_rollback_restore_swap` treated the canonical rollback slot as the pre-restore generation whenever it existed. With no pre-restore db (restore onto a fresh root — the disaster-recovery flow), a crash before the first evacuation + lost staging hit `no restorable database remains` every launch; a post-crash occupant could also claim the free slot and get blessed as pre-restore. Fix: the journal records `pre_restore_live` before the first move; journaled rollback honors it (empty truth settles to empty; an invalid post-crash occupant is parked back, never blessed). Orphan/old journals keep the strict fallback; schema stays v1 (additive field).

**Verified clean (in `docs/reviews/rev52-data.md`):** audit completeness catches a planted unregistered table → `coverage_gap` + `create_backup` refusal *even with* `allow_stale=True` (new end-to-end test); manifest↔member↔staged-db pipeline; partial-corruption handling; journal-before-swap + recovery chain precedence + residue-sweep ordering; `_MIGRATIONS` quarantine states; `integrity_error` fail-closed at every boundary.

**Noted, not fixed (cross-domain):** upgrade quarantine is not consulted by `ensure_native_schema` (non-upgrade opens bypass the marker); latent aux park/lookup path asymmetry; valid-foreign-occupant adoption semantics documented.

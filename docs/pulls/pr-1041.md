## Summary

「全部屋境界面へ適用」 previously looped `assign_material` per surface — one committed upsert each — so a mid-loop failure or interrupt left a **partial** boundary assignment while the UI still reported success. This PR makes the whole apply one sealed transaction: every boundary commits in a single `BEGIN IMMEDIATE` transaction or none does, and the operator sees the named failure with 「変更された面: 0」.

**Authority (`cad_acoustic_material.py`)**
- `assign_material_bulk(document_id, surface_ids, material, *, surfaces, only_unassigned, expected_scene_revision_id)` — one shared connection; re-verifies the persisted material payload hash and the preview-pinned scene head *inside* the write transaction; mid-write SQL error, `material_not_persisted`/`material_sha_drift`, `surface_missing`, or `scene_revision_drift` (`MaterialBulkApplyError.reason`) rolls the whole batch back.
- `preview_assign_material_bulk` — read-only pre-commit snapshot: head pin, material id + sha, per-surface rows, and overwrite / unassigned / kept / dangling counts.
- `boundary_material_state` — honest read side: per-surface `assigned`/`unassigned`/`unresolved_reference`, `stale_surface_ids`, and a boundary summary (`unassigned`/`partial`/`uniform`/`mixed`/`unresolved`/`no_boundaries`) that never coerces a partial apply to "assigned". A hash-corrupted row still fails closed like `assignments_for_document`.
- `restore_assignment_rows` + `assignment_rows_for` — verbatim row capture/restore in one transaction for the revert leg (restores rows a fresh `assign_material` would refuse).
- `material_assignment_changes` — before/after rows → one `SceneChange` on the `material_boundary` axis, the `extra_changes` vocabulary #964 revalidation consumes. *(Honest gap: no consumer feeds sidecar diffs into `compose_revalidation_queue` yet — the compose path is head-vs-parent and sidecars don't advance the head.)*
- Deterministic commit order: targets deduplicated + sorted by `surface_id`.

**Panel (`room_acoustics_panel.py`)**
- `_apply_to_all_boundaries` rewritten: preview → explicit confirmation only when overwriting existing rows (「すべてに適用（上書き）」/「未割当のみに適用」/cancel, with counts) → one atomic commit inside a single `CompositeEditCommand` (`inner=None` + side legs) → readiness reports 適用/維持/既存割当を保持 counts or the named failure + 変更された面: 0.
- One undo reverts the whole bulk apply.
- `_refresh_surfaces` renders `BoundaryMaterialState`: 混在 / 一部のみ割当 / 参照解決不能 shown honestly; dangling rows display as 「（解決不能な割当: …）」 combo entries repairable by a fresh assign or clear.

**Tests** — `backend/tests/test_issue_996_material_bulk_apply.py` (25 tests): all-or-nothing under injected Nth-statement failure at 2/100/1000 surfaces, ordering/dedupe, all four refusal reasons, unassigned-only vs overwrite-all diffs, mixed/partial/unresolved honesty, single-step undo/redo, and panel wiring (confirm paths, injected failure, honest status text).

**Docs** — `docs/issues/issue-996-material-transaction.md`.

No schema bump: reuses existing `cad_surface_material_assignments` (already lifecycle-labeled, bound, and audit-registered).

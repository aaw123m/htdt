## Summary

Calibration deployment / verification-loop authority for #806 — seals the stages the device-adapter layer already produces (designed ≠ exported ≠ deployed ≠ verified) into append-only deployment authority, a pre-apply gate, post-deployment effectiveness comparison, and scoped rollback records.

Core rules enforced in `cad_calibration_deployment.py`:

- `CalibrationDeployment` (`cald-`) pins plan → export → materialization → `AdapterDeviceBinding` → `DeploymentCapabilityDeclaration` → observed-snapshot hashes. `deployment_verified` requires `machine_readback` + an observed snapshot — an export or apply ack can never reach it. `deployment_attested` requires `operator_attestation` + attestor (visibly weaker). `deployment_unverified` pins no snapshot; `deployment_superseded` is never stored — derived only by `deployment_state_with_rollbacks`.
- `evaluate_deployment_gate` fails closed: missing capability declaration, `supports_apply`/`supports_materialization` false, or non-empty `unsupported_items` → `deployment_blocked`.
- `derive_deployment_state` maps `EffectiveAppliedSettingsSnapshot.source` to the strongest honest state: None → unverified; divergence → mismatch; `read_back` → verified; `operator_entered` → attested.
- `DeploymentEffectivenessReport` (`defx-`) binds pre/post measurement refs to the deployed state; `improvement_verified` requires post refs + an improved delta and is disqualified by any `regressed` delta. `evaluate_deployment_effectiveness` returns `inconclusive` for unverified/blocked/superseded/mismatch deployments even when a report exists.
- `DeploymentRollbackRecord` (`drbk-`) invalidates only `affected_evidence_refs` bound to the superseded deployment; room/material/measurement evidence is structurally untouched.

Wiring: 4 sealed append-only tables (`cad_deployment_capability_declarations`, `cad_calibration_deployments`, `cad_deployment_effectiveness_reports`, `cad_deployment_rollbacks`), `NATIVE_SCHEMA_VERSION` 79→80 via `_migrate_79_to_80` (idempotent baseline replay), `_ROW_BINDINGS`, audit `_RepositoryChain` + 4 replay probes, `_LIFECYCLE_TABLE_LABELS`, JA evidence-display lines in `measurement_evidence_display.py`.

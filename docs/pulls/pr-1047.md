## Summary

`HelpDialog` stacked every wrapped body `QLabel` under a plain `QVBoxLayout` with a fixed `resize(480, 360)` — no `QScrollArea` — so 10+ section topics and the 40+ row shortcut reference overflowed low-resolution and high-DPI screens with no keyboard path to the bottom, and `related_commands` rendered as dead-end text (`関連操作: A、B`).

Changes in `backend/src/htdt/workflow_help.py`:

- Fixed heading + body in `_BodyScrollArea` (`QScrollArea`, `widgetResizable`). Its `keyPressEvent` maps PageUp/PageDown/Home/End/↑/↓ onto the vertical scrollbar — plain `QScrollArea` consumes none of those keys, and unhandled presses from focused child widgets propagate up to it. StrongFocus, `accessibleName` (ヘルプ本文 / Help body), initial focus on the scroll area, explicit 閉じる/Close button.
- `_fit_to_screen(available)` caps `maximumSize` + `resize` at 90% of `screen().availableGeometry()` (device-independent pixels, so DPI/text-scale shrinks the cap automatically), floor 240×200, default 560×420. Injectable `QRect` for the DPI-matrix test.
- `HelpDialog.topic(..., help_registry=...)` renders `related_commands` as per-command `QPushButton`s: enabled state + localized reason come from `CommandRegistry.availability()`; clicks dispatch through `CommandRegistry.execute()` so the data-mutation freeze gate, availability providers, deep-link handler and error handler all apply — authoritative ops never run straight from help text. Successful dispatch closes the dialog so the workspace/result is visible; failed dispatch (e.g. a dispose guard declining) keeps it open. Registry-less fallbacks and unknown ids degrade to plain text + an unavailable reason.
- `related_topics` render as `htdt-topic:` anchors (the `GlossaryDialog` convention) opening the bound topic as a nested modal; missing topics degrade to `id（利用できません）`.
- `workflow_application._open_help_topic`, `measurement_page_workspace._show_help_topic` and `GlossaryDialog._open_related_topic` pass the help registry through so nested topics resolve.

Closing help remains a plain modal `exec()` return — no progress/dirty-state side effects; navigation commands go through the same deep-link handler the palette uses, so shell navigation history keeps the return context.

## Summary

Follow-up fix on the #577/#604 REV56-DECISION branch (base feature landed via #623): `_pairwise_objective_verdict` in `optimization_workflow_controller.py` read `evidence.sampled_envelope.sampled_max` / `.sampled_min`, but `SampledObjectiveEnvelope` (`optimization_robustness.py`) names its fields `sampled_max_value` / `sampled_min_value`. Any candidate carrying an O90 robustness envelope raised `AttributeError`, and the whole `_refresh_decision_verdicts` path failed — the UI showed 証拠判定を計算できません and persisted nothing for those pairs.

Found by end-to-end GUI verification on a seeded document (comparison page → `Pareto集合を更新`); candidates without envelope evidence were unaffected (they correctly reported 証拠不足).

## Change

- 4-token fix: `sampled_max` → `sampled_max_value`, `sampled_min` → `sampled_min_value` in both per-candidate blocks of `_pairwise_objective_verdict`.
- New regression test `test_o90_envelope_pairwise_verdict_uses_sampled_envelope_fields` exercises the unbound helper with real sealed `RobustnessEvaluation`/`SampledObjectiveEnvelope` models (canonical-hash construction) and asserts the verdict persists to `cad_decision_verdicts` and is content-hash idempotent.

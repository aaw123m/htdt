## Summary

REV63/#791: operational energy / power-mode evidence authority (schema v89). A standby watt number detached from the exact firmware/config/network/power-management state is not evidence.

Four sealed records:

- `DevicePowerModeObservation` (`cad_device_power_mode_observations`, dpmo-) — mode + electrical quantities + producing state bound together. `device_state_ref` optionally pins the #592/#595 state epoch so firmware/PM changes stale exactly the right observations. Standards-based measurements pin `standard_profile` + `standard_reference` edition (`IEC 63474@2026` form); an IEC 62087 product-profile **active-mode** claim additionally requires `stimulus_ref` (#608). `energy_wh` requires `energy_interval_s`; all quantities ≥ 0, PF ≤ 1.
- `NetworkedStandbyEvidence` (`cad_networked_standby_evidence`, nse-) — IEC 63474:2026 fields: interfaces/connection state/network availability/wake capability/PM config, `low_power_reached` flag, duration + stability rule, result. **ANSI/CTA-6043 requires `adopted_base_profile='iec_63474_2023_withdrawn'`** — the US adoption is a copy of the 2023 edition, not the same evidence as IEC 63474:2026; a direct 2026 result carries no adopted base.
- `OperationalEnergyScenario` (`cad_operational_energy_scenarios`, oes-) — typed `ScenarioComponent` entries each pinning `observation_ref` sha + device + mode, so an always-on endpoint is never hidden inside a system average. Never a bare average.
- `EnergyUseDerivation` (`cad_energy_use_derivations`, eud-) — `derived_schedule` requires explicit mode+hours schedule and source; `long_term_meter` requires meter recipe + period; tariff is all-or-none (currency+rate+unit+source). Same material can be re-derived via `derivation_version`.

Evaluators (both fail-closed):
- `evaluate_observation_currency` → `current` / `stale_after_state_change` / `unknown` (unpinned or current state unknown).
- `evaluate_networked_standby_claim` → `not_networked_standby` / `networked_standby_unverified` (no evidence, unpinned profile, or missing low-power flag/duration/result) / `networked_standby_verified`.

Also: `_SealedStore` repository (`CadOperationalEnergyRepository`), migration v88→89, `_ROW_BINDINGS` + audit probes, JA table labels, `energy_mode_label`/`energy_observation_line` display helpers.

Tests: `test_issue_791_operational_energy.py` — 17 tests covering state binding, CTA-6043 adoption pin, IEC 62087 stimulus, fail-closed evaluators, scenario composition, derivation schedule/tariff gates, repository round-trip + tamper detection. Manifest entry notes field power-measurement capture as the remaining manual check.

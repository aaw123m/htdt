## Summary

Implements the two P1 interop issues on the REV56 line, on `backend/src/htdt` with native schema v33→v34 (12 append-only tables + 3 indexes; v33 was taken by REV56-OPS mid-flight so the migration renumbers).

**#578 — IFCImportAuthority (openBIM IFC 4.3 import/export)**

- `ifc_step.py`: bounded STEP Part 21 parser (256 MiB / 2M entities / depth 64), full header + entity parse, `''`/`\S\c`/`\X\hh`/`\X2\`/`\X4\` escapes, fail-closed `IfcStepParseError` — never a partial model. Accepts only declared schema identifiers (IFC4X3_ADD2 per ISO 16739-1:2024, IFC4X3, IFC4, IFC4_ADD2, IFC4_ADD2_TC1).
- `cad_ifc_interop.py` pins coordinate truth as declarations: length unit resolved only from IfcSIUnit/IfcConversionBasedUnit; **undeclared or unresolvable length units withhold the metre transform** (`world_transform_m=None`, counted in `IfcImportCoverage.unresolved_placement_count`, warned) — no silent mm↔m ambiguity, no identity fallback on cyclic placements. True north, axis convention, WCS origin, and IfcMapConversion/ProjectedCRS georeference are kept as declared/partial/undeclared states; `world_transform_source_units` always stays in source units.
- Semantic map per the issue: IfcSpace→`room_candidate`, wall/slab/roof→`boundary`, door/window→`opening` (linked via RelVoidsElement→RelFillsElement), covering→`finish_hint`, furnishing→`obstacle`, proxy→`generic_unknown`. Material layer sets extracted as construction hints only — no absorption preset is ever synthesized. Property sets via RelDefinesByProperties preserved verbatim; unsupported property shapes counted in `dropped_property_count`.
- Stable-GlobalId `compute_ifc_revision_delta` classifies unchanged/geometry/semantics/coordinate/added/removed/`ambiguous_rebind` (needs explicit `mark_mapping_reconciliation`), including project-level coordinate-authority comparison.
- `evaluate_ifc_intake` runs IDS-style declared-requirement checks and returns actionable missing-data diagnostics (`overall_state: satisfied | satisfied_with_gaps | failed`); even a parser-level failure yields a sealed evaluation, not an exception.
- `build_ifc_export_package` emits declaration-symmetric STEP (reference/update-proposal/as-built) that round-trips through our own parser; every non-exportable item is listed in `unexported_items` with its reason.

**#586 — RP1IngestionProfile (CEDIA RP1 Performance Facts ingestion)**

- `cad_performance_facts.py`: `PerformanceFactsProfile` pins publisher/family/doc-revision/`maturity_state` (industry_review can never pose as final)/field-mapping version/content hash — source-and-revision driven since RP1-1 was industry-review at CEDIA Expo 2025, never inventing a final schema.
- `ManufacturerProductIdentity` never merges variants. `PerformanceFact` records values under the declared evidence class (manufacturer stays manufacturer, never promoted to measured) with `PerformanceFactConditions` kept verbatim; `evaluate_fact_sufficiency` demotes facts missing required conditions — "100 W/ch without context is not a complete amplifier capability."
- Conflicting sources coexist (no overwrite); `PerformanceFactsProfileRebind` requires explicit per-field disposition so review→final rebinding can't silently drop values. `rp22_consumption_view` projects facts as `design_prediction` observations capped at `nominal_spec_only`/`modelled_with_output_limits` basis — consumable by RP22, never commissioning proof.
- Both repositories verify stored parent shas on child saves, reject forged seals, and `save_export_package` re-verifies `step_sha256` against the actual STEP text.

UI wiring stays minimal per #578 §15: JA lifecycle labels + 12 audit `_ReplayProbe` entries only — raw IFC internals are not exposed as editing UI. Verification manifest entries added for #578/#586; full write-up in `docs/reviews/rev56-interop.md`.

## Summary

Follow-up to #784 (E2E finding): mounting the 検証ウィザード froze the GUI thread for ~20s while all 320 manifest gates sealed + sqlite writes ran synchronously in the page constructor, surfacing as a visible "(Not Responding)" stall.

- `_ManifestLoadWorker(QThread)`: manifest parse → `ManifestGateStore` build → `load_gates` seal now run off the GUI thread; `loaded`/`failed` signals deliver (store, issues, gates) or the exception. Parse runs before store construction so a missing manifest fails without creating the sqlite file.

- Cross-thread use is safe by design: `SceneRepository` pools read connections per thread ident and connections opt out of same-thread checking.

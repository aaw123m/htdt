## Summary

REV54 solver/numerics/optimization deep-review + fix pass. Two verified compute-load defects in the candidate-sweep and Pareto paths are fixed with before/after measurements; the rest of the assigned surface was audited clean. Behavior is bit-identical — these are pure hoisting changes.

**1. `pareto_front` recomputed canonical SHA-256 inside the O(n²) sweep.** `_dominates_metrics` resolved `metric.definition_id` per pair per metric, which internally runs `effective_definition()` → `ObjectiveDefinition.legacy()` (full pydantic validation) → `canonical_sha256`. `_validate_comparison_authority` already proves all candidates share definition_ids, so the pairwise checks were redundant O(n²·k) hash work. Now `_metric_comparison_key` resolves `(objective_id, definition_id, value, direction)` once per (candidate, objective) and `_dominates_keys` compares plain tuples. `_dominates_metrics` remains as a compat wrapper over the same keys. N=120×k=2: **0.46s → 0.02s** (definitions), **0.57s → 0.02s** (legacy metrics). `joint_pareto_front`, `robust_pareto_front`, `repository.pareto_front` all benefit via `pareto_front`.

**2. `generate_search_space` rebuilt context geometry + spec per candidate.** Each of up to 50k sweep candidates ran `evaluate_constraint_set`, which re-validated `StoredConstraintSetSpec`, rebuilt `_room_polygon_and_edges` (shapely polygon + wall edge LineStrings), `_entity_baselines`, profiles and region geometries — all invariant across the sweep. A two-level prepare API is added to `placement_constraints.py`:

```python
prepare_constraint_context(context_payload)      # room polygon/edges/baselines
prepare_constraint_spec(prepared_context, spec)  # spec validate + profiles + regions
evaluate_prepared_constraint_set(prepared, request)
evaluate_constraint_set(ctx, spec, request)      # = prepare+evaluate (unchanged signature)
```

`generate_search_space` prepares once per enumeration: **2.26s → 0.86s** (3087-candidate fixture, −62%). `_final_pose_constraint_rejections` in `cad_topology_search` shares the prepared context and the parsed `CadConstraintSet` across the base×orientation sweep while still re-validating the per-candidate spec (final-pose profiles legitimately vary).

**Verified clean** (see `docs/reviews/rev54-solver.md`): capability-manifest emit (produced-observable narrowing, fail-closed on stale descriptor), PFFDTD adapter finite-record numerics, IR import (rejects non-uniform sampling rather than resampling), prediction preflight cache identity, geometry/solver provenance chain, enumeration-cache authority replay cost (~1ms/page — left as-is).

Regression tests pin bit-identity: prepared-vs-single-shot evaluation across 16 candidates, shared-context spec prepare + fail-closed geometry version, Pareto front/dominators vs a naive reference dominance scan over 60 candidates.

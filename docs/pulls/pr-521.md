## Summary

The REV42-AUTOMATE audit found `build_measurement_quality_report` / `CadMeasurementQualityRepository.save_report` were only ever called from tests: no production path derived or stored quality reports, so every committed measurement stayed `missing`/`quality_pending` forever and quality-gated consumers (calibration plans' `measurement_quality_report_id` requirement, evidence gates, workspace quality cells) could never resolve.

This PR adds `CadMeasurementQualityProducer` (`cad_measurement_quality_producer.py`), an honest producer that derives a `CadMeasurementQualityReport` only from provable evidence:

- **Usable band** ← the imported dataset grid bounds, attested through a machine `CadMeasurementObservation` (`source_kind='raw_asset'`, or `'mixed'` once an IR dataset exists) pinned to the FR asset's `source_sha256`.
- **Timing** ← fields copied verbatim from the newest covering `CadAcquisitionContext` (all-None when unbound, so `timing_reference` stays UNKNOWN).
- **Calibration** ← only when `context.microphone.calibration_sha256` resolves through `validate_calibration_file`; applied==expected → PASS, a phantom sha is recorded as expected with applied unknown → UNKNOWN.
- **IR evidence** ← `has_impulse_response` + window bounds from bound IR datasets; `ir_truncated` is never inferred → `ir_window` stays honestly NOT_EVALUATED/UNKNOWN.
- **Repeatability** ← same-binding repeats with identical grid + `level_reference`, scored by `measurement_repeatability_rms_db`; single measurements stay NOT_EVALUATED.
- **Clipping / SNR / polarity** ← never inferable from an import → UNKNOWN.

`produce_report` is idempotent per report epoch (a second call with identical evidence returns `'current'`, saving nothing; a new dataset epoch saves a new report) and **fails closed**: an unverifiable subject returns `'unresolved'` and persists nothing.

Wiring — every production commit path now derives a report:

- `MeasurementWorkflowController.commit_pending` / `commit_batch` / `import_ir_for_measurement` / `runner_commit_cell`
- `OptimizationWorkflowController._rew_task_completed` (REW auto-ingest)
- `measurement_views` backfills missing reports on first quality read, so pre-producer committed measurements surface real states immediately.

`_produce_quality_report` never raises to callers — a failed derivation logs and leaves the state `missing`, retried on the next quality read, so a quality problem can never block a save.

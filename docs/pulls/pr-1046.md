## Summary

Watch-folder drops that failed used to surface as 「完了」 in the Activity Center, and a file that exhausted `_ROUTE_MAX_ATTEMPTS = 3` kept its `_seen` marker with no inbox row and no recovery path — a permanent silent loss. This PR makes completion typed-accurate and adds a bounded, persistent failure queue with explicit manual reprocess actions.

**Completion honesty** (`workflow_application._on_capture_watch_completed`): all-staged → `capture_watch_stage` COMPLETED; all-failed → `fail(error_summary=…)` (the error never hides in `result_summary`); mixed batches split into one COMPLETED row + one FAILED row since the activity model has no partial terminal state. Staged paths resolve out of the failure queue.

**Failure capture** (new `capture_watch_failures.py` + `routes_exhausted` signal on the runner): a route hitting the cap emits a `WatchRouteExhaustion` record whose `(mtime_ns, size)` is the kept `_seen` signature — the fingerprint of exactly the bytes that failed. `CaptureWatchFailureQueue` persists upserts to `data_dir/capture-watch-failures.json` (schema v1, max 50, TTL 14d, atomic save, corrupt-loads-empty). No stall/generation/epoch machinery touched.

**Queue UI** (`CaptureInboxPage` 「失敗キュー」 tab): per-route rows {basename, sanitized error kind, attempts, first/last seen, retryable/unsupported/user_action_required} with detail panel + verify verdict. Actions:
- 「安全に再試行」— `verify_watch_retry` gates on failure-class → existence → `(mtime_ns, size)` fingerprint → watch-root epoch; `REPLACED`/`DELETED`/`EPOCH_MISMATCH`/`NOT_RETRYABLE` refused with reason. Verified routes run on the bundle pool with a real RUNNING→terminal operation row; stamped `arrival_source='watch_queue_retry'`.
- 「このファイルを選んで取込」— explicit operator import of the current file (fingerprint/epoch deliberately skipped, existence still required; content validation stays with the router).
- 「サポート診断」— sanitized JSON note under `diagnostics/` carrying basename + fingerprint + `[diag: XXXX]` correlation id; full paths and raw bundles never leave the machine.

A successful manual reprocess resolves the entry and lands exactly one inbox row; a failed reprocess bumps `attempts` and ends FAILED. No auto schema-repair, no promotion — completion state, authority-promoted, inbox-staged, project-assigned remain distinct.

**Tests**: 12 new in `backend/tests/test_issue_1022_capture_failure_queue.py` (all-success/all-failed/partial states, exhaustion record = `_seen` signature, persistence+reload, every verify verdict, replaced-file refusal, verified retry → exactly 1 staged row, failed retry bumps attempts, page gating, diagnostic redaction, corrupt-store fail-closed). `test_workflow_application.py` REV43-SEAMS updated to the FAILED+`error_summary` contract. 50 tests pass (Windows offscreen, Py3.12.10).

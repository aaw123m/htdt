## Summary

「すべて既定値に戻す」previously committed every registered default in one click — integrations, compute, and UI settings rewritten with no review. Now `_reset_all` enumerates only the keys that would actually change and opens `PreferencesResetDialog`: per-category checkboxes with per-key `現在値 → 既定値（適用の影響）` rows, and three explicit choices — 選択カテゴリのみ初期化 / すべて初期化 / キャンセル. Nothing reaches the store until a reset button is accepted; zero-change shows a status line without opening the dialog.

## Details

- Rollback: after a successful reset, 「元の設定に戻す」 restores the pre-reset values via `store.update(snapshot)` (external equipment state explicitly out of scope).
- `PreferenceNotificationError` is reported as 保存成功＋一部反映失敗 — never mislabeled as rolled back.
- The sanctioned recovery path for corrupt/newer-schema files (`reset_persisted_file`) now warns first via `SanctionedResetDialog`, naming the `.recovery` destination up front; cancel discards nothing.
- `test_ia_v2_integration`'s sanctioned-reset test updated to accept the new warning.

## Summary

REV30 follow-ups: a declared feature-scale floor for the deterministic acoustic verdict kernels (fail closed instead of diverging), a real tolerance bug found and fixed while specifying the scale, direct offscreen tests for the five GUI editor classes REV27 flagged as untested, and a large honest reduction in round-13 hash-sweep skips.

**1. Sub-millimetre feature scale is now specified and enforced.** `MIN_SUPPORTED_FEATURE_M = 2.0e-3` in `cad_geometric_acoustics_adapter.py` declares the smallest compiled-triangle feature scale the deterministic kernels support — REV28 showed occluder verdicts diverging between scaled and unscaled tolerance paths below ~1.5 mm. `execute_deterministic_ga` and `execute_late_field_energy` both call `_require_supported_feature_scale`, which raises `DeterministicGaUnsupportedError('UNSUPPORTED_GEOMETRY')` when any compiled triangle's max edge falls below the floor. Scenes needing finer detail go through the compiler's existing `tiny_feature_policy` upstream of execution. The regime is documented in `docs/R150_DETERMINISTIC_GA_ADAPTER.md` §"Supported feature scale".

**2. Point-in-triangle degenerate check fixed.** Both `_point_in_triangle` and `_point_in_triangle_prepared` compared `abs(denominator) <= tolerance` — but the denominator is a Gram determinant (m⁴), so the bare-length threshold rejected triangles under ~16 mm² as degenerate. Now `<= tolerance * tolerance`, matching the proven pattern in `cad_geometric_acoustics_portal.py` and the adjacent `normal_length` checks. Fixed in both the raw and prepared variants to keep them bit-identical. `test_rev30_feature_scale.py` covers the gate boundary (inclusive), both execute entries failing closed, and 5 mm triangles now inside-testing correctly while true degenerates still reject.

**3. Direct tests for the five zero-coverage editor classes.** `test_rev30_gui_editors.py` (18 tests) constructs `RoomEditorWindow`, `WallEditorWindow`, `CadEditorWindow`, `TheaterEditorWindow`, `ConstraintEditorWindow` offscreen against the seeded F1 fixture and asserts each layer's distinctive contract: room sketch/edit lifecycle + vertex insert/delete, wall topology derivation + split/merge round-trip, the CAD layer's routing of vertex-count ops to wall-edit guidance once a topology exists, object palette add/duplicate/302-template persistence, and constraint authoring (walkway/allowed/wall-clearance/pair-clearance) plus tree-driven deletion.

**4. Hash-sweep skips reduced by making synthesis smarter, not by hiding them.** `_synth` now handles `Sequence`/`Mapping`/`Iterable`/`bytes`/`Path` annotations and recursively synthesizes nested `BaseModel` payloads; `_distinct_model_payload` gives pairwise-distinct literals so ordering validators (`min < max`) can pass; `_seal_payload` resolves synthesized `*_sha256` seal fields to their true canonical hashes; `_builder_args` resolves real annotations via `get_type_hints` (incl. string forward refs), keeps hazard literals for primitives, and validates model args to instances; `_cross_reference_repair` re-points unambiguous `*_referenced_field` couplings between sibling args (e.g. `exported_settings.requested_plan_semantic_sha256 = plan.plan_semantic_sha256`) and re-seals. Skips citing 'builder parameters not auto-synthesizable' drop **143 → 24**; remaining skips are genuine preconditions the builder itself rejects (verified `ValueError`/`ValidationError` paths, now exercised rather than uncollected). No skip was removed by assertion weakening — builders now fail or pass on real behavior.

Scoped pytest green: the two touched suites, both new REV30 files, and the hash sweep (222 passed / 143 skipped / 0 failed) run under xdist offscreen.

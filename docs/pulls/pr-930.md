## Summary

Two confirmed hardening gaps, one PR:

1. **Silent in-place schema migration had no recovery copy** (found during #879 review). `ensure_native_schema` — used by `SceneRepository`, the headless `htdt` CLI, and the diagnostics orchestrator — migrates an older-versioned real database IN PLACE with no recovery copy; the dialog + copy only exist on the GUI `plan_native_upgrade` path. Adds `_snapshot_pre_migration_backup(path, version)`: for a real pre-existing file (`0 < version < current`) it writes a sibling `*.schema-v{version}-backup` byte copy before the migration loop — write-once (a resumed chain never overwrites it), never created for fresh (v0) or current databases, best-effort (copy failure never blocks migration). Restoring is a file rename.
2. **Rotted presentation-profile tests revived.** `test_cad_profile_repositories.py` still exercised the removed `save_profile`/`select_profile` API — rewritten against the current `HomeTheaterVideoDesignProfile` / `save_video_profile` / `video_profiles.list` contract; divergent-copy test now asserts `PresentationProfileIntegrityError` (a tampered seal fails `_assert_sealed` before the conflict check — sealed convention).

Five confirmed defects fixed; each has a regression test in `backend/tests/test_rev61_persist.py` proven to fail on the unfixed code (`git stash` verification — 13 behavioral tests go red, all 17 green after the fix).

## What was broken

1. **`data_relocation._verify_staged_root` verified 2 of 8 `_ASSET_TABLES` specs.** Only `cad_measurement_assets` + `cad_quality_calibration_files` were checked; a staged root with dangling `htdt_acceptance_evidence` rows, managed `cad_equipment_evidence_authorities`, non-NULL `cad_treatment_evidence_authorities`, or empty `cad_{directivity,wave_excitation,projector_spec}_source_assets` content addresses passed verification and was promoted live. Now iterates the shared `_ASSET_TABLES` registry: `where` predicates (`col='lit'` / `col IS NOT NULL`, unknown → fail closed), `[0-9a-f]{64}` digest check, registry paths through `managed_asset_path` containment, digest-only rows resolved at `measurement-assets/<sha>`.

2. **`CadDeviceSnapshotRepository` inserted sealed records unverified (all six saves).** `model_copy(update={sha, id})` forged rows landed and then raised `ValidationError` on every read path. Added `_assert_sealed(record, sha_field, id_field)` re-deriving `canonical_sha256(semantic_payload())` + `<prefix>-<sha[:24]>` id binding → `DeviceSnapshotIntegrityError`. Same class fixed in `CadProjectTemplateRepository.save_template` and `CadProjectActivityNoteRepository.save_note`.

3. **`AcceptanceRunRepository._insert_evidence` used bare `INSERT OR IGNORE`.** `evidence_id` is caller-supplied (uuid), so a same-id row claiming different bytes was silently masked while the run payload claimed the new digest; malformed sha/unsafe path/negative size also landed in `htdt_acceptance_evidence` (an `_ASSET_TABLES` member). Now asserts shape before insert and compares the stored row to the claim on conflict — divergence raises `NativeSchemaError`.

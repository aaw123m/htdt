## Summary

Refs #792.

Implements the #792 lifecycle/supportability authority as a sealed `cad_*` domain module + repository, following the REV60/REV61 conventions (`cad_ulf_acoustics.py`, post-REV61 `_SealedStore`).

**New files**
- `backend/src/htdt/cad_supportability.py` — five sealed records (`SupportabilityProfile` `spro-`, `ExternalDependency` `exdep-`, `LifecycleRiskObservation` `lro-`, `OfflineContinuityEvidence` `oce-`, `ReplacementReadiness` `rpr-`), helper sub-models (`DeclaredFunction`, `LicenceEntitlement`, `SoftwareAvailability`, `IntegrationDependency`, `ServiceabilitySnapshot`), `SUPPORTABILITY_LABELS` JA registry, and six evaluators.
- `backend/src/htdt/cad_supportability_repository.py` — `CadSupportabilityRepository` with the `_SealedStore` contract: seal assertion on `save()`, id + sha + every bound column verified on `get()`, `document_id` verified on `list()`.

**Semantics (all evaluators fail closed — `unknown`/degraded, never inferred truth; no future-proof or vendor-viability score)**
- Function-level dependency binding (16-kind taxonomy), never device-global labelling.
- `OfflineContinuityEvidence` cannot be sealed unless `authorized` + non-`destructive`; continuity verdict dominates `unavailable > degraded > unknown > continue_local`.
- `LicenceEntitlement` carries identity/state only — `extra='forbid'`, no key-material field exists.
- `evaluate_recovery_capability` composes #592 backup + software availability + licence path + restore deps + restore test (backup alone is never proof).
- `evaluate_security_maintenance` reports available/limited/ended and routes risk decisions via #598 — never a compromise claim.
- `evaluate_replacement_readiness` → `replacement_ready` only with all criteria confirmed + compatible + pinned #596 requalification and #592 restore refs.
- Strict explicit-UTC timestamps; `review_by_utc` evidence horizon + `superseded_by_ref` (#765) drive freshness verdicts.

**Schema**: `NATIVE_SCHEMA_VERSION` 79 → **80** (base was v79 — sibling PR #800 claimed 79 first). Five tables + indexes in `NATIVE_BASELINE_DDL`/`NATIVE_SCHEMA_TABLES`, `_ROW_BINDINGS` for all five (nullable refs `optional=True`), `'supportability'` chain + 5 replay probes in `native_authority_audit.py`. Note the dependency table is `cad_supportability_dependencies` — `cad_external_dependencies` is already taken by the dependency-resolution domain.

**Tests**: `backend/tests/test_issue_792_lifecycle.py` — 82 tests covering every verdict path (fail-closed especially), seal/id derivation, validator rejections, repository round-trip/idempotence/tamper detection, and the LFC fixture scenarios. All pass (`QT_QPA_PLATFORM=offscreen`). `test_cad_schema.py` updated for v80.

**Known pre-existing main rot** (not this PR): `capture_mission_rebase_decisions` from PR #800 lacks audit coverage registration — `test_authority_audit_coverage` + one backup test fail identically on main.

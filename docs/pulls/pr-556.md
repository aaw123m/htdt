## Summary

REV50-PERFUX follow-up (after #555). Real-GUI verification at 1024×768 caught the placement context right panel forcing a horizontal scrollbar — seat-row spins and the 登録… buttons were pushed off-screen. Root cause: the column's content minimum width was ~358px vs the right stack's 248px minimum, driven by combos sized to their longest item, unwrapped `_SpinRow` labels, and one row holding label + combo + 2 buttons.

- `room_workspace`: every `QComboBox` inside the placement column gets `minimumContentsLength(6)` + `AdjustToMinimumContentsLengthWithIcon`; every `QFormLayout` gets `WrapLongRows` so labels wrap above fields when narrow
- `room_video_panel`: same treatment at refresh-time creation sites (seat-card `riser`/`pose` combos, card form), `WrapLongRows` on `screen_form`/`display_form`/`policy_form`, `_SpinRow` labels `setWordWrap(True)`, seat-view buttons moved to their own row
- `seat_priority_panel` / `system_expansion_widgets`: same combo policy + `wordWrap` at runtime-created widgets

Measured offscreen: `RoomVideoPanel.minimumSizeHint().width()` 358 → 238px, seat card 220px — both under the 248px stack minimum, so no horizontal scrollbar.

New regression test `test_placement_column_content_stays_inside_right_stack` pins the ≤248px bound plus the per-widget policies. Scoped pytest green (rev50 13 + room_workspace 26 + constraints/seat-priority/install-handoff 24). Details: `docs/reviews/rev50-perfux.md` addendum (F1–F4).

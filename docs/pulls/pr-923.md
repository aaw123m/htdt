## Summary

REV68 slice for #885 — a sealed **guided troubleshooting orchestrator** that drives the diagnostic loop `OBSERVATION → HYPOTHESES → SAFE DISCRIMINATING TESTS → AUTOMATIC MEASUREMENT/READBACK → EVIDENCE UPDATE → RANK/ELIMINATE → NEXT TEST / RESOLUTION` on top of the landed authorities. It runs discriminating tests; it never auto-diagnoses.

- `cad_diagnostic_orchestrator.py` — stage machine (`observation → hypotheses → test_planning → measurement → evidence_update → ranking` loop, terminal `resolved/unresolved/needs_inspection/aborted`), sealed records (`diag-`/`dtr-`/`dhyp-`/`dtp-`/`dob-`/`dev-`/`dres-`/`dau-`), `derive_session_state` re-derives purely from the transition log (resume like #868), `DiagnosticOrchestrator` service mirrors every machine observation into #719 (`diagnostic_case`/`diagnostic_hypothesis`/`diagnostic_test`/`diagnostic_verdict`) so the evidence ladder stays the single source of truth.
- **Three executable fault trees** (`channel_missing_output`, `sub_output_low`, `prediction_residual_unexplained`) covering routing, polarity, crossover cancellation, deployment mismatch, and measurement-chain faults — each with predeclared `DiscriminationRule`s and a manual-gated `operator_inspection` step.
- **Real engines, real evidence**: plans dispatch to `MeasurementAcquisitionEngine` (#869, pins `swrun-` runs), `run_verification_plan` (#876, pins `cvvd-` verdicts), and adapter `read_back` + `build_observation` (#806/#878, pins `effective_settings_snapshot`). Device read-back always precedes manual re-entry — the operator template is structurally unselectable while an automated discriminating test remains.
- **Plan-level safety**: forbidden action tokens (protective-earth defeat, ground lift, mains-live, …) are unrepresentable; `device_mutation` requires a one-shot `DiagnosticOperatorAuthorization` (`dau-`, consumption derived from observation pins); acoustic templates must fit the session `max_stimulus_level_dbfs`; `reconfiguration` requires a declared rollback note.
- **Fail closed**: observations carry only machine-produced facts — unmeasurable quantities evaluate `insufficient_evidence`; ranking is deterministic (state → declared `rank_seed`); a single surviving hypothesis resolves to `fault_isolated` at most — never a physical root-cause claim (`root_cause_confirmed` requires the #719 controlled-intervention verdict); inspection-only survivors or exhausted evidence end `unresolved`/`needs_inspection`.
- `cad_diagnostic_orchestrator_repository.py` — 8 `_SealedStore` tables under schema **v104**, with `_ROW_BINDINGS` + authority-audit `_RepositoryChain`/`_ReplayProbe` wiring and JA table labels.
- 26 tests cover seal integrity, append-only + tamper detection, every safety path, the transition machine, and end-to-end scripted-backend walks — including the injected-fault acceptance run that isolates `device_not_deployed` and honest `unresolved`/`needs_inspection` terminations.

## Summary

REV42 automation sweep: audited every user-facing workflow for manual-but-automatable steps and shipped the three real gaps as fail-closed background lanes. Audit report: `docs/reviews/rev42-automate.md`.

**A — periodic backup re-drive.** `AutomaticBackupRunner` only evaluated `periodic` **once per launch**, so a multi-day session never produced another generation despite `interval_hours` (contradicting `record_clean_close`'s "the next eligible scheduler tick"). Added a `QTimer` re-drive (15 min) on the same `NativeWorkerPool`: ticks are absorbed while a job is in flight, a `pool.start` raise can't wedge `_in_flight`, `shutdown()` stops the timer. Only a *real* run surfaces an Activity entry — quiet evaluations stay silent.

**B — scheduled storage integrity scan.** `missing_referenced` and `reclaimable_bytes` only surfaced if the user remembered to open データ管理 and click scan. `StorageWatchRunner` drives `plan_storage_gc` on a worker every 4 h. Deliberately bypasses `DataManagementController.scan_storage` — its completion signal pops a `QMessageBox` every run, which would be a nagging dialog per interval. Only reportable results (missing refs, or ≥64 MiB reclaimable) produce one Activity entry + statusbar; `run_storage_gc` stays behind its manual confirm. Opt-out pref `maintenance.storage_watch_enabled` (default on, new メンテナンス category), re-read every tick.

**C — `.htdtcapture` watch-folder.** A bundle on disk only reached the inbox via relaunch arg or manual open. New `integrations.capture_watch_dir` pref (opt-in, empty=off) + `CaptureWatchRunner`: baseline marks pre-existing files seen-never-staged, two-scan `(mtime,size)` signature settle, then `route_capture_intent` (ingest → **inbox stage, never promote**) on a worker job. New `arrival_source` parameter stamps `watch_folder` honestly (default `document_open` unchanged). Activity entry deep-links to inbox; mounted inbox page refreshes; junk drops report `failed` once and never become rows or kill the lane.

## Stays manual — and why

| Step | Reason |
|------|--------|
| Batch `commit_batch` | Explicit evidence gate — user reviews auto-assignment before persist |
| `run_storage_gc` delete | Destructive unlink under confirm — scheduling deletes is exactly the bypass this sweep must not do |
| Journey/wizard auto-advance | Auto-opening pages hijacks context; one-click nav is already honest |
| Manual refresh buttons | Fallbacks for when an auto-lane is off/stale |
| REW host/port | Loopback-only by contract |
| Pre-existing files in watch dirs | Baseline-skip (REW contract): new drops only, no surprise bulk import |

**Judgment call — flagged, not fixed:** measurement quality reports have *no production producer* (`build_measurement_quality_report`/`save_report` are test-only) — every measurement's quality stays `missing`/`quality_pending` forever. Honestly deriving a report needs an evidence-derivation design — a dedicated feature, not a sweep fix.

## Summary

Implements #789 — a dedicated authority for surge/lightning transient-protection evidence, distinct from power-capacity (#587), power-quality (#738), UPS capability (#736) and product-certification (#751) authorities.

**New authority** (`cad_transient_protection.py`, `cad_transient_protection_repository.py`; schema v88, full audit wiring + JA labels):

- `ProtectedPath` — one exact electrical or conductive path (`utility_service → panel_distribution → branch_circuit → receptacle_pdu_ups → av_device`, or external-copper variants) with a pinned load ref. Protection is evaluated per path, never per theater.
- `TransientProtectionPlan` — declared protection domains per path + jurisdiction/code pin (code family requires edition) + qualified-review requirement; declaring `external_lightning_protection_system` forces the review flag.
- `SPDEvidence` — product/listing/install evidence bound to (path, domain): `spd_type_class`, `standard_profile` incl. `iec_61643_11_2011_withdrawn`, mandatory `standard@edition` pin, method-specific ratings kept exact (`vpr_volts`/`mcov_volts`/`nominal_discharge_current_ka`/`max_discharge_current_ka`/`sccr_ka` — never normalized into one surge rating), install record (`installed_verified` requires installer report/photo/panel-circuit association), `coordination_ref`, `evidence_basis`.
- `TransientProtectionObservation` — manufacturer-state health readback (`status_ok`/`replace_required`/`fault`/`remote_alarm`) with source; no life estimation from elapsed time.
- `TransientProtectionEvent` — lightning/severe-transient/utility-fault/SPD-alarm/topology-change; stales affected paths until `inspection_record_ref` closes it.
- `TransientProtectionAssessment` — sealed per-path verdict from `evaluate_path_protection`, binding the exact evidence the verdict rests on.

**Fail-closed evaluator** (precedence): `stale_after_event` → `status_degraded` → `no_protection_evidence` → `review_required` → `designed_not_installed` → `coordination_unverified` → `partial_point_of_use_only` → `protected_with_evidence`.

**Hard rules**

- `evidence_basis='vendor_marketing'` never satisfies a domain — a `surge protector` label is not SPD evidence.
- `non_spd_transient_feature` (UPS ride-through etc.) only satisfies its own declared domain, never a power-path SPD domain.
- ≥2 SPDs without a coordination reference → `coordination_unverified`; two datasheets never imply coordination.
- Coverage counts against declared domains only — evidence for an undeclared domain cannot complete an unspecified requirement (no-plan paths are always `no_protection_evidence`).

**Tests** — `backend/tests/test_issue_789_transient_protection.py` (26 tests): every verdict path, marketing/non-SPD/other-path rejection, latest-observation wins, event stale + inspection release, seal/id integrity, append-only + column tamper detection, JA labels. `docs/issues/issue-789-transient-protection.md` documents the evidence model and boundaries; verification manifest gains pytest + manual field-capture checks.

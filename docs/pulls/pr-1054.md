## Summary

Refs #1025

The 保持管理 deletion-candidate picker was a single flat `QComboBox` (series id + 8-char revision prefix + counts) — at hundreds of revisions, same-prefix ids and one-series-many-revisions made wrong-selection easy. This replaces it with a searchable/sortable/groupable `QTreeWidget` and an itemized dry-run, without touching the purge authority (`plan_capture_revision_purge`, in-transaction re-verify, Cancel-default confirmation are all unchanged).

**Listing (`capture_retention.py`)** — `CaptureRevisionListing` gains `linked_evidence_count`, `linked_payload_bytes` (DISTINCT runs→`capture_ingestion_source_links`→`capture_source_evidence` join) and `assigned_document_ids` (`capture_semantic_promotions.scene_revision_id → scene_revisions.document_id` — exact FK authority only; un-promoted revisions return `()`).

**Widget (`capture_retention_ui.py`)**
- Toolbar: free-text search (id/series/document/date/counts/bytes haystack), グループ combo (なし/シリーズ/プロジェクト/取り込み日), ソート combo (最終取り込み/ID/シリーズ/件数/サイズ), honest `表示 N 件 / 全 M 件` count.
- Tree: 6 columns, full revision id on every leaf (no ambiguous 8-char prefix), non-selectable group headers; leaves carry `capture_revision_id` on `UserRole` — the only row→record resolution path.
- Selection pinned by id: no auto-selection; filter/sort/group/refresh re-resolve by id; hidden pin shows `絞り込み条件で非表示です`, vanished pin shows `…ありません` — never silently moved.
- Dry-run itemizes every plan category (linked evidence deletable/retained, record counts, retention obligations, reclaim bytes+blobs, up to 8 blocking dependents with kind labels); `blocked`/`absent` plans say so and never arm purge.
- Arming discipline: dry-run arms `_planned_revision_id`; scope edits, selection change and `refresh()` disarm; sort/group alone do not (referenced set unchanged). Purge button requires armed id == selected id && not busy.

**Tests** — new `test_issue_1025_retention_search.py` (17): listing field joins, exact promotion→document assignment, 1000-revision listing + widget filter/pin/regroup, colliding 8-char prefixes, busy gate, two-repo project switch, plan invalidation matrix, confirmed-purge targets only the selected id, 360×640 narrow UI + `_unnamed_controls` UIA sweep. `test_review_round8_capture_retention_ui.py`/`test_round14_dialogs.py` updated for the tree API (`select_revision`, `listed_revision_ids`).

Verified: 17 new + 39 round8/round14 + 46 rev24/round19/round14-pipeline pass offscreen; `test_accessible_labels.py::test_standalone_dialogs_have_no_unnamed_controls` covers the widget. Note: `test_accessible_labels.py` intermittently hard-crashes this box's interpreter mid-file — reproduced identically without this change (pre-existing environment flake).

# #886 初回セットアップウィザード

## 目的

新規利用者が「何をすればよいか」で迷わないよう、プロジェクト作成から
レポート出力までの正規経路を 6 ステージのガイド付きウィザードで提示する。
ウィザードはガイダンスでありゲートではない — エキスパートはどの
ワークスペースからも自由に作業でき、ウィザードはその結果を自動的に
反映する。

## ステージ構成

| # | ステージ | 完了条件 (権威由来) |
|---|----------|---------------------|
| 1 | プロジェクトと部屋 | シーン保存済み + 部屋完成 (Overview readiness) |
| 2 | 機材と配置 | スピーカー登録 + ch 役割確定 + 機材バインド解決 |
| 3 | 測定の準備 | オーディオバックエンド利用可能 + 校正ウィザード完了 (cwrun-) + チャンネル検証 `map_state == 'verified'` |
| 4 | ベースライン測定 | 測定レコード存在 (Overview `measurement` ステップ) |
| 5 | 最適化と適用 | バリアントが適用段階到達 + (候補がある場合) readback 検証済み (corch- `furthest_stage >= readback_verify`) |
| 6 | 完了とレポート | `measured_validated` バリアント存在 |

## 設計上の不変条件

- **進行は導出であり保存しない**: ステージ状態は `derive_wizard_progress`
  が権威ストア群から毎回導出する。ウィザードが独自の「完了フラグ」を
  持つことはない — エキスパートが外部で完了した作業は次回表示時に
  自動的に完了として表示され、未完了の権威をウィザードが見せかけで
  完了にすることも構造上不可能。
- **blocked は必ず理由を持つ**: 構造的に欠落した前提条件
  (オーディオバックエンド不在など) は `blocked` + JA 理由 + 詳細文。
  「なぜ進めないか」が表示されない blocked 状態は存在しない。
- **同時に current は 1 つだけ**: blocked が resume 対象を確保するので、
  下流ステージが後勝ちで current になることはない。
- **resume ファイルは権威ではない**: `first-run-wizard/state.json` は
  「開始/閉じた/後で」の表示状態のみを記録する。破損・改ざんされても
  自動表示が止まるだけで、証跡や権威には一切影響しない
  (`load_wizard_state` は破損時 None を返す fail-open、導出は常に権威由来)。

## 配線

- プロジェクトメニュー「初回セットアップウィザード…(&W)」で随時再開可能。
- 自動表示: アプリ起動時とプロジェクト切替時に `record.status == 'active'`
  またはレコード未作成の場合のみ表示。`あとでやる` で `dismissed` 化し
  以後は自動表示しない (メニューから常に再開可能)。全ステージ完了で
  `completed`。
- 各ステージのプライマリアクションは対応ワークスペースへの deeplink:
  ROOM/geometry・ROOM/placement・MEASUREMENT/calibration_wizard・
  MEASUREMENT/acquisition・OPTIMIZATION/interventions・PRESENTATION。

## 範囲外 (issue 境界)

- ウィザード独自のデータモデルは持たない (issue の明示的非ゴール)。
- #877 校正ウィザード・#876 チャンネル検証・#869 スイープ等の個別
  ワークフローは deeplink で起動するだけであり、ウィザード内への
  インライン埋め込みはしない (権威パスを素通しにしないため)。
- デバイス自動検出は #879 のスコープ — ウィザードは検出結果を反映する
  が独自の検出を行わない。

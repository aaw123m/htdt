## Summary

Follow-up to #455 fixing two issues surfaced by offscreen e2e testing of the underlay paths.

**1. Regression in #455 (fixed):** `_underlay_image_cache` served a decoded raster indefinitely — after the render blob row was deleted, items still carried `image` (stale pixels) instead of rendering empty per the pinned spec. The cached entry is now served only when `repository.has_blob(digest)` still holds; a missing blob evicts it and renders empty. `test_round21_attachment_lifecycle.py::test_underlay_missing_blob_is_flagged_not_silent` passes again.

**2. Pre-existing repaint bug (rev25-uiperf `8c572ebe`, fixed while in the file):** the `render_document` signature keyed `_underlay_items`/`_guide_items` by `id()` under a "reassigned wholesale ⇒ identity is staleness-safe" assumption — but `_refresh_underlay_ui` syncs aux state twice per refresh, so a same-length replacement tuple lands on the freed previous tuple's address and the signature collides. Verified effect: `update_underlay_field(uid, opacity=...)` (and the other same-count field edits — elevation, calibration finish) never repainted until an unrelated scene change. The signature now stores `tuple(_underlay_item_key(item) for item in items)` (same content key the render cache uses) and the guide-items tuple itself. Two regression tests added: a same-length replacement rebuild test and a `_underlay_item_key` field-coverage test.

## Summary

SupportPage gains a read-only 「アプリとプロジェクトの状態を診断」 lane that surfaces the existing `run_health_checks` — no new validator. The check runs off the UI thread through a new `SupportHealthRunner` (`NativeWorkerPool` + `ActivityCenter`, `CANCELLABLE` + `SAFE_NEW_ATTEMPT`), and results render itemized per category with reason-specific JA guidance that only routes to existing surfaces.

- `support_diagnostics.py`: added the live check/probe factories the `integrity_runner` / `integration_probes` hooks were designed for — `semantic_integrity_check` (clones the live DB via SQLite `backup()` on a read-only URI + hardlinked `measurement-assets/` into a `finally`-removed temp dir, so the authority audit never opens a file it might migrate), `rew_api_probe`, `capture_receiver_probe` (frozen UI-thread snapshot), `vtk_probe` (`find_spec` only — never a GL context).
- `support_health_runner.py`: one in-flight run (busy `start()` → `False`); cancel lands as `CANCELLED`, never as a result; `input_authority_refs=(managed-data:<fingerprint>)` so restores/project switches reclassify stale ops; `_closed` drops late completions during teardown.
- `application_pages.py::SupportPage`: `アプリとプロジェクトの状態診断` section — run/cancel buttons (`supportRunHealthCheck`/`supportHealthCheckCancel`), status line with 最終実行 timestamp + target dir + data-state fingerprint, and a `QScrollArea` of per-category results with JA check labels, summaries, details, and guidance buttons. `refresh()` re-renders the stored report verbatim — never silently re-runs. INTEGRATIONS failures show the honest "not app damage" note; `health_check_guidance` maps each check_id to an actionable surface (`data_management`, `authority`, `preferences`, `capture_settings`, `activity`, `export`) with category-level fallback.
- `workflow_application.py`: `_support_health_job_factory` snapshots `rew_api_base_url()` and receiver state on the UI thread, then freezes the worker job (`owns_lock=True`, same as the bundle export); guidance actions call `settings_dialog.open_settings/open_preferences/open_capture_settings`, the authority inspector, the bundle export, and `navigate_to_target(WorkspaceId.ACTIVITY)`.

Read-only guarantee: storage probes only read; the semantic audit operates on a consistent throwaway clone — no writes, no lock acquisition beyond what `run_health_checks` already does. Nothing auto-repairs; repair-adjacent guidance always routes through the backup restore preview.

Tests: `backend/tests/test_issue_1018_support_health_check.py` — 16 tests covering button→async-job→results, real runner + ActivityCenter record, concurrent re-run refusal, cancel/failure honesty, integration non-escalation, guidance mapping + routing, no false all-PASS, refresh re-use semantics, fingerprint stamping, narrow/DPI200/UIA reachability, runner drain on close, and clone-audit cleanliness. 113 tests pass across the support/diagnostics suites.

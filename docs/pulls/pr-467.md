## Summary

Adds `.github/workflows/build-windows-artifacts.yml` — a `workflow_dispatch`-only packaging pipeline that produces the Windows installer and a portable package from the existing scripts, plus a GitHub-Release option. No PR CI is introduced; test verification stays local per repo convention.

- Steps: `actions/checkout` → CPython 3.12 x64 (`actions/setup-python`) → `choco install innosetup` → `scripts/build-native.ps1` → portable zip + manifest → `scripts/build-installer.ps1` → `actions/upload-artifact` → optional `gh release create`.
- New artifact: `HTDT-portable-<display_version>.zip` (raw PyInstaller onedir tree for no-install use) with a `htdt-release-manifest/1` manifest carrying the zip SHA-256 — same schema as the installer manifest, so provenance tooling treats both uniformly.
- Display version is resolved from the packaged `build_info.json`, so zip name, installer name, `HTDT.exe --version`, and manifests all agree on `<version>+g<sha8>[.dirty]` by construction.
- `publish_release`/`release_tag` inputs attach everything in `dist-installer/` to a new release (`contents: write` permission is scoped to that optional step's need).
- Every `uses:` is pinned to a full commit SHA — `test_workflow_actions_are_sha_pinned` activates now that `.github/workflows` exists; verified locally (test file green).
- `docs/RELEASING.md` gains a "Manual build workflow" section documenting dispatch, outputs, and the SHA-pin requirement.

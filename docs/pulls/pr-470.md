## Summary

REV31 harden track — probe-first, fix-second across five items. Probing confirmed three real defects (receiver certificate identity) and two latent-contract items (engine id sharing, `occluder_triangle_indices`); the grazing machinery and UI-thread sqlite paths needed pinning rather than new behavior.

**Certificate identity (`capture_receiver.py`)** — three confirmed defects:
- `get_config()` raced on first call: two threads seeing `row is None` both minted certs and the loser hit `UNIQUE constraint failed: capture_receiver_config.id` (reproduced 3/4 threads failing). Mint+insert now runs under a process-wide `_CONFIG_LOCK` and a cross-process `sqlite3.IntegrityError` re-reads the winning row instead of raising.
- Silent certificate regeneration left `pinned_identity` stale: `_ensure_certificate()` regenerates whenever files are missing, but the config row kept the old pin, so the QR payload pinned a cert the server no longer serves. `get_config()` now reconciles the stored pin against the live certificate on every read (`UPDATE ... SET pinned_identity` when drifted). The served credential is the live artifact; the pin is derivative.
- `_ensure_certificate()`'s exists-guard trusted any two files: a torn pair (interrupted `os.replace` promote, manual splice) passed the guard, was pinned, and only failed later inside `start()`'s `load_cert_chain`. The read path now `load_cert_chain`-validates an existing pair and regenerates in place on `ssl.SSLError`, so every caller gets a consistent credential.

**Engine id sharing (`cad_geometric_acoustics_adapter.py`)** — `engine_id` is a family id: three families each have two implementations (`HtdtPortalDirectEngine`/`HtdtPortalGraphDirectEngine`, `HtdtPortalFirstOrderReflectionEngine`/`HtdtPortalSpecularGraphEngine`, planar order-1/2). All digest/provenance surfaces already carry `(engine_id, engine_version)`, which is unique — renaming ids would break recorded artifacts. New `_ENGINE_SOLVER_REF_BY_ID_VERSION` registry pins the contract: an engine claiming a registered family id whose `(id, version)` pair doesn't name the `solver_implementation_ref` it declares is rejected in `execute_deterministic_ga`. Custom test engines with unregistered ids are unaffected.

**`occluder_triangle_indices`** — declared on `DeterministicGaExecutionInput` and hashed into `semantic_sha256`, but nothing ever checked it. Execution now verifies the declared set reproduces the non-`room_boundary` triangle indices of the compiled geometry (`_occluder_object_triangle_indices`, shared helper replacing three duplicated expressions). A self-consistent input lying about its occluder set now fails closed instead of executing under a false identity. Digests unchanged — the field was already hashed; inconsistent inputs are rejected, not re-derived.

**UI-thread sqlite (`application_pages.py`, `commissioning_wizard.py`)** — three read paths bypassed the repository's per-thread pooled read connection: `_document_heads` and `list_recent_revisions` opened raw `connect_sqlite()` (~2.7ms/call vs ~0.2ms pooled, probed), and `CommissioningWizard._other_documents` opened a write-mode `_connect()` that was never closed — a leaked connection plus no REV29 reopen-fence gating. All three now borrow `repository._read()` per the pooled convention.

**Grazing-ray probe (no defect found)** — `_segment_grazes_plane` thresholds verified at all boundaries (degenerate, in-plane, `tol/len` ratio, 0.25 clamp). First-order legs cannot graze: `compile_deterministic_ga_execution_input` rejects any endpoint within `geometric_tolerance_m` of a region boundary (`membership=boundary`), which dominates the `tol/len` gate for segments ending on the plane. Only second-order P1→P2 legs are grazable and both emission sites already gate them. Regression tests pin the truth table and the wall-hug rejection.

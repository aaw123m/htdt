## Summary

Follow-up fixes to #481 found by real-GUI E2E verification — two bugs, one pre-existing and one in the new registry:

- `MeasurementPageWorkspace._job_completed` called `to_user_facing_error(error)` without the required `title=` kwarg → `TypeError` before `warn_user` ran, so the retryable-error modal (and the `on_help` button added in #481) was unreachable on every retryable failure. Pre-existing since REV10-UX; now passes `error_prefix` as the title.
- `STATUS_EXPLANATIONS` keyed raw codes flat, but the same code means different things in different columns: `'unknown'` is emitted by the evidence column, `record.quality_status`, AND `phase_status`; `'UNKNOWN'` by the capability decision AND the `QualityDecision` vocabulary; `'calibration'` by attachment kinds and campaign purposes. Split into domain-scoped vocabularies resolved via `status_explanation(code, domain=...)` / `explain_combo_items(combo, domain=...)` — the quality cell now explains quality, the phase cell phase, the timing cell the capability decision. Also adds the missing `usable`/`warning` quality entries and drops an invented `'WARN'` code.
- Regression tests: `test_colliding_status_codes_resolve_per_domain` (crossed texts observed live on the UI) and `test_retryable_job_error_shows_warn_user_with_help` (the branch now reaches `warn_user` instead of TypeError-ing); coverage test restructured per domain.

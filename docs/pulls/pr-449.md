## Summary

Round-2 user-perceptible performance pass (REV25-UIPERF), all measured on a populated project (40 revisions, 15 variants, 60 measurement assets, ~120 ledger rows) on Windows.

**The wins, by measured impact:**

| Path | Before | After |
|---|---|---|
| `measurement_views` build ×60 assets | 3885 ms | 57 ms |
| `workspace.refresh()` (measurement) | 5474 ms | 380 ms |
| `render_document` ×8 identical inputs (warm navigate) | 4423 ms | 3.3 ms |
| `set_context` same-context re-issue | 5612 ms | ~0 ms |
| `SceneRepository.get` ×40 revisions | 156 ms | 0.9 ms |
| `list_variants` (15 rows, full authority replay) | 65 ms | 3.5 ms |
| `get_variant` ×15 | 110 ms | 3.8 ms |

| `build_solver_output_ledger` (120 rows) | 7.4 ms | 5.4 ms |

**What changed:**

- `SceneRepository` / `CadSystemVariantRepository`: per-thread pooled read connections (`_SharedReadConnection`, no-op `close()`) replace `sqlite3.connect()` per call — ~3 ms each on Windows. Reads still re-`SELECT` rows every call so external deletes/tampering stay observable (fail-closed contract preserved); only row deserialization (`tuple(row)` key) and the deterministic variant authority replay (`variant_sha256`, `baseline.revision_id`, `baseline.content_hash` key) memoize. `close()` releases the pooled handle; the authority audit's `_RepositoryChain.close()` calls it so throwaway audit clones still unlink on Windows.
- `read_managed_asset_verified`: bounded (512) signature memo keyed `(path, digest, size_bytes, st_size, st_mtime_ns)` — containment/symlink/size checks still run per call; only the byte-level re-hash is elided for an unchanged on-disk signature (same contract as `cad_schema` ensure signatures).
- `build_solver_output_ledger`: one `sqlite_master` probe replaces 21 `_table_exists` round-trips; one fetch + one `_payload` parse per row is shared by all linkage maps and the entry loop.
- `RoomViewport3D.render_document`: a signature over (document, selection, hidden/locked, overlays, extras, section) skips the whole scene rebuild on identical inputs — the shell issues several identical `render_document` calls per navigation. Overlay actor namespaces (`proposal-`, `measure-`, `constraint-`, `video-`, `history-ghost-`, `search-domain-`, `snap-feedback-`, …) are still dropped so compositing callers re-populate them. Entity meshes memoize by `model_dump_json` content (LRU 2048); cached meshes are shared read-only across viewports.
- `MeasurementPageWorkspace.set_context`: same-context route re-issue early-returns instead of doubling `activate()`'s refresh.

**Invalidation/staleness notes:** every memo is keyed by content or immutable row bytes; every read still hits SQLite. The only residual staleness gap (documented in code): a managed-asset file overwritten while forging size+mtime_ns would serve cached bytes — same accepted gap as the existing schema-signature memo.

**Tests:** 4 new/extended regression tests (memo identity + miss-liveness, materialized-proposed identity, same-context no-refresh, render dedup + overlay scoping + changed-input rebuild). Scoped gate: 168 tests pass on `merge-test` (this branch merged on `893fbbd9`).

**Remaining headroom (not done — diminishing returns or needs design):** first VTK render still ~0.5 s software-GL init per viewport mount; measurement `workspace.refresh` remainder is mostly first-time VTK/underlay texture work; dialogs (inspector ~100 ms) already fast enough not to touch; import-time module cost (PySide6/VTK ~1.5 s) unchanged — real startup win would need lazy imports/deferred viewport creation.

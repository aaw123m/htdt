**Race reproduced?** Yes. Barrier-controlled old worker resumed *after* the new epoch started: on the pre-fix runner 4/5 gated tests fail — the abandoned worker's poison marker and root-A `seen`/`pending` entries leak into `runner._seen`, and its extra route bumps `arrival_count`. On the fix: zero cross-writes.

**Fix shape:**
- Each job computes on job-local `seen`/`pending`/`route_failures` snapshots and returns a frozen `_WatchScanResult` — the worker never touches runner state (not even reads; abandonment flows only through its `cancel` event).
- `_on_completed` (Qt owner thread) publishes next-state wholesale only while `(root, generation)` still names the live epoch — not a post-hoc check after side-effects.
- `_job_generation` bumps on stall-cancel *and* every watch-root change; `_job_finished(key, generation)` ignores stale generations so a late `finished` can't unlatch the replacement.
- Idempotency is at the canonical repo: ingest dedups on `lineage_digest`, `inbox.stage` → `already_staged` — content identity, not `(mtime_ns,size)` hints.

**Test counts:** new `test_issue_1014_capture_watch_isolation.py` — 7 tests (race repro, mid-route stall → 1 inbox row with `arrival_count==2`, root A→B, disable→enable, shutdown, publish/latch guard units). Combined with existing suite: **21/21 pass** on Windows/PySide6 offscreen.

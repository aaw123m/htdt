## Summary

`cad_spatial_ir_metrics` shipped with `iacc` implemented (SPAT10) and `lateral_fraction` / `lateral_fraction_cosine` / `listener_envelopment` permanently `unsupported` — the spec validator refused any directional channel refs, so no spatial-impression metric besides IACC could ever be derived even though #974's `SpatialRoomImpulseResponseDataset` now supplies directional receiver evidence. This implements the three metrics per ISO 3382-1 Annex A against hash-pinned channels.

- New `DirectionalIrChannelRef` evidence ref (`channel_role` ∈ `omnidirectional` / `figure8_lateral` / `free_field_omni_reference`) pins channel IRs by decoded-PCM hash plus dataset id/sha.
- Spec validation per metric: lateral fractions require a `figure8_lateral` + `omnidirectional` pair from the *same* sealed dataset with matching rate/length/kind; `listener_envelopment` (L_J, a level) requires a `free_field_omni_reference` with `absolute_amplitude_authority=True` — a relative reference can never yield an ISO level, so spec construction fails closed.
- `J_LF` = fig-8 energy in the pinned window / omni energy 0→window-end; `J_LFC` uses `|p_L·p|` (cos-weighting); `L_J` = `10·log10(∫_window p_L²/∫ p_ref²)` in dB.
- `SpatialIRMetricResult` gains `value_unit` (`dimensionless`/`decibel`); computed results must declare it. Schema/authority versions bump to `spatial-ir-metrics-2` (nothing persists these records yet).
- `build_spatial_ir_metric_spec` auto-pins the correct `analysis_method` per metric; a mismatched method is rejected.

`evaluate_spatial_ir_metric` gains `lateral_ir`/`omni_ir`/`reference_ir` kwargs; supplied samples are sha256-verified against their pinned refs before any math runs. Closes #213.

## Summary

Round-9 deep review of the numerical/acoustic math layer (full evidence + reproductions in `docs/reviews/round9-accuracy.md`). Every finding was proven against an analytic reference before being counted. 7 findings: 2 high, 3 medium, 2 low — all fixed; 2 prior-round deferrals still standing.

**High:**
- `compute_minimum_phase_deg` extracted `atan2(Im, Re)` of the liftered spectrum — i.e. `arg(log H_min)` — instead of `Im(log H_min)`. On a discrete-time minimum-phase golden (`H(z)=(1+0.8z⁻¹)(1−0.55z⁻¹)`) the old path errs up to **180°**; the corrected `spectrum.imag` extraction is **exact to 1e-6°**. This was the round-7 "~35° bias" deferred item: the old test masked it by subtracting a DC offset and asserting loose tolerances. The docstring now honestly documents the mirrored-extension truncation bias (flat tail policy) instead of hiding it.
- `reconstruct_mode_shape` paired residue amplitudes (keyed by `position_id`) to anonymous `Position3` coords positionally — any caller ordering other than residue insertion order silently attributed each measured amplitude to the wrong physical position. Now requires `evaluation_position_ids`, bound by id lookup, fail-closed on set mismatch.

**Medium:**
- `_interpolate_db` was linear-in-Hz; the pinned comparison authority convention is `linear_in_log2_frequency`. A 20→160 Hz segment mid-point read −3.4 dB where the convention reads −5.3 dB — a 1.9 dB residual bias.
- `_fractional_octave_smooth` was arithmetic dB mean; the declared authority `fractional-octave-power-mean-1` requires `10·log10(mean(10^(L/10)))`. A −20 dB notch read −6.7 dB instead of −1.7 dB, over-weighting narrow dips in correction evidence.
- `run_ir_analysis` crashed on silent evidence: zero-energy IR → 0/0 in the ETC/Schroeder normalizations → NaN through the clamp floors → `canonical_json(allow_nan=False)` raises at sealing. Now fails closed: floor-level traces, `unknown` metrics, `usable_dynamic_range_db=None`. Non-finite samples rejected up front.

**Low:**
- `analyze_minimum_excess_phase` ignored declared `hf_extension`: `linear_slope`/`producer` specs silently got flat-extension semantics → now raises a domain `ValueError`.
- `window_start_s/window_end_s` rounding to the same sample index produced an empty `windowed` array and a raw numpy `Invalid number of FFT data points (0)` → now a domain `ValueError`.

**Persisted-computation flag:** `minimum_phase_deg`/`excess_phase_deg` traces and `SpatialCorrectionEvidence` residuals change for new runs (old values were numerically wrong). No authority hashes bumped (`IR_ANALYSIS_ALGORITHM_SHA256`, `HTDT_MIN_PHASE_ALGORITHM='htdt_min_phase_v1'`, etc.) — sealed specs replay to the corrected values.

## Summary

REV54-PASS5 — fifth-pass review of REV53's merged changes (`baf69460` REV53-CAPTURE + PR #563 `c7b08768` REV53-PASS4). Two real defects, both in the relocation rollback leg of `_recover_journal_locked`, are fixed; all other reviewed surfaces verified clean and recorded in `docs/reviews/rev54-pass5.md`.

**Defect 1 — stale `parked_dir` can restore the wrong generation.** Until the `SOURCE_PARKED` journal write lands, `journal.parked_dir` is only the *planned* park name: a crash between `_park_directory`'s rename and that journal write leaves the real generation at a diverted `<parked>.<n>` sibling while the journaled slot can hold an older parked generation (reachable on same-second relocation retries, where the timestamp-named plan slot is still occupied). Recovery would promote the wrong generation back live. New `_locate_parked_source` resolves the parked generation by the `source_database_sha256` recorded at `PREPARED` across `parked` and its numeric diverted siblings — content-addressed, fail closed. Digest-less legacy journals keep name-only trust (unchanged behavior).

**Defect 2 — the rollback raise always claimed a rollback.** The `DataRelocationError` said `rolled the source back to {source}` even when no restore ran — source slot occupied, source already holding the journaled generation, or nothing restorable — while the journal was cleared. It now reports the actual outcome (`rolled the source back` / `already holds the pre-relocation generation` / `was left in place` / `no restorable parked generation`).
